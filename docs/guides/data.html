概述

图数据由节点、边和可选的 Combo 分组组成。将业务对象映射为节点、对象之间的关系映射为边，再把数据传给 Graph。图已经渲染时，可以替换整份数据，也可以只修改变化的元素。

数据结构

图数据（GraphData）

下图中，A、B、C 属于同一个 Combo，边用两端节点的 ID 建立连接。

字段类型必填默认值说明
nodesGraphNode[]是—节点列表。创建空图时传 []。
edgesGraphEdge[]是—边列表。没有边时传 []。
combosComboData[]否无分组分组列表。节点通过 comboId 引用其中的分组。

节点数据（GraphNode）

字段类型必填默认值说明
idstring是—节点的唯一 ID。边通过它指定端点，也可以用它查询和更新节点。
namestring否—节点名称，可在 node.style.label 回调中读取并显示。
dataNodeData否—自定义业务数据，例如 { score: 80 }。其中 cluster 如有设置，需为字符串。
xnumber否无布局时为 0节点在图坐标系中的横坐标。配置布局后，最终位置由布局计算，可用 fx 固定横坐标。
ynumber否无布局时为 0节点在图坐标系中的纵坐标。配置布局后，最终位置由布局计算，可用 fy 固定纵坐标。
fxnumber否不固定横坐标布局计算完成后，将节点的横坐标设为此值。
fynumber否不固定纵坐标布局计算完成后，将节点的纵坐标设为此值。
comboIdstring否不属于分组所属 Combo 的 ID，需引用 combos 中已声明的分组。
statesNodeState[]否[]节点的初始状态，例如 ['selected']。通过 node.stateStyles 配置对应外观。

边数据（GraphEdge）

字段类型必填默认值说明
idstring否自动生成边的唯一 ID。需要在整图替换前后识别同一条边时，显式传入稳定 ID。
sourcestring是—起点节点的 ID，需引用 nodes 中的节点。
targetstring是—终点节点的 ID，需引用 nodes 中的节点。与 source 相同会形成自环。
dataEdgeData否—自定义业务数据，类型为 Record<string, unknown>，例如 { weight: 2 }。
statesEdgeState[]否[]边的初始状态，例如 ['selected']。通过 edge.stateStyles 配置对应外观。

分组数据（ComboData）

字段类型必填默认值说明
idstring是—分组的唯一 ID。节点通过 comboId 引用它，子分组通过 parentId 引用它。
parentIdstring否无父分组父分组的 ID，需引用同一 combos 列表中的分组。父子关系不能成环。
collapsedboolean否false设为 true 时初始折叠分组，隐藏后代节点及其关联边。
stylePartial<ComboStyleConfig>否使用图级分组样式为当前分组覆盖指定的样式字段，例如 { fill: '#e6f4ff' }。 分组样式配置
dataRecord<string, unknown>否—自定义业务数据，例如 { department: 'engineering' }。
statesElementState[]否[]分组的初始状态，例如 ['selected']。通过 combo.stateStyles 配置对应外观。

数据操作

数据初始化

将 data 传入 new Graph()，等待首次 render() 完成，再调用数据写入方法。示例中的 #container 需要已挂载并具有宽高。

选择更新方式

变化方法保留或重算
切换数据集 / 全量返回setData替换全图，有配置就布局；默认适配
少量业务字段变化updateNodeData / updateEdgeData浅合并 data，不重布局
新增或删除元素addNode(s) / addEdge(s) / remove…新增节点提供坐标，删除节点连带删除边
位置变化updateNodePosition(s)图坐标变化，不改变身份
选择、隐藏、归组状态 / Combo 方法按所属主题修改，不必全量替换

替换整份数据

准备好完整的 GraphData 后调用 setData()。它会按当前配置重新布局，默认重新适配画布。传入 fitView: false 可以保留用户当前的缩放和平移。

新数据决定初始选中状态。要保留选择，按仍存在的稳定 ID 恢复。 保留选择 · 视野保留示例

查询数据

用 getNodes() 和 getEdges() 读取列表，用 getNodeData(id) 和 getEdgeData(id) 按 ID 查询单个元素。

输入、模型与快照

形式用途修改方式
GraphData 输入声明节点、边和 Combo交给 new Graph / setData
查询 Model读取当前工作图，states 是集合通过 Graph 方法修改
getData 快照导出当前坐标、归属与状态修改后显式 setData；嵌套对象可能共享

稳定 ID 表示业务身份，数组顺序和坐标都不表示身份。相同端点可以有多条不同 ID 的边；跨刷新保留边选择时显式提供稳定 ID。

Model 是 Graph 持有的实时视图。数据替换或删除后重新查询。首次渲染前，各查询方法返回相应的空值，getData() 则返回构造数据的快照。查询可能在销毁后仍有返回值，可用 destroyed 检查实例。

getData() 在渲染后导出当前坐标、实际边 ID、归属和状态。快照省略折叠派生的 hidden，固定轴 fx / fy 和布局配置需另存。

查询返回类型
返回类型字段
NodeModelid、name?、x、y、data?、states
EdgeModelid、source、target、data?、states
ComboModel分组坐标、尺寸、成员、折叠状态等
ElementModelNodeModel | EdgeModel | ComboModel

字段均为只读，? 表示可选。节点的 x、y 是图坐标，data 的类型是 Readonly<Record<string, unknown>>，states 的类型是 ReadonlySet<ElementState>。

常见问题

修改导出数据为什么没生效？

getData 不自动写回；少量变化用增量方法，整图替换才显式 setData，并选择视野策略。

删除后为什么原来的下标指向其他元素？

数组顺序可能变化。用 ID 查询，分别匹配节点和边，不保存数组下标作为身份。

更新后标签或颜色没变？

确认字段写在 data，样式函数读取同名字段；修改导出副本或直接改 Model 不会按公开流程更新。

更新后为什么视野或选择丢了？

setData 默认适配，状态按新输入建立。保留相机用 fitView: false，保留选择则按稳定 ID 显式恢复。
