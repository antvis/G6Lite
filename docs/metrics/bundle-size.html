包大小

G6-GL 的真实打包体积与同类图可视化库横向对比

包体积直接影响首屏加载与 npm 安装成本，是衡量一个前端库「轻量」与否的核心指标。本页给出 G6-GL 的真实打包体积，并与同类图可视化库横向对比。

测量方法

体积数据由 size-limit 自动产出，已接入 CI——每个 PR 都会自动检查体积是否超过阈值，防止无意间的体积膨胀。测量口径如下：

  • 入口：dist/index.js（即 import { Graph } from '@antv/g6-gl' 的实际入口）。
  • 打包器：size-limit 内部使用 esbuild 将整棵依赖树 bundle 成单文件，模拟用户真实引入后打进业务 bundle 的体积。
  • 压缩：分别给出 minify + gzip 与 minify + brotli 两种结果（gzip 为最通用口径，brotli 为现代浏览器/CDN 常见口径）。
  • 复现：在仓库根目录执行 npm run size 即可。

体积会随版本演进变化，下表数据基于 0.1.0-beta 阶段构建产物。CI 中的体积阈值见仓库根 .size-limit.json。

G6-GL 体积构成

维度体积（minify + gzip）体积（minify + brotli）
核心引擎（不含布局/图数据依赖）~32 KB28.05 KB
全量（含 @antv/graphlib + @antv/layout）116.7 KB99.3 KB

可以看到：

  • G6-GL 核心渲染引擎本身仅约 28 KB（brotli）——这部分包含 WebGL 渲染管线、DataModel、调度器、交互行为等全部自研代码。
  • 体积的大头来自 @antv/layout（提供 15+ 种布局算法）。如果你的场景只用到内置的少数布局、或自行计算坐标，未来可通过按需引入进一步瘦身（规划中）。

横向对比

下表为同类 WebGL/Canvas 图可视化库的全量 gzip 体积量级对比（数据来自各库官方 npm 发布产物，仅供量级参考，具体以各库当前版本为准）：

库渲染技术全量体积（gzip）说明
G6-GLWebGL~117 KB含 15+ 布局
sigma.js v3WebGL~60–80 KB需搭配 graphology，布局为独立包
G6 v5Canvas（@antv/g）~400 KB+功能全面，插件生态丰富
Cytoscape.jsCanvas~350 KB+含大量分析算法

对比结论：

  • 相比 G6 v5：G6-GL 全量体积约为其 1/3 以下，因为它聚焦「大规模渲染 + 核心交互」，不携带完整插件体系与 Canvas 图形栈。
  • 相比 sigma.js：两者都走 WebGL 轻量路线，量级接近。G6-GL 的差异在于布局算法内置（sigma 需额外引入 graphology-layout 等），因此「开箱即用」的总成本更可控，单看核心则 G6-GL 核心层（28 KB brotli）同样精简。
  • 相比 Cytoscape.js：G6-GL 不内置图论分析算法，因此在纯可视化场景下更轻。

如何进一步减小体积

  • 使用支持 tree-shaking 的打包器（Vite / Rollup / esbuild）；G6-GL 已标注 "sideEffects": false。
  • 若不需要全部布局，关注后续版本的布局按需引入能力。
  • 生产环境启用 brotli 压缩，相比 gzip 可再省约 15%（117 KB → 99 KB）。
