Migrate from G6 v5

Migrate configuration, data, interactions, events, and extensions with a reversible business baseline

View source on GitHub

G6Lite and G6 v5 use separate npm packages and implementations. This guide uses G6 5.1.1 as its starting point and maps its usage to the public G6Lite APIs. G6 quick start · Graph API · GitHub Releases

Decide whether to migrate

Validate the most complex nodes, interactions, labels, and groups first. Keep G6 when arbitrary DOM/React nodes, multiple renderers, server rendering, full animation, algorithms, or established plugins are essential.

Installation and imports

Import values and types from @antv/g6-lite only; do not migrate to deep src/dist paths.

Data field mapping

Provide nodes/edges arrays, unique node IDs, and valid endpoints. Keep stable edge IDs. Use node x/y, comboId, and business data fields. Do not copy G6 internal models or assume per-node style compatibility.

Runtime node additions require positions; full replacement and incremental writes differ. See input data · data updates。

Node, Edge and Combo configuration

Built-in circle/rect and common edges reuse WebGL primitives; they do not replace arbitrary scene-graph shapes. State styles live in node.stateStyles, edge.stateStyles, and combo.style.stateStyles. Nested/collapsed/runtime-grouped Combo remains experimental.

Layout migration

Matching names do not guarantee matching options. Fix data and node sizes when mapping center, rankdir, iteration, and distance options. At runtime call setLayout then await layout. See layout contracts for cancellation and Worker boundaries.

Event migration

Use string names and GraphEventMap instead of G6 event enums. Element native events use nativeEvent; selection/drag derived payloads have their own contracts. Do not replace every event field globally. Pair listeners with off.

Extension, Transform and Plugin

G6 base classes do not migrate unchanged. Select the category and follow tutorials and contracts. The controlled context is not a full Graph. Hosts can explicitly inject plugin subscriptions, with cleanup in destroy.

Unsupported capabilities and alternatives

Run algorithms in a separate analysis pipeline and write results into data. Implement peripheral controls in application UI or Plugins. Keep G6 pages that cannot fit supported primitives, runtimes, or lifecycles; partial migration is not full compatibility.

Migration acceptance checklist

  1. Pin both versions and retain the original fallback.
  2. Verify data, styles, labels, states, groups, and key gestures.
  3. Cover updates, unsubscription, asynchronous unmounting, and repeated mounting.
  4. Measure layout, rendering, interactions, and resources under equivalent visual/runtime conditions before switching.
