Performance comparison

First-draw timing and browser bundle sizes for G6Lite, G6, Sigma.js, and ECharts on the same graph data

View source on GitHub

This comparison covers G6Lite, G6, Sigma.js, and the ECharts Graph series. All renderers receive the same precomputed positions, and all bundles use the same build settings. The 2026-11-13 run used a locally packaged G6Lite 0.1.0 build.

First-draw timing

The table shows the median time in milliseconds from graph creation through two animation frames after the render API completes. Headless Chromium uses the SwiftShader software renderer for WebGL in this run.

npm packageRenderer1,000 nodes / 3,000 edges (ms)5,000 nodes / 15,000 edges (ms)
@antv/g6-lite@0.1.0WebGL134.1146.1
@antv/g6@5.1.1Canvas 2D297.41,502.2
sigma@4.0.4 + graphology@0.26.0WebGL 2466.1748.4
echarts@6.1.0Canvas 2D56.6236.3

Test conditions

  • Apple M3 Pro, macOS (Darwin 25.2.0), headless Chromium 151.0.7922.34. The canvas is 900 × 600 CSS pixels at DPR 1. The WebGL renderer reports ANGLE (Google, Vulkan 1.3.0 (SwiftShader Device (LLVM 10.0.0) (0x0000C0DE)), SwiftShader driver).
  • Each library receives the same nodes, edges, and fixed positions. The graphs use circular nodes and straight edges, with labels and animation disabled and no layout run. For each size, each library warms up 3 times, then runs 20 interleaved samples. The instance is disposed after each sample.
  • Libraries are loaded before timing. Samples cover instance and internal model creation, the first render, and two animation frame callbacks. Sigma.js includes building the Graphology graph. Measure GPU execution, layout, and interactions separately. Download raw samples

These results apply only to the environment above and do not certify minimum supported browser versions. See Minimum browser versions for capability version references and the remaining acceptance scope.

Measuring your own graph

Use production data and target devices to measure layout, first draw, and interactions separately. For a slow startup, isolate layout from drawing before assessing Worker execution. For slow updates, reuse the graph and update data or states incrementally. For frame drops during zoom, compare labels, decorations, and viewport size one at a time.
