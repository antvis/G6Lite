# P5 官网首页优化建议（待确认）

## 状态

- 状态：待确认，暂不实施
- 日期：2026-07-24
- 当前处理：中文默认首页回退到 P5 前的视觉版本；仅修正已失效的文档链接，并让版本号读取 `package.json` 当前版本。
- 多语言说明：P5 前没有英文首页，`/en` 暂时保留已完成的英文基础页；中英文视觉统一放到本方案确认后处理。

## 1. 为什么单独暂停首页优化

首页同时承担品牌表达、能力说明、Benchmark 口径、示例入口和快速开始。与文档结构、SEO、静态输出相比，首页视觉和信息密度包含更多主观判断，也更容易因主视觉素材、性能数据和内容优先级变化而返工。

因此本轮先保留旧首页，继续完成 README、文档、Examples、技术指标、兼容性、多语言和静态发布链路；首页改版在本文件确认后单独实施和验收。

## 2. 旧首页需要保留的特征

- 居中的品牌区和明确的 G6-GL 产品识别。
- 可横向浏览的真实案例与布局截图，直接展示图可视化能力。
- 性能、开发体验、产品能力和安装入口等完整叙事。
- 已形成的 AntV 品牌色、圆角、卡片和明暗主题视觉语言。

## 3. 当前旧首页的已知问题

- 页面较长，性能、能力与价值表达存在重复，首屏之后的信息密度偏高。
- `~0ms`、`0.1ms`、`5k` 等历史展示值缺少与当前 Benchmark 报告的一一对应关系，不能作为稳定发布口径直接保留。
- Hero 案例跑马灯视觉丰富，但首屏焦点分散，且多张浅色截图在深色主题下的一致性有限。
- 最小代码仍包含旧行为命名和历史说明，需要改为当前包根稳定 API。
- 部分区块宽度、标题层级、卡片阴影和按钮规格不完全一致。
- 移动端页面较长，案例跑马灯、性能表格和流程图的阅读成本较高。
- P5 前没有英文首页，不能直接通过复制旧页面完成多语言，需要重新整理对应英文信息层级。

## 4. 建议方案

推荐采用“保留旧视觉语言、收敛内容结构”的渐进方案，不重新设计品牌风格。

首页收敛为五个主要区块：

1. Hero：品牌、稳定定位、快速开始、GitHub 和一个主案例入口。
2. 核心价值：WebGL 批渲染、增量更新、AntV 布局、受控扩展四项。
3. 最小代码：与 README、快速开始使用同一套稳定公开 API。
4. 精选案例与技术指标：案例按 API 概念组织；指标只展示可复现、可追溯的发布口径。
5. 文档与安装 CTA：连接快速开始、示例、技术指标和兼容性。

视觉上继续使用旧版的 AntV 品牌色和真实渲染截图，只调整以下内容：

- 统一内容最大宽度、区块间距、标题层级、按钮和卡片圆角。
- 降低首屏标题和后续模块之间的尺寸跳变。
- 主视觉优先使用内容居中、信息密度合适的真实截图；避免图形集中在角落产生大面积空白。
- 删除重复性能模块，不使用无法跨机器比较的营销跑分。
- 明暗主题分别检查截图背景、边框、代码块和文字对比度。
- 移动端将复杂表格和流程图改为纵向信息卡，不依赖横向滚动理解核心内容。

## 5. 实施边界

方案确认前不再修改首页结构、文案、主视觉、性能值或视觉样式。

确认后只修改首页相关组件和样式，不顺带调整文档页、API 页面、Examples 组件或构建工具。首页中涉及的指标必须引用技术指标文档中的同一数据源，示例必须来自 `playground/demos/catalog.json` 中面向官网发布的案例。

## 6. 验收标准

- 中文 `/` 与英文 `/en` 结构和信息层级一致，文案分别本地化。
- 桌面端、移动端、浅色和深色主题无溢出、遮挡、低对比度或异常留白。
- Hero、核心价值、最小代码、精选案例和 CTA 的主要链路均可点击。
- 首页不出现搜索、本地运行等不可用入口。
- 所有性能与包体积数据均可从技术指标页面追溯到运行环境和复现命令。
- 最小代码只使用 `@antv/g6-gl` 包根稳定公开 API，并与 README、快速开始保持一致。
- 静态构建、站点输出检查和内部链接检查通过。

## 7. 待确认项

- 是否采用推荐的渐进方案，保留旧版视觉语言并收敛为五个区块。
- Hero 保留案例跑马灯，还是改为单一主视觉加精选案例区。
- 首页允许公开展示哪些 Benchmark 或体积指标。
- 中英文首页是否在同一批次一次性交付。
