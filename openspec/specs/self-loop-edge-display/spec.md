# 自环边展示优化技术方案

> 日期：2026-08-13
> 状态：已实现，验证通过
> 分支：`feature/self-loop-edge-display`
> 基线：`origin/master@601c32f1`

## 1. 背景

当前同一节点存在多条自环边时，自环曲线虽然会按层级向外扩展，但多个边标签仍可能只显示一个或少量几个。用户期望适当增大自环之间的间距，使多条自环及其标签都能清晰展示。

仓库已经具备以下能力：

- 自环边使用三次贝塞尔曲线绘制，支持多条嵌套自环。
- 边标签通过自环的真实曲线路径定位，`start`、`center`、`end` 均不会落在节点中心。
- 标签层默认开启碰撞隐藏，避免真正重叠的标签全部堆叠显示。
- `playground/demos/self-loop-labels.ts` 已覆盖单条、三条和五条自环标签场景。

因此本次问题不是缺少自环标签能力，而是自环几何间距与标签碰撞判断共同导致的展示问题。

## 2. 根因

### 2.1 自环层级间距偏小

`src/renderer/renderer.ts` 当前使用：

```ts
const loopSize = 35 + loopIndex * 15;
```

自环标签默认取三次贝塞尔曲线的中点。按当前固定角度和控制点计算，相邻自环的中点锚点在 `zoom = 1` 时只相差约 `9.9px`。默认边标签字号为 `10px`，再加上背景留白后，视觉上容易挤在一起。

### 2.2 标签碰撞网格存在粗粒度误判

`src/renderer/labelGrid.ts` 当前只记录一个 `150px` 网格单元是否被占用，不记录单元内的真实标签包围盒。

这意味着两个标签即使没有实际相交，只要包围盒经过同一个网格单元，后绘制的标签也会被判定为碰撞并隐藏。多条自环标签集中在节点上方，通常都会落入同一个网格单元，因此仅小幅增大自环间距仍不能稳定展示全部标签。

## 3. 目标

1. 适当增大多条自环之间的默认层级间距，使曲线和箭头更容易区分。
2. 默认碰撞策略开启时，三条和五条自环在默认视图下能够展示各自标签。
3. 只有包围盒真实相交的标签才按现有顺序隐藏，不再因处于同一个粗粒度网格而误隐藏。
4. 自环曲线、标签路径缓存和箭头继续使用同一套几何参数，拖动、缩放和重绘后保持一致。
5. 不新增或修改公开 API，不要求业务关闭全局标签碰撞。

## 4. 非目标

- 不新增自环方向、角度、半径或间距的公开配置。
- 不改变单条自环的朝向、节点连接点和箭头方向。
- 不关闭或绕过全局 `label.hideOnCollision` 策略。
- 不增加多行、富文本、DOM 标签或多个标签合并为一个文本的能力。
- 不修改普通直线、弧线、折线、平行边或反向边的几何规则。
- 不修改节点、Combo、布局、交互和发布配置。

## 5. 方案

### 5.1 增大自环层级间距

在 `src/renderer/renderer.ts` 中将自环基础尺寸和层级间距收口为内部常量：

```ts
const SELF_LOOP_BASE_SIZE = 35;
const SELF_LOOP_LEVEL_GAP = 24;

const loopSize = SELF_LOOP_BASE_SIZE + loopIndex * SELF_LOOP_LEVEL_GAP;
```

保持第一条自环尺寸不变，避免单条自环发生不必要的视觉变化；从第二条开始把层级增量由 `15` 调整为 `24`。按当前曲线参数计算，相邻中心标签锚点在 `zoom = 1` 时约相差 `15.8px`，可以容纳默认 `10px` 标签及背景留白，同时不会让五条自环过度膨胀。

`loopSize` 继续同时用于：

- `EdgeLoopProgram.processLoop()` 的 WebGL 曲线；
- `edgePathCache` 中供标签采样的三次贝塞尔路径；
- 自环终点箭头的位置和方向。

本次不改变固定朝向和开口角度。

### 5.2 将标签网格改为“网格粗筛 + 包围盒精判”

保留 `LabelGrid` 的空间网格结构，但不再只存储“单元已占用”状态：

1. `register()` 将标签真实包围盒登记到其经过的网格单元。
2. `hasOverlap()` 先定位候选网格单元，再对单元内候选包围盒执行 AABB 相交判断。
3. 只有真实相交时返回 `true`；同单元但不相交的标签允许继续绘制。
4. `reset()` 同时清空单元索引和包围盒集合，保持每帧重新计算的现有生命周期。

该调整继续服务节点和边标签的共享碰撞层，保持以下语义不变：

- 节点标签先绘制，边标签后绘制，先登记者优先。
- `hideOnCollision: false` 时仍完全跳过碰撞查询和登记。
- Decoration 使用独立碰撞网格，不纳入本次变更。
- 自定义 Label Renderer 继续使用其测量结果参与真实包围盒判断。

### 5.3 更新自环标签示例

更新 `playground/demos/self-loop-labels.ts`：

- 保留单条、三条和五条自环分组。
- 使用更接近业务场景的可读关系标签，避免仅用 `T1`、`F1` 掩盖展示问题。
- 保留 `start`、`center`、`end` 切换与拖动节点验证。
- 状态说明明确默认碰撞开启时多条自环标签全部可见才通过。

不新增独立页面或站点信息架构变更。

## 7. 验收标准

### 7.1 自动验收

1. 三条和五条同节点自环的曲线路径按索引逐层向外扩展，相邻中心标签锚点在 `zoom = 1` 时保持不小于 `15px` 的间距。
2. 两个标签处于同一个 `150px` 网格单元但真实包围盒不相交时，二者均进入绘制路径。
3. 两个标签真实包围盒相交时，继续只绘制先登记的标签。
4. 跨越多个网格单元的标签与任一候选标签相交时能够正确识别碰撞。
5. 自环标签采样路径与 WebGL 自环、终点箭头使用相同的 `loopSize`，不存在标签与曲线层级错位。
6. 既有节点、普通边、自定义标签和 `hideOnCollision: false` 测试继续通过。

### 7.2 人工验收

1. 打开 `self-loop-labels` 示例，在默认 `center` 模式和默认缩放下，单条、三条、五条自环的所有关系标签均可见。
2. 多条自环的曲线、箭头和标签层级清晰，不覆盖节点主体，不出现明显背景重叠。
3. 切换 `start`、`center`、`end` 后，标签均沿各自真实曲线定位。
4. 拖动节点、缩放和移动画布后，标签继续跟随对应自环，无闪烁、错层或控制台错误。
5. 构造真实重叠的普通标签时，默认碰撞隐藏仍然生效。

## 9. 风险与控制

- 标签碰撞判断由单元占用变为单元内精确比较，会增加少量包围盒存储和比较成本。
  - 控制：继续使用网格做候选粗筛，不做全量两两比较；真实重叠场景可提前返回。
- 自环层级间距增大后，五条以上自环会占用更多画布空间。
  - 控制：第一条尺寸不变，层级增量只调整到 `24`；本次不引入无限放大的动态规则。
- 更精确的碰撞判断会让部分过去被误隐藏的普通标签显示出来。
  - 控制：这属于碰撞语义修正；真实包围盒相交、绘制优先级和关闭碰撞配置均保持不变，并通过回归测试锁定。
