# 官网样式美化技术方案

> 编写日期：2026-06-24
> 状态：待确认后实施
> 范围：`website/` 官网首页、全局视觉 token、文档站导航与通用组件样式微调
> 参考站点：https://infographic.antv.vision/

## 背景

当前官网已经完成 Next.js + Fumadocs 迁移，并具备首页、文档、性能指标、布局缩略图等基础内容。用户明确希望参考 AntV Infographic 官网风格。该参考站的核心观感是：白底留白、Alibaba PuHuiTi 字体、粉红主强调色、胶囊导航、轻阴影小卡片、大字号标题、真实模板/图形缩略图横向展示。

现有首页视觉方向偏“浅色科技感”，但还存在几个可继续打磨的问题：

1. 首屏仍是左右分栏式 Hero，右侧终端卡片信息密度偏低，不能第一时间展示 G6Lite 最核心的“图可视化产品感”。
2. 装饰性渐变光斑较多，页面气质容易偏模板化，且与图可视化引擎的真实能力关联不够强。
3. 卡片圆角、阴影、渐变、动效使用较重，文档型官网需要更克制、清晰、可扫描。
4. 功能卡片使用 emoji，和 AntV / Fumadocs 的工程化品牌质感不够统一。
5. 首页、CTA、代码块、性能卡、文档导航之间的视觉规则还可以进一步统一。

## 目标

- 对齐 AntV Infographic 的轻量品牌官网风格：干净白底、充足留白、柔和卡片、粉红强调和清晰主视觉。
- 让首屏直接呈现 G6Lite 的核心对象：大规模图渲染结果、布局能力和交互性能。
- 提升整体精致度，但保持技术文档站的克制、清晰和可读性。
- 保留现有内容结构和真实布局缩略图资产，避免大范围重构。
- 兼顾浅色 / 深色模式、移动端、静态导出和无障碍体验。
- 不引入新的重型前端依赖，不影响库源码构建。

## 非目标

- 不改动 `src/` 图渲染核心逻辑。
- 不重写 Fumadocs 文档渲染体系。
- 不新增在线服务或运行时数据接口。
- 不调整文档信息架构和正文内容。

## 参考站视觉拆解

根据 `https://infographic.antv.vision/` 首页观察，本次应吸收以下设计语言：

| 维度 | 参考站表现 | G6Lite 转译 |
| --- | --- | --- |
| 页面底色 | 大面积纯白，区块间用极浅灰分割 | 保持浅色模式纯白，次级区块使用 `#f6f8fb` 一类极浅冷灰 |
| 品牌强调 | 粉红 / 玫红为主色，按钮和 active nav 使用胶囊色块 | G6Lite 保留 AntV 蓝作为能力色，新增玫红作为官网品牌强调色 |
| 导航 | 顶部极轻、居中宽度、小字号胶囊导航 | 顶栏改为轻量胶囊 active 状态，弱化边框和阴影 |
| 首屏 | 左侧品牌与标题，右侧小型演示卡片，下面横向模板缩略图 | 左侧 G6Lite 标识和标题，右侧图配置/性能卡，下面布局缩略图横排 |
| 标题 | 4xl/5xl 大标题，行高紧凑但不拥挤 | Hero 标题控制在 44-56px，避免过度营销化 |
| 卡片 | 小圆角、轻阴影、浅色背景，内容留白充足 | 统一 8-12px 圆角，减少当前 24px/32px 大圆角 |
| 区块 | 大留白，浅灰整段背景承载代码演示 | 性能/代码区使用浅灰 band，而不是重渐变装饰 |
| 图像 | 真实模板缩略图，直接展示产品产物 | 使用现有真实 G6Lite 布局截图作为视觉资产 |

需要避免的是：大面积深色科技风、复杂极光光斑、过多旋转/漂浮装饰、单一蓝青渐变铺满页面。

## 设计方向

### 1. 首屏 Hero：从分栏终端改为产品感首屏

将首页首屏调整为更接近 AntV Infographic 的轻量结构：

- 左侧：G6Lite 标识、主标题、简短价值描述、主次按钮。
- 右侧：轻量演示卡片，可展示安装命令、布局配置、性能标签或小型图可视化预览。
- 首屏下方：横向排列 4-6 张布局缩略图，类似参考站模板卡片展示。
- 首屏背景保持白底或极淡粉蓝径向柔光，不做大面积极光。
- 首屏高度控制在可看到下一段内容露出的范围，避免用户误以为页面只有单屏。

建议结构：

```tsx
<section className="home-hero">
  <div className="home-hero__media" />
  <div className="home-hero__content">
    <p className="home-kicker">G6Lite</p>
    <h1>高性能 WebGL 图可视化引擎</h1>
    <p>万级节点渲染、增量交互更新、轻量布局能力。</p>
    <div>快速开始 / GitHub</div>
  </div>
</section>
```

### 2. 视觉 token：引入 Infographic 式玫红强调

当前品牌色集中在蓝青渐变。参考站主强调为粉红，本次建议保留 AntV 蓝作为图可视化能力色，同时引入玫红作为官网品牌强调：

| 用途 | 建议 |
| --- | --- |
| 官网强调 | Rose `#ff356a`，用于主按钮、active nav、少量标签 |
| 产品能力色 | AntV Blue `#1677ff`，用于性能数值、图元素和链接 |
| 辅助渐变 | Rose → Indigo，少量用于按钮或徽标，不作为大背景 |
| 数据/性能强调 | Cyan / Green 少量用于数值、状态 |
| 布局分类 | 使用现有缩略图背景的浅色系，但降低饱和度 |
| 页面背景 | 浅色用白 + 极浅冷灰，深色用中性深灰 |
| 边框/分割 | 比当前更明确的低透明度边框，减少阴影依赖 |

全局 token 继续放在 `website/src/app/global.css`，以 CSS variable 为主，Tailwind class 为辅。

### 3. 卡片与控件：统一半径、描边、悬浮反馈

- 首页重复卡片统一使用 8-12px 圆角，弱化大圆角。
- 减少大面积柔光阴影，改为边框、轻投影和 hover 位移。
- CTA 不再使用嵌套卡片式大容器，改为完整 section band。
- 代码窗口保留 mac 标题栏，但压低阴影、增强代码区对比度。
- 性能对比卡改为更紧凑的数据面板，强化数值和条形图可读性。
- 导航、按钮、标签采用参考站式 pill 形态，但避免所有组件都胶囊化。

### 4. 图标系统：用 lucide 替代 emoji / 手写 SVG

`website/package.json` 已有 `lucide-react`，建议：

- 功能卡片使用 `Zap`, `MousePointerClick`, `Network`, `Layers`, `Gauge`, `PackageCheck` 等 lucide 图标。
- GitHub 按钮可继续使用现有 SVG，也可封装为统一 `IconButton` 风格；若新增 GitHub 图标包会增加依赖，不建议。
- 按钮、链接、文档浮动 Ask AI 入口保持尺寸和圆角一致。

### 5. 首页区块节奏

建议首页顺序保持不变，但调整视觉表达：

1. Hero：产品主视觉 + 核心价值 + CTA。
2. StatsBand：保留 count-up，背景改为干净分割带。
3. Layout Gallery：参考 Infographic 模板缩略图区，改为静态横向卡片或低速横向滚动，减少旋转和强动效。
4. Performance：改为数据面板式三列卡，降低营销感。
5. Code Demo：左右布局保留，增加移动端代码可读性。
6. Features：lucide 图标 + 统一小卡片。
7. CTA：全宽浅色 band，避免大卡片包裹卡片。

## 文件变更计划

| 文件 | 变更 |
| --- | --- |
| `website/src/app/(home)/page.tsx` | 调整首页 Hero、画廊位置、性能区、功能卡图标和 CTA 结构 |
| `website/src/app/(home)/stats-band.tsx` | 微调数值带背景、间距、移动端排版 |
| `website/src/app/(home)/code-block.tsx` | 统一代码窗口圆角、边框、阴影与移动端溢出 |
| `website/src/app/global.css` | 更新品牌 token、通用工具类、移除过重装饰类或降低使用 |
| `website/src/lib/layout.shared.tsx` | 如有必要，微调顶栏链接、按钮和导航宽度 |
| `website/public/layouts/*` | 优先复用；如首屏需要更合适图像，再通过现有脚本生成新截图 |

## 实施步骤

1. 确认方案后，先启动官网开发服务，截取当前首页作为对照。
2. 修改 `global.css` 中的 token 和基础工具类，建立新的视觉基线。
3. 重构首页首屏和区块顺序，确保移动端不溢出、不重叠。
4. 替换功能卡 emoji 为 lucide 图标，统一按钮和卡片样式。
5. 调整文档顶栏与首页宽度、边距、按钮形态的一致性。
6. 使用 Playwright 对桌面和移动端首页截图验证。
7. 运行官网构建 / 类型检查，确保静态导出不受影响。
8. 完成后在 `openspec/changes/` 新增实施变更记录。

## 验证方式

- `npm --prefix website run lint`
- `npm --prefix website run types:check`
- `npm --prefix website run build`
- 本地浏览器验证：
  - 首页桌面端首屏、宽屏、移动端布局正常。
  - 文案不遮挡图像重点，不和按钮/卡片重叠。
  - 深色模式可读性正常。
  - 跑马灯或动画在 `prefers-reduced-motion: reduce` 下可降级。
  - 图片资源在静态导出路径下可正确加载。

## 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 首屏图片遮罩影响文字可读性 | 使用固定对比度遮罩，并分别检查浅色 / 深色模式 |
| 首页视觉改动影响文档站 Fumadocs 默认样式 | 全局样式尽量限定作用域到首页 class，少覆盖 Fumadocs 内部选择器 |
| 真实截图在 GitHub Pages 子路径下加载异常 | 使用站点已有 public 静态资源路径规则，并通过 `next build` 验证 |
| 动效影响性能或可访问性 | 控制动画数量，保留 `prefers-reduced-motion` 降级 |

## 确认点

实施前需要确认以下方向：

1. 首屏是否接受调整为 AntV Infographic 式“左标题 + 右轻演示卡 + 下方布局缩略图”。
2. 是否接受引入玫红 `#ff356a` 作为官网强调色，同时保留 AntV 蓝用于产品能力表达。
3. 是否需要保留当前跑马灯；若保留，建议改为更轻的模板缩略图展示，减少旋转和强阴影。
