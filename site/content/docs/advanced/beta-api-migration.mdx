本页适用于从较早的 `0.1.0-beta` 版本升级。它说明 API 与扩展体系重新基线后的迁移方式；如果你正在从 G6 v5 迁移，请改看 [G6 v5 迁移说明](/docs/advanced/g6-v5-migration)。

## Graph 创建入口保持不变

`new Graph(options)` 是唯一推荐且长期保留的创建入口。本轮没有引入 `createGraph()`，也不会要求把 Graph 改为无 `new` 的函数调用。

```ts
import { Graph } from '@antv/g6-gl';

const graph = new Graph(options);
await graph.render();
```

`Graph`、DataModel、Renderer、Scheduler 和 WebGL Program 等需要长期持有状态或资源的核心模块继续使用 class。函数化只针对用户扩展和无状态计算。

## Node 扩展改用统一 register

早期 beta 允许继承 `BaseNode` 并调用 `registerNode()`：

```ts
import { BaseNode, registerNode } from '@antv/g6-gl';

class StatusNode extends BaseNode {
  base = 'rect' as const;
  style = { width: 96, height: 34 };
}

registerNode('status-node', StatusNode);
```

新代码应声明无状态 `NodeExtension`，并通过统一入口注册：

```ts
import { register, type NodeExtension } from '@antv/g6-gl';

const statusNode: NodeExtension = {
  base: 'rect',
  style: { width: 96, height: 34 },
  getStyle(node) {
    return node.data?.status === 'error'
      ? { fill: '#fff2f0', stroke: '#ff4d4f' }
      : { fill: '#e6f4ff', stroke: '#1677ff' };
  },
};

register('node', 'status-node', statusNode);
```

`BaseNode`、`BreathingNode` 和 `registerNode()` 在 beta 迁移期继续可用，但均已 deprecated。内置呼吸节点直接配置 `node: { type: 'breathing-node' }`，无需实例化 `BreathingNode`。

## 有状态扩展使用 extensionFactory

Node、Edge、Label、Decoration 等无状态描述可以直接注册对象。有内部状态的 Behavior、Layout、Transform 和 Plugin 应使用 `extensionFactory()`，避免实例在不同 Graph 之间共享：

```ts
import {
  extensionFactory,
  register,
  type BehaviorExtension,
  type ExtensionContext,
} from '@antv/g6-gl';

register(
  'behavior',
  'business-click',
  extensionFactory(() => {
    let context: ExtensionContext | undefined;

    return {
      init(nextContext) {
        context = nextContext;
      },
      getEvents() {
        return {
          'node:click': (event) => {
            if (event.targetId) context?.state.set(event.targetId, ['selected']);
          },
        };
      },
      destroy() {
        context = undefined;
      },
    } satisfies BehaviorExtension;
  }),
);
```

裸 factory 和 class constructor 在 beta 阶段仍兼容，但不再是推荐写法。对象实例只进行尽力克隆，只有 `extensionFactory()` 保证有状态实例隔离。扩展创建、`init`、`update`、类别能力调用和 `destroy` 均由引擎隔离错误。

## context.graph 改为受控能力

新扩展不应保存或调用完整的 `context.graph`。根据职责使用以下入口：

- `context.data`：查询节点或边，并通过受控 API 更新业务数据。
- `context.state`：读取、替换或清理元素状态。
- `context.viewport`：进行坐标转换和读取 zoom。
- `context.requestRender()`：扩展自身视觉状态变化时请求刷新。
- `context.isDestroyed()`：确认所属 Graph 是否已经销毁。

```ts
init(context) {
  const node = context.data.getNode('node-1');
  context.data.updateNode('node-1', { score: Number(node?.data?.score ?? 0) + 1 });
  context.state.set('node-1', ['selected']);

  const point = context.viewport.screenToGraph({ x: 120, y: 80 });
  const zoom = context.viewport.getZoom();
  context.requestRender();
}
```

`context.graph`、`context.screenToGraph()`、`context.graphToScreen()` 和 `context.getZoom()` 只保留 beta 兼容，正式扩展应迁移到上述分组能力。

`context.data.getNode()` / `getEdge()` 返回只读结构快照，并复制状态数组和顶层 `data` 对象；更新数据必须继续使用 `context.data.updateNode()` / `updateEdge()`。

## Internal 类型改为公开 Model

查询 API 不再向业务暴露 `InternalNode`、`InternalEdge` 或 `InternalCombo`。从包根使用新的只读 Model 类型：

```ts
import type { ComboModel, EdgeModel, ElementModel, NodeModel } from '@antv/g6-gl';

const node: NodeModel | undefined = graph.getNodeData('node-1');
const edge: EdgeModel | undefined = graph.getEdgeData('edge-1');
const combo: ComboModel | undefined = graph.getComboData('combo-1');
const element: ElementModel | undefined = graph.getElementData('node-1');
```

Model 是 Graph 持有的只读查询视图，不承诺不可变快照或稳定对象身份。不要直接改写查询结果；节点、边、位置和状态更新应继续通过 Graph API 完成。

## 不再依赖 internal 与深层路径

`DataModel`、`RenderScheduler`、`RefreshLevel`、`RendererData` 和 Renderer 低层能力不再属于包根公开契约。源码深层路径也不承诺兼容。

迁移时遵循以下原则：

- `getLayoutNodes()` 改用公开的 `getNodes()` 查询 Model。
- 不调用 `scheduleRender()`；Graph 数据、状态、布局和相机 API 会自行调度，扩展内部使用 `context.requestRender()`。
- 不调用 `pickAt()` 或直接访问 Renderer；通过 Graph 元素事件或 Behavior 获取命中结果。
- 不依赖 `getCanvas()`；DOM 扩展应保存创建 Graph 时传入的容器引用。
- 类型和函数统一从 `@antv/g6-gl` 包根导入，不从 `src/types`、`renderer/*` 等路径导入。

## 自定义布局改用 execute

自定义布局通过 `LayoutExtension.execute()` 接入。每次执行都应返回新的节点坐标，并响应 `AbortSignal`：

```ts
import { extensionFactory, register, type LayoutExtension } from '@antv/g6-gl';

register(
  'layout',
  'horizontal-business',
  extensionFactory(() => {
    const layout: LayoutExtension = {
      execute(data, { height, signal }) {
        if (signal?.aborted) throw new DOMException('Layout aborted', 'AbortError');
        return {
          nodes: data.nodes.map((node, index) => ({
            ...node,
            x: 120 + index * 180,
            y: height / 2,
          })),
        };
      },
    };
    return layout;
  }),
);
```

内置 `mindmap`、`indented` 和 `fishbone` 已改为无状态 executor，但配置 API 没有变化。已有业务仍使用 `layout: { type: 'mindmap' }` 等配置；即使设置 `worker: true`，也不会退化为随机布局。

布局计算必须以 `execute(data, runtime)` 收到的 `data` 和只读 `runtime.options` 为准。`context.data` 只代表 Graph 已提交的数据，首次 render 可能为空，数据替换过程中也可能是上一版。直接调用 `runLayout(data, config)` 时没有 Graph context，因此跳过 `init()`、直接执行 `execute()`，完成后仍调用 `destroy()`。

## ESM 与 .js 后缀

当前发布包是 ESM-only：

```ts
import { Graph } from '@antv/g6-gl';
```

CommonJS `require('@antv/g6-gl')` 尚不属于支持范围。业务代码无需为包入口添加 `.js` 后缀。

仓库源码中的 `./module.js` 相对 import 是当前 `tsc` 直接生成 Node ESM 产物所需的解析约定。除非未来先落地新的 ESM/CJS 构建方案和消费测试，否则不要机械删除这些后缀。

## 升级检查清单

- 保留 `new Graph(options)`，无需迁移创建方式。
- 将 `BaseNode` / `registerNode()` 改为 `NodeExtension` / `register('node', ...)`。
- 将有状态裸 factory 或 constructor 改为 `extensionFactory()`。
- 将 `context.graph` 和平铺 viewport 方法改为受控 Context 分组。
- 将 `Internal*` 类型改为公开 `*Model` 类型。
- 删除 DataModel、Renderer、Scheduler 和源码深层路径依赖。
- 自定义布局使用 `LayoutExtension.execute()`，并处理取消信号。
- 确认消费环境使用 ESM import。

完整扩展契约见[扩展体系](/docs/advanced/extensions)，当前公开签名见 [API 参考](/docs/api)。
