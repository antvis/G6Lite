---
title: 性能调优
description: 大图首屏、交互、标签、状态和布局的优化建议
---

G6Lite 的优势在渲染后交互和状态更新。首屏耗时通常由布局计算决定，而不是 WebGL draw call。

## 首屏优化

- 如果后端已有布局坐标，直接传 `x` / `y` 并省略 `layout`。
- 大图优先使用 `grid`、`circular` 等确定性轻量布局，谨慎使用高迭代力导向。
- force 系布局可开启 `worker: true`，避免阻塞主线程。
- 控制首屏边数量和标签数量，必要时先渲染骨架，再逐步补充细节。

```ts
layout: {
  type: 'force',
  worker: true,
}
```

## 交互优化

高亮、选中、隐藏等场景优先使用状态 API：

```ts
graph.setItemState('n1', 'highlight', true);
graph.batchSetState([
  { id: 'n2', state: 'inactive', value: true },
  { id: 'e1', state: 'inactive', value: true },
]);
```

状态变更会走增量刷新路径，适合高频交互。

## 样式优化

- 静态样式成本最低。
- 函数式样式适合按数据分类，但不要在函数中做复杂计算。
- 需要复杂映射时，先在业务侧预计算成字段，再在样式函数中读取。

```ts
node: {
  style: {
    fill: (node) => node.data?.color as string,
  },
}
```

## 标签优化

标签由 Canvas 2D 绘制。大规模图中，全量标签可能成为交互瓶颈。

建议：

- 首屏只展示关键节点标签。
- 缩放到一定层级后再展示更多标签。
- 悬停、选中或聚焦时展示局部标签。

## 复现与度量

布局基准：

```bash
node --experimental-vm-modules scripts/bench-layout-5k.mjs
```

端到端首屏自测：

```ts
const t0 = performance.now();

graph.on('afterrender', () => {
  console.log('firstRender:', performance.now() - t0);
});

await graph.render();
```

更多基线数据见 [性能指标](/docs/metrics/performance)。
