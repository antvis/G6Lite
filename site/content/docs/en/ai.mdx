## Use the Skill locally

Give the repository's [antv-g6lite-graph](https://github.com/antvis/G6Lite/tree/master/skills/antv-g6lite-graph) directory to a Skill-capable agent and follow that client's installation process. The Skill does not install the G6Lite npm package. Clients with explicit invocation can use:

```text
Use $antv-g6lite-graph to implement the graph described below.
Check the installed @antv/g6-lite version and package-root types first.
```

Run `npm ls @antv/g6-lite` in the project to identify its version. The Skill emphasizes package-root APIs, browser lifecycle, supported capabilities, and incremental verification. Query the [API overview](/en/docs/api) instead of inventing deep imports or copying v5 plugins.

## Good tasks for an agent

| Task | Inputs to provide |
| --- | --- |
| Create or update a graph | Framework, sample data, ID/endpoint rules, size, container dimensions |
| Add selection, dragging, or Tooltip | Gestures, business responses, state retention, cleanup |
| Change layout, labels, or branding | Supplied positions, layout goals, label density, target screenshot |
| Migrate or troubleshoot | Installed version, minimal code, errors, reproduction, behavior to preserve |

### Copyable input template

```text
Use $antv-g6lite-graph for this task:
- Project: React + TypeScript; inspect actual dependencies and G6Lite version
- Data: nodes A/B/C and edges A→B, A→C; stable node IDs
- Container: 100% width, 360px height; create only on the client
- Layout: circular; node ID labels; zoom, pan, and node dragging
- Update: add D and B→D; reuse Graph and preserve the viewport
- Cleanup: unmounting before the first render finishes must release resources
- Deliver: complete component, dependencies, verification steps and expected results
Confirm real fields and methods before implementation. Identify unsupported needs.
```

Replace the framework, data size, and interactions with your requirements. For Vue, use the lifecycle in [Vue integration](/en/docs/getting-started/vue).

## Recommended workflow

1. **Render a minimal graph**: verify container, data, and first render against the [quick start](/en/docs/getting-started/quick-start).
2. **Add one capability**: introduce styles, layout, states, or extensions individually. Use [API contracts](/en/docs/api) and [guides](/en/docs).
3. **Verify updates and navigation**: change data, leave quickly, and mount repeatedly. Enable StrictMode in React.
4. **Accept real workloads**: check labels, picking, layout time, and cleanup on target devices; see [performance measurements](/en/docs/metrics/performance).

### Minimum acceptance steps

The template starts with 3 nodes / 2 edges and updates to 4 / 3 while preserving the viewport and dragging. Unmounting must remove the canvas; remounting must work again. Verify both type checking and browser interaction instead of judging from a code screenshot.
