---
title: Graph
description: Create a graph and call its data, state, viewport, layout, and event methods
---

`Graph` is the instance application code uses to operate one graph. Import it from the package root, pass [options](/en/docs/api/options), then `await graph.render()`.

```ts
import { Graph } from '@antv/g6-lite';

const graph = new Graph({ container, data });
await graph.render();
```

Data writes, state changes, and `layout()` run after the first successful `render()`. After `destroy()`, those methods return immediately.

## Lifecycle

See the [lifecycle method reference](/en/docs/api/graph/lifecycle) for construction, rendering, destruction, and refresh contracts. [Graph lifecycle](/en/docs/concepts/graph-lifecycle) explains stage selection and cleanup.

### `new Graph(options)`

[Construct an instance](/en/docs/api/graph/lifecycle#new-graph): container requirements, canvas ownership, and GraphOptions.

### `render()`

[render](/en/docs/api/graph/lifecycle#render): valid initialization, repeated rendering, event order, and cancellation boundaries.

### `destroy()`

[destroy](/en/docs/api/graph/lifecycle#destroy) releases instance resources. Application requests, timers, and DOM listeners still need application cleanup.

### `destroyed`

[destroyed](/en/docs/api/graph/lifecycle#destroyed) is a read-only destruction flag, not proof of successful rendering or current task validity.

### `refresh()`

[refresh](/en/docs/api/graph/lifecycle#refresh) reprocesses styles and draws, without reinitialization, layout, or fitting.

## Replacing data and styles

### `setData()`

[setData](/en/docs/api/graph/data-mutations#setdata) replaces graph data; see the reference for arguments, fitting, cancellation, and failure. Follow the [data guide](/en/docs/guides/data)。

### `updateOptions()`

[updateOptions](/en/docs/api/graph/lifecycle#updateoptions) updates node, edge, label, and theme. See the reference for object, function, and state-style merge rules. Layout, Behavior, and Plugin configuration are not accepted; use [setLayout + layout](/en/docs/api/graph/layout) to change layouts.

## Changing nodes and edges

Use after a valid render. See signatures and batch boundaries in [data mutations](/en/docs/api/graph/data-mutations)。

### Nodes

[addNode(s)](/en/docs/api/graph/data-mutations#addnode) · [updateNodeData](/en/docs/api/graph/data-mutations#updatenodedata) · [updateNodePosition(s)](/en/docs/api/graph/data-mutations#updatenodeposition) · [removeNode(s)](/en/docs/api/graph/data-mutations#removenode)

Supply positions on addition. Data merges shallowly; node removal also removes adjacent edges, without layout or fitting.

### Edges

[addEdge(s)](/en/docs/api/graph/data-mutations#addedge) · [updateEdgeData](/en/docs/api/graph/data-mutations#updateedgedata) · [removeEdge(s)](/en/docs/api/graph/data-mutations#removeedge)

Addition returns actual IDs; batch updates can change endpoints; removing edges leaves nodes intact.

[findNodesByState](/en/docs/api/graph/states#findnodesbystate), [findEdgesByState](/en/docs/api/graph/states#findedgesbystate), and [findCombosByState](/en/docs/api/graph/states#findcombosbystate) query IDs; [clearItemStates](/en/docs/api/graph/states#clearitemstates) clears business states.

## Viewport

See the [viewport method reference](/en/docs/api/graph/viewport) for camera, zoom, fitting, focus, sizing, and conversion contracts. The [viewport guide](/en/docs/guides/viewport) covers tasks; the [concept page](/en/docs/concepts/viewport) explains coordinate spaces.

Inspect and restore cameras with [getCamera](/en/docs/api/graph/viewport#getcamera), [setCamera](/en/docs/api/graph/viewport#setcamera), and [resetCamera](/en/docs/api/graph/viewport#resetcamera).

### Container resize

[setSize](/en/docs/api/graph/viewport#setsize) synchronizes canvas dimensions. ResizeObserver handles container CSS changes. [autoFit](/en/docs/api/options#autofit) controls resize fitting, followed by resize. See the [live width-switching example](/en/docs/api/graph/viewport#fitting-after-a-container-narrows-or-widens).

### `zoomTo()` and `zoomBy()`

[getZoom](/en/docs/api/graph/viewport#getzoom) reads zoom; [zoomTo](/en/docs/api/graph/viewport#zoomto) sets an absolute value, and [zoomBy](/en/docs/api/graph/viewport#zoomby) multiplies it. See the reference for anchors and ZoomOptions, and [Behavior configuration](/en/docs/api/options/behaviors#navigation-and-dragging) for wheel limits.

### `fitView()`

[fitView](/en/docs/api/graph/viewport#fitview) adjusts translation and zoom; [fitCenter](/en/docs/api/graph/viewport#fitcenter) centers without changing zoom. See [preserving the view on refresh](/en/docs/guides/viewport#refresh-data-with-or-without-fitting).

### Coordinate conversion

[screenToGraph](/en/docs/api/graph/viewport#screentograph) converts client CSS positions to graph coordinates; [graphToScreen](/en/docs/api/graph/viewport#graphtoscreen) does the reverse. See the [coordinate guide](/en/docs/guides/viewport#convert-coordinates-to-position-dom-content) for a live observer and DOM positioning.

## Layout

Signatures, preconditions, events, and cancellation are in the [layout method reference](/en/docs/api/graph/layout): [setLayout](/en/docs/api/graph/layout#setlayout) stores configuration, [layout](/en/docs/api/graph/layout#layout) computes positions, and [cancelLayout](/en/docs/api/graph/layout#cancellayout) discards pending work.

See the [configuration reference](/en/docs/api/options/layout) for fields and the [Layout guide](/en/docs/guides/layout) for steps. Use [runLayout](/en/docs/api/graph/layout#runlayout) to compute positions without Graph.

## Events

Register and remove listeners with [on](/en/docs/api/graph/events#on), [off](/en/docs/api/graph/events#off), and [once](/en/docs/api/graph/events#once). Subscriptions can be registered before the first render.

- [GraphEventMap](/en/docs/api/graph/events#grapheventmap): argument tuples, subscription types, and custom-name boundaries.
- [Element payloads](/en/docs/api/graph/events#element-event-payloads), [selection](/en/docs/api/graph/events#selection-events), and [dragging](/en/docs/api/graph/events#drag-events): complete fields and trigger conditions.
- [Lifecycle and data](/en/docs/api/graph/events#lifecycle-and-data-events): timing for rendering, layout, mutations, resizing, and destruction.

For business integration and inline code with previews, see the [event guide](/en/docs/guides/events). Activate Behaviors using [interaction combinations](/en/docs/guides/interactions).
