Subscribe through a Graph instance. This page defines the complete contract; see the [event guide](/en/docs/guides/events) for workflows and the [Behavior reference](/en/docs/api/options/behaviors) for activation and options.

## on

`graph.on<K extends keyof GraphEventMap>(event: K, handler: Handler<GraphEventMap[K]>): void`

Add a persistent listener. Register before the first render to receive initial layout/render events. Adding after destruction does nothing. Duplicate registrations invoke the function multiple times. The return value is neither an unsubscribe function nor a chainable Graph.

## off

`graph.off<K extends keyof GraphEventMap>(event: K, handler: Handler<GraphEventMap[K]>): void`

Remove listeners with the same event name and function reference, including a pending once listener. All duplicate registrations of that function are removed. Missing registrations are a no-op. The public method requires a handler and has no remove-all overload.

## once

`graph.once<K extends keyof GraphEventMap>(event: K, handler: Handler<GraphEventMap[K]>): void`

Receive only the next occurrence after registration; previous events are not replayed. Adding after destruction does nothing. Returns void; cancel with off.

## GraphEventMap

The package root exports GraphEventMap, GraphElementEvent, NodeGraphEvent, EdgeGraphEvent, ComboGraphEvent, CanvasGraphEvent, and Handler. Map values are argument tuples: destroy is [], and every other event below has one object argument.

```ts
import type { Graph, GraphEventMap, Handler } from '@antv/g6-lite';

declare const graph: Graph;
const onClick: Handler<GraphEventMap['node:click']> = ({ nodeId, nativeEvent }) => {
  console.log(nodeId, nativeEvent.clientX);
};
graph.on('node:click', onClick);
graph.off('node:click', onClick);
graph.once('destroy', () => console.log('destroyed'));
```

All three subscription methods retain the `method<Args extends unknown[]>(event: string, handler: Handler<Args>): void` overload for unknown names and application-declared arguments. It neither rejects misspelled names nor creates events. Graph has no public emit. Use an application event channel for business events; the [custom Behavior](/en/docs/guides/custom-behavior#event-typing) event-map generic provides consumer-side typing only.

<details>
<summary>Listener ordering and exceptions</summary>

Listeners run synchronously in registration order, with once removed before invocation. A Behavior handling an element event can synchronously emit a nested derived event. Do not assume application code always observes node:click before node:selectchange. Query state from the appropriate derived completion event when you need the final selection.

Exceptions from ordinary graph.on handlers propagate and may interrupt subsequent listeners or the operation. Handle errors in application callbacks and rejected asynchronous work yourself; dispatch does not await Promises. A * subscription receives payloads without an additional event-name argument, so it cannot provide a named universal event log.

</details>

## Element event payloads

| Field | Type / meaning |
| --- | --- |
| targetType | node / edge / combo / canvas; the corresponding literal in NodeGraphEvent, EdgeGraphEvent, ComboGraphEvent, or CanvasGraphEvent |
| targetId | Required string for nodes, edges, and Combos; no target ID on canvas |
| data? | Optional business data from the node/edge, rather than a complete GraphNode/GraphEdge; not supplied for Combo or canvas |
| client | `{ x, y }` in viewport CSS pixels, equal to native clientX/clientY |
| canvas | `{ x, y }` in CSS pixels from the canvas top-left, not DPR-scaled buffer pixels |
| graph | `{ x, y }` in graph coordinates after the inverse camera transform; suitable for graph positioning after pan/zoom |
| nativeEvent | MouseEvent for clicks, hover, press/release; WheelEvent for wheel. A pointer name does not imply PointerEvent or touch support |
| event | The same original object as nativeEvent; a deprecated alias only in this payload family |
| nodeId | Required string in NodeGraphEvent |
| edgeId / edgeIndex | Required string / number in EdgeGraphEvent. Without an explicit edge ID the dispatcher can fall back to an index string; do not persist edgeIndex across data replacements |
| source / target | Required endpoint node IDs in EdgeGraphEvent, both strings |
| comboId | Required string in ComboGraphEvent |

NodeGraphEvent and EdgeGraphEvent accept data and native-event generics. ComboGraphEvent and CanvasGraphEvent accept a native-event generic. GraphEventMap already narrows the native type by event name; business data remains an optional Record whose fields the application must validate.

### Element event inventory

Every name below is an individual event, not a wildcard expansion. The dispatcher is mounted by the first render; no additional Behavior is required.

| Event names | Payload |
| --- | --- |
| node:pointerover, node:pointerenter, node:pointermove, node:pointerleave, node:pointerdown, node:click, node:dblclick, node:contextmenu | NodeGraphEvent with MouseEvent |
| node:wheel | NodeGraphEvent with WheelEvent |
| edge:pointerover, edge:pointerenter, edge:pointermove, edge:pointerleave, edge:pointerdown, edge:click, edge:dblclick, edge:contextmenu | EdgeGraphEvent with MouseEvent |
| edge:wheel | EdgeGraphEvent with WheelEvent |
| combo:pointerdown, combo:click, combo:dblclick, combo:contextmenu | ComboGraphEvent |
| canvas:pointermove, canvas:pointerdown, canvas:pointerup, canvas:click, canvas:dblclick, canvas:contextmenu | CanvasGraphEvent with MouseEvent |
| canvas:wheel | CanvasGraphEvent with WheelEvent |

<details>
<summary>Picking, hover, and gesture boundaries</summary>

Picking priority is node → edge → Combo → canvas. Clicks and presses dispatch only to the picked target family, without bubbling to Combo or canvas. Movement and wheel on a Combo background use canvas events; there are no combo:pointermove/over/leave/wheel events, nor node:pointerup or edge:pointerup.

When mousemove hits a new node/edge, the old target receives pointerleave, then the new target receives pointerover → pointerenter → pointermove. Further movement on the same target emits pointermove only. Empty or Combo backgrounds emit canvas:pointermove. Leave coordinates describe the pointer at departure. A consumed drag suspends hover picking. A consumed gesture or release more than 3 CSS pixels from press suppresses the next click, without promising to cancel dblclick.

canvas:pointerup comes from window mouseup, does not pick the release target, and does not require a preceding press on this Graph; track your own gesture start. contextmenu prevents the browser menu. Returning false from a normal handler does not cancel dispatch or other Behaviors.

</details>

## Selection events

These are plain payload objects without client/canvas/graph/nativeEvent. Their event field remains an actively used MouseEvent field.

| Event | Complete payload | When emitted |
| --- | --- | --- |
| node:selectchange | `{ nodeId: string; selected: boolean; event: MouseEvent }` | After click-select toggles the clicked node |
| edge:selectchange | `{ edgeId: string; edgeIndex: number; source: string; target: string; selected: boolean; event: MouseEvent }` | After click-select toggles the clicked edge |
| selection:clear | `{ ids: string[]; event: MouseEvent }` | click-select clears a nonempty selection; ids can mix nodes and edges |
| brush:select, brush:end | `{ nodeIds: string[] }` | brush-select: select for nonempty hits; end at gesture completion, possibly empty |
| lasso:select, lasso:end | `{ nodeIds: string[] }` | lasso-select: select for nonempty hits; end at gesture completion, possibly empty |

Brush, lasso, and programmatic selected-state updates do not emit per-node selectchange or selection:clear. Clearing selection does not emit per-item deselection events. Lasso nodeIds describes this gesture's set, which can differ from the final global selection; query findNodesByState('selected') / findEdgesByState('selected') for the latter. Replacement rules are in the [selection reference](/en/docs/api/options/behaviors#selection).

## Drag events

| Event | Complete payload | Timing |
| --- | --- | --- |
| node:dragstart | `{ nodeId: string; nodeIds: string[]; event: MouseEvent }` | drag-node exceeds 3 CSS pixels, before the first position write |
| node:drag | `{ nodeId: string; nodeIds: string[]; dx: number; dy: number; event: MouseEvent }` | After position updates; dx/dy are graph-coordinate displacements from gesture start, not per-frame deltas |
| node:dragend | `{ nodeId: string; nodeIds: string[] }` | Release after a real drag; no native-event argument |
| combo:dragstart | `{ comboId: string; event: MouseEvent }` | drag-node moves a Combo background beyond the threshold |
| combo:drag | `{ comboId: string; dx: number; dy: number; event: MouseEvent }` | After member positions are updated; same displacement units |
| combo:dragend | `{ comboId: string }` | Release after a real Combo drag |
| edge:dragstart, edge:drag | `{ edgeId?: string; edgeIndex: number; source: string; target: string; dragEnd: 'source' or 'target'; event: MouseEvent }` | drag-edge starts at press without the node-drag threshold; movement emits drag |
| edge:dragend | `{ edgeId?: string; edgeIndex: number; source: string; target: string; originalSource: string; originalTarget: string; reconnected: boolean; newEndpoint?: string; event: MouseEvent }` | At release; source/target are proposed endpoints for a valid drop, original endpoints otherwise |

During multi-node dragging, nodeId is the first nodeIds entry, not necessarily the pressed node. Read getNodePosition at dragend to persist results through your own API. reconnected means a valid drop target was found; it neither confirms a data write nor guarantees different endpoints. drag-edge emits events only; the write-back example is in [interaction combinations](/en/docs/guides/interactions#event-dispatch).

## Lifecycle and data events

| Event | Complete payload | Timing |
| --- | --- | --- |
| beforelayout, layout:start | `{ nodeCount: number }` | In order before calculation for render / layout / setData with a configured layout and nonempty nodes |
| layout:end, afterlayout | `{ duration: number; nodeCount: number }` | In order after valid computation, before write-back; duration is calculation milliseconds, excluding drawing |
| beforerender | `{ nodeCount: number; edgeCount: number }` | Explicit render, after layout/runtime preparation and before fitting and synchronous drawing |
| afterrender | `{ nodeCount: number; edgeCount: number }` | After explicit render's synchronous draw; not a completion event for every animation frame or partial update |
| resize | `{ width: number; height: number }` | After resizing and optional auto-fit; dimensions are container CSS pixels |
| destroy | No arguments | First destroy, after marking destroyed and cancelling pending layout, before runtime/canvas cleanup; graph listeners are then removed |
| datachange | `{ nodeCount: number; edgeCount: number }` | After a valid setData writes data, optionally fits, and requests drawing; not an item diff |
| afteradditem | `{ type: 'node'; id: string }` or `{ type: 'edge'; id: string; source: string; target: string }` | addNode(s) / addEdge(s) after scheduling drawing, once per item in batch calls |
| afterremoveitem | `{ type: 'node' or 'edge'; id: string }` | removeNode(s) / removeEdge(s) after scheduling; incident edges removed with a node do not emit separate edge events |
| afterupdateitem | `{ type: 'node'; id: string; action: 'position' or 'data' }` or `{ type: 'edge'; id: string; action: 'data' }` | updateNodePosition(s) / updateNodeData / updateEdgeData, once per batch result; node dragging also emits position updates |
| combo:collapse, combo:expand | `{ comboId: string }` | After collapseCombo / expandCombo changes state and schedules; no repeated event if already in that state |

Incremental events describe method execution, not a guarantee that values changed. setData does not emit item-by-item add/remove/update events. State, visibility, viewport, and visual-option updates have no dedicated state/viewport/change event, and do not synthesize datachange or afterrender. Avoid synchronous recursion by unconditionally updating the same data inside afterupdateitem.

### Ordering and completion boundaries

- Successful explicit render with layout and nonempty nodes: beforelayout → layout:start → layout:end → afterlayout → beforerender → afterrender. Without layout, omit the four layout events.
- setData: optional four layout events → write-back and optional fit → request drawing → datachange. No beforerender/afterrender.
- layout: four layout events → write-back → request drawing, without datachange. Positions queried in completion callbacks can still be old; await layout before querying.
- Incremental after*item, datachange, and Combo events do not confirm the browser has drawn its next frame. Initial afterrender precedes the initialized flag and plugin mounting; await graph.render() before calling incremental mutation methods.

Cancelled or superseded work need not emit matching end events. Standalone runLayout emits no Graph events. See the [layout method reference](/en/docs/api/graph/layout) for cancellation and calculation semantics.
