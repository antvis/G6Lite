Use on to subscribe, off to unsubscribe, and once for a one-time listener. Start with [event basics](/en/docs/guides/events), or look up [element](/en/docs/api/graph/events/element), [selection](/en/docs/api/graph/events/selection), [drag](/en/docs/api/graph/events/drag), and [lifecycle/data](/en/docs/api/graph/events/lifecycle) events.

## on

Receive events until unsubscribed or the instance is destroyed.

```ts
import type { Graph } from '@antv/g6-lite';

declare const graph: Graph;
graph.on('node:click', ({ nodeId }) => {
  console.log('clicked', nodeId);
});
```

**Parameters**: event is the name; handler receives arguments inferred from that name. **Returns**: void.

Register before render to receive initial events. Duplicate registrations invoke the function multiple times. Adding after destruction does nothing.

## off

Unsubscribe using the original function. Also cancels a pending once listener.

```ts
import type { Graph, GraphEventMap } from '@antv/g6-lite';

declare const graph: Graph;
const onClick = ({ nodeId }: GraphEventMap['node:click'][0]) => console.log(nodeId);
graph.on('node:click', onClick);
graph.off('node:click', onClick);
```

**Parameters**: original event name and handler reference, both required. **Returns**: void.

All duplicate registrations of the function are removed. Missing listeners are a no-op. See [cleanup](/en/docs/guides/events#removing-listeners) for page integration.

## once

Receive only the next occurrence after registration, then automatically unsubscribe. Past events are not replayed.

```ts
import type { Graph } from '@antv/g6-lite';

declare const graph: Graph;
graph.once('afterrender', ({ nodeCount }) => console.log(nodeCount));
await graph.render();
```

**Parameters** are the same as on. **Returns**: void. Adding after destruction does nothing.

## Element event payloads

Element events describe what was hit. Common fields are nodeId / edgeId / comboId, business data, and client, canvas, and graph coordinates. Read the original mouse/wheel object from nativeEvent.

See [event parameters](/en/docs/api/graph/events/element#read-event-parameters) for field definitions and coordinate spaces.

## Selection events

Selection events describe selection results and require a corresponding Behavior. Their payloads differ from element clicks.

- [node:selectchange](/en/docs/api/graph/events/selection#nodeselectchange): the clicked node's selected state toggles.
- [selection:clear](/en/docs/api/graph/events/selection#selectionclear): an existing selection is cleared.
- [brush:end](/en/docs/api/graph/events/selection#brushend), [lasso:end](/en/docs/api/graph/events/selection#lassoend): region selection finishes.

Find all fields in the [selection reference](/en/docs/api/graph/events/selection) and integration in [selection and dragging](/en/docs/guides/events#selection-and-drag-events).

## Drag events

A drag follows start → drag → end. Persist positions from [node:dragend](/en/docs/api/graph/events/drag#nodedragend); read edge drop proposals from [edge:dragend](/en/docs/api/graph/events/drag#edgedragend).

The [drag reference](/en/docs/api/graph/events/drag) separates node, Combo, and edge-endpoint payloads and write-back responsibilities.

## Lifecycle and data events

- [afterrender](/en/docs/api/graph/events/lifecycle#afterrender): explicit render finishes synchronous drawing.
- [datachange](/en/docs/api/graph/events/lifecycle#datachange): setData completes replacement.
- [afterupdateitem](/en/docs/api/graph/events/lifecycle#afterupdateitem): incremental update results.
- [destroy](/en/docs/api/graph/events/lifecycle#destroy): first destruction, no arguments.

Find layout, resize, and Combo collapse events in the [full reference](/en/docs/api/graph/events/lifecycle). Explore timing with the [lifecycle guide](/en/docs/guides/events#lifecycle-and-data-events).

### Ordering and completion boundaries

Subscribe before render, await graph.render(), then mutate data or states. setData, layout, and partial updates do not repeat afterrender.

Layout completion events precede position write-back; await graph.layout() before reading final positions. See [ordering and completion](/en/docs/api/graph/events/lifecycle#ordering-and-completion).

## GraphEventMap

To type a reusable handler, extract the first argument of its public GraphEventMap entry:

```ts
import type { GraphEventMap } from '@antv/g6-lite';

type NodeClick = GraphEventMap['node:click'][0];
type DestroyArguments = GraphEventMap['destroy']; // []
```

<details>
<summary>Full subscription signatures and typing boundaries</summary>

on, off, and once share these public signatures:

```ts
import type { GraphEventMap, Handler } from '@antv/g6-lite';

declare function subscribe<K extends keyof GraphEventMap>(
  event: K, handler: Handler<GraphEventMap[K]>,
): void;
declare function subscribe<Args extends unknown[]>(
  event: string, handler: Handler<Args>,
): void;
```

Map entries are argument tuples: [] for destroy, one object argument otherwise. The unknown-string overload accepts application types and can also accept misspelled names. Graph has no public emit; custom typing does not create business events. Element parameter types are exported from the package root; see [element fields](/en/docs/api/graph/events/element#read-event-parameters).

</details>

<details>
<summary>Listener ordering and exceptions</summary>

Listeners run synchronously in registration order, with once removed before invocation. A Behavior handling an element event can synchronously emit a nested derived event. Do not assume application code always observes node:click before node:selectchange. Query state from the appropriate derived completion event when you need the final selection.

Exceptions from ordinary graph.on handlers propagate and may interrupt subsequent listeners or the operation. Handle errors in application callbacks and rejected asynchronous work yourself; dispatch does not await Promises. A * subscription receives payloads without an additional event-name argument, so it cannot provide a named universal event log.

</details>
