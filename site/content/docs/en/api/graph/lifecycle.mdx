Create, await render, update data / states / styles as needed, then destroy on exit. See [Graph lifecycle](/en/docs/concepts/graph-lifecycle) for the complete flow and [lifecycle events](/en/docs/api/graph/events/lifecycle) for payloads.

## new Graph

`new Graph(options: GraphOptions): Graph`

container and data are required; see [GraphOptions](/en/docs/api/options) for other fields and defaults. container accepts a CSS selector matching an HTMLElement or an HTMLElement instance. Invalid containers throw `Invalid container`. Use a dedicated mounted container with nonzero dimensions.

Construction stores configuration and prepares the canvas and WebGL renderer, without layout or element drawing. An existing first canvas is reused and later removed by destroy. Do not share the container between instances or borrow an application-owned canvas. See [browser and runtime requirements](/en/docs/compatibility/browser).

```ts
import { Graph, type GraphData } from '@antv/g6-lite';

export function createGraph(container: HTMLElement, data: GraphData) {
  return new Graph({ container, data });
}
```

## render

`graph.render(): Promise<void>`

Runs transforms and layout from saved data and options, builds the data model, interaction and label runtime, fits and draws synchronously, then finishes initialization and plugin mounting. On a valid completion path, await this method before data, state, or updateOptions calls. The first afterrender event is earlier than that boundary.

```ts
import { Graph, type GraphData } from '@antv/g6-lite';

export async function initialize(container: HTMLElement, data: GraphData) {
  const graph = new Graph({ container, data });
  try {
    await graph.render();
    if (graph.destroyed) return graph;
    graph.setItemState('A', 'selected', true); // A exists in data
    return graph;
  } catch (error) {
    graph.destroy();
    throw error;
  }
}
```

Repeated render reruns transforms, layout, runtime setup, and fitting. Input is the constructor data or the latest setData input. Incrementally added elements, runtime states, and the user's view are not guaranteed to survive. Do not render again for routine updates: use updateOptions for visual configuration and refresh for external style inputs.

<details>
<summary>Events, stale work, and failures</summary>

When layout is configured and data is nonempty, layout events come first, then beforerender → fitting and synchronous drawing → afterrender → initialization and plugin mounting. Synchronous drawing does not mean browser compositing has finished. render does not use datachange as its completion notification; updateOptions, refresh, setData, and layout do not emit afterrender.

New render, setData, layout, cancelLayout, or destroy calls can invalidate earlier layout work. An old Promise may still fulfill; cancellation need not emit ending events or finish initialization. Guard application side effects with your own generation. See [layout methods](/en/docs/api/graph/layout). render after destruction fulfills without work; fulfillment alone is not proof of a usable instance.

Layout loading / execution, drawing, or event callbacks can reject the Promise; some extension and layout errors have internal fallbacks. Catch errors and clean up instances you own. Callback errors propagate along the calling chain; handle them inside application callbacks to avoid interrupting initialization or cleanup.

</details>

## updateOptions

`graph.updateOptions(opts: Partial<Pick<GraphOptions, 'node' | 'edge' | 'label' | 'theme'>>): void`

Requires the first valid render to have completed; earlier calls throw, and calls after destruction do nothing. Merges configuration and synchronously performs full visual processing and drawing. It returns no drawing Promise and does not rerun layout, remount Behaviors / Plugins, move nodes, or refit the view.

| Input | Merge rule |
| --- | --- |
| node / edge | Shallow merge; omitted fields remain |
| node.style | Field merge for two objects; if either is a whole-object function, the supplied style replaces it |
| edge.style | Object fields merge |
| node.stateStyles / edge.stateStyles | Whole top-level field replacement; state names do not deep-merge |
| label | Shallow merge |
| theme | Whole option replacement, then preset resolution; no deep merge with the previous theme object |

Does not accept data, layout, behaviors, plugins, transforms, combo, container, or autoFit. Use [data methods](/en/docs/api/graph#setdata) for data and [layout methods](/en/docs/api/graph/layout) for layout. Other capabilities follow their initialization or extension contracts.

```ts
import type { Graph } from '@antv/g6-lite';
declare const graph: Graph; // Rendered
graph.updateOptions({
  node: { style: { fill: '#F59E0B' } },
  edge: { style: { lineWidth: 2 } },
  label: { hideOnCollision: false },
});
```

### Visual updates, refresh, and rebuilding

A starts selected. Update style turns nodes orange; External + refresh toggles input to the external size callback. Neither increases render events. Render again emits render events and rebuilds states, removing A's temporary selection. Select A selects it again. Destroy graph removes the canvas and reports destruction; Reset example creates a new instance.

## refresh

`graph.refresh(): void`

Forces synchronous full visual processing and drawing when a render runtime exists. Does nothing before a scheduler exists or after destruction. Does not rerun registered Transform beforeRender, layout, initialization, or fitting, and does not emit beforerender / afterrender.

Data, state, and camera methods already arrange updates. Use refresh for an external input read by a style callback; prefer tracked data or configuration changes when possible.

```ts
import type { Graph } from '@antv/g6-lite';
declare const graph: Graph; // Style callbacks read application-owned external input
graph.refresh();
```

## destroy

`graph.destroy(): void`

The first call sets destroyed to true, invalidates the layout generation, aborts pending layout, then emits destroy before runtime and canvas cleanup has finished. It then tears down interactions, plugins, labels, transforms, and renderer resources, removes the canvas, and clears Graph listeners. Repeated calls after normal cleanup have no additional effect. A destroyed instance cannot be rendered again for reuse; create a new one.

Application fetch requests, timers, DOM listeners, and subscriptions are not Graph resources; cancel or remove them yourself. Destroy immediately on unmount even if render is still pending, instead of waiting for asynchronous completion.

```ts
import type { Graph } from '@antv/g6-lite';

export function dispose(graph: Graph, controller: AbortController) {
  controller.abort(); // Application-owned request
  graph.destroy();
}
```

## destroyed

`graph.destroyed: boolean` (read-only)

false after construction, true from the start of destruction. It is not a readiness, successful-render, or task-generation flag. Check it after asynchronous work, alongside your own request generation when needed.

```ts
import type { Graph, GraphData } from '@antv/g6-lite';

export async function reload(graph: Graph, load: () => Promise<GraphData>) {
  const data = await load();
  if (graph.destroyed) return;
  await graph.setData(data, { fitView: false });
}
```

## isDestroyed

`graph.isDestroyed(): boolean` is deprecated and returns the same value as destroyed. New code should read the property.
