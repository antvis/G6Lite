Import application APIs from @antv/g6-lite. Use this overview to choose a reference; canonical pages own signatures, fields, and behavior. Follow [data workflows](/en/docs/guides/data) or [Extensions](/en/docs/guides/extensions) for implementation.

```ts
import { Graph, register, extensionFactory, runLayout, resolveTheme, EventEmitter } from '@antv/g6-lite';
import type { GraphOptions, GraphData, GraphEventMap } from '@antv/g6-lite';
```

## Entries you can call

| Entry | Purpose | Reference |
| --- | --- | --- |
| Graph | Operate one graph | [All public members by task](/en/docs/api/graph) |
| GraphOptions and topic option types | Declare constructor input | [Top-level fields and topics](/en/docs/api/options) |
| register / extensionFactory | Register extensions and create isolated instances | [Registration, factories, scope](/en/docs/api/extensions/registration) |
| runLayout | Calculate node positions independently | [Utilities](/en/docs/api/utilities#runlayout) |
| resolveTheme | Resolve presets and tokens | [Utilities](/en/docs/api/utilities#resolvetheme) |
| EventEmitter / Handler | Dispatch application-owned events | [Independent event utility](/en/docs/api/utilities#eventemitter) |

Use [Graph.on / off / once](/en/docs/api/graph/events) for graph subscriptions. Extension scope varies by category rather than exactly one factory call per Graph.

## Call order

Follow [Graph lifecycle](/en/docs/concepts/graph-lifecycle) for creation, subscriptions, valid rendering, and unmount cleanup. See [lifecycle methods](/en/docs/api/graph/lifecycle) for exact prerequisites. Environment, module format, and client requirements belong in [runtime environments](/en/docs/compatibility/browser) and [ESM / CommonJS boundaries](/en/docs/compatibility/api-stability#esm-and-commonjs).

## Query results are read-only

Models are live views with read-only types; getData returns a snapshot shallow-copied by layer. Write through data/state APIs. See [queries](/en/docs/api/graph/data) for copying rules and the [data guide](/en/docs/guides/data) for workflows.

## Engine-only members

Internal class members are outside application API. Avoid renderer, picking, and internal event transport. See [public and internal boundaries](/en/docs/compatibility/api-stability#public-and-internal-boundaries) for public alternatives.

## Compatibility entries

BaseNode, BreathingNode, registerNode, and deprecated methods support existing consumers. Canonical names and replacements are in [deprecated compatibility entries](/en/docs/compatibility/api-stability#deprecated-compatibility-entries), alongside upgrade and experimental-capability boundaries.
