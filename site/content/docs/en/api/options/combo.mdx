## ComboData

Declare groups with `GraphData.combos?: ComboData[]`; nodes join through `comboId`. Edge source and target still reference node IDs.

| Field | Type | Required | Default and rules |
| --- | --- | --- | --- |
| `id` | `string` | Yes | Unique identity; avoid collisions with node and edge IDs |
| `parentId` | `string` | No | No parent; references a parent in the same combos array |
| `collapsed` | `boolean` | No | `false`; see [Initial collapse](#initial-collapse) |
| `style` | `Partial<ComboStyleConfig>` | No | Overrides matching global style fields |
| `data` | `Record<string, unknown>` | No | Business data; not automatically used as labels or layout parameters |
| `states` | `ElementState[]` | No | Empty; read as a deduplicated Set |

### Membership and nesting

- Node `comboId` sets direct membership; Combo `parentId` sets hierarchy. The engine computes member sets.
- Parents may be declared later. References must be valid and hierarchy acyclic; currently invalid references are ignored, so validate them in your application.
- Bounds use member positions, sizes, child groups, and padding. x/y and width/height are not input fields. Empty groups draw no placeholder.

## Initial collapse

`collapsed: true` hides descendant nodes and their connected edges without creating virtual edges. `states: ['collapsed']` does not collapse a group. See [appearance fields](#collapsed-appearance) or [runtime methods](/en/docs/guides/combo).

<details>
<summary>Nested collapse and hidden states</summary>

Child Combo outlines are not automatically hidden by ancestor collapse. Expanding preserves existing business hidden states on nodes and edges. Multiple collapsed ancestors retain member hiding; expanding one may not reveal members.

</details>

## Initial states

`states` declares initial states; [state styles](#state-styles) define their appearance. `hidden` hides only the group itself. Built-in `click-select` handles nodes and edges only; use state APIs for Combo selection, as in the interactive example below.

## Read-only query model

After the first `await graph.render()`, `getComboData(id)` returns `ComboModel | undefined`. Results are read-only; use [Combo methods](/en/docs/api/graph#combo) or [state methods](/en/docs/api/graph#state-visibility-and-focus) for updates.

| Field | Type | Meaning |
| --- | --- | --- |
| `id` / `parentId` | `string` / `string \| undefined` | Identity and parent |
| `childNodeIds` | `ReadonlySet<string>` | Direct node members, excluding nodes inside child groups |
| `childComboIds` | `ReadonlySet<string>` | Direct child groups |
| `collapsed` | `boolean` | Current collapsed state |
| `x` / `y` | `number` | Bounds center in graph coordinates |
| `width` / `height` | `number` | Bounds dimensions, not collapsed display dimensions |
| `style` | `Readonly<Partial<ComboStyleConfig>> \| undefined` | Local input, not fully resolved styles |
| `data` | `Readonly<Record<string, unknown>> \| undefined` | Business data |
| `states` | `ReadonlySet<ElementState>` | Current states |

```ts
const group = graph.getComboData('client');
const directChildren = graph.getComboChildren('platform');
const membership = graph.getNodeCombo('web'); // 'client'
const selected = group?.states.has('selected');
```

<details>
<summary>Bounds updates and data export</summary>

Bounds are recalculated during rendering; membership queries do not guarantee synchronously updated geometry. `getData()` exports current membership, parentId, collapsed, and states, excluding hidden states derived from collapse. Style functions cannot be persisted directly as JSON.

</details>

## Basic appearance and local overrides

Set global values in `combo.style`, or override one group in `data.combos[].style`. Both accept these fields.

### Basic style fields

| Field | Type | Default | Rules |
| --- | --- | --- | --- |
| `fill` | `ComboStyleValue<string>` | `'rgba(100, 150, 255, 0.08)'` | Canvas color; `'transparent'` removes fill |
| `stroke` | `ComboStyleValue<string>` | `'rgba(100, 150, 255, 0.3)'` | Canvas outline color |
| `strokeWidth` | `ComboStyleValue<number>` | `1` | Screen pixels; does not thicken with zoom |
| `opacity` | `ComboStyleValue<number>` | `1` | 0–1; affects group fill, outline, and text only |
| `borderRadius` | `ComboStyleValue<number>` | `8` | Expanded corners in graph units; capped at half the box dimensions |
| `padding` | `number \| [number, number, number, number]` | `20` | Graph units; arrays use their maximum on all sides; no callback |
| `label` | `ComboStyleValue<string \| false>` | No expanded label | false/empty string hides text; no automatic id/data.name label |
| `labelFontSize` | `ComboStyleValue<number>` | `12` | Unscaled CSS-pixel font size |
| `labelColor` | `ComboStyleValue<string>` | `'rgba(0, 0, 0, 0.65)'` | Text color |
| `labelPlacement` | `'top' \| 'bottom' \| 'inside' \| 'center'` | `'top'` | Expanded text location; no callback |

<details>
<summary>Valid values, themes, and text scaling</summary>

Use valid Canvas colors, finite positive dimensions/widths/font sizes, and finite nonnegative padding/radii. There is no uniform invalid-value cleanup or theme-token injection.

Outlines account for DPR. Expanded font size is `labelFontSize * DPR * min(zoom, 1.5)`; text is skipped below 6 drawing pixels.

</details>

### Callbacks and precedence

`ComboStyleValue<T> = T | ((combo: ComboModel) => T)`. Callbacks receive one group model, including data, direct-member sets, and states. Keep them inexpensive and do not mutate the model.

Merge each field: **global base → local base → active state overrides → resolve surviving callbacks**. Local constants or callbacks replace the global field; undefined does not clear it. See [state ordering](#state-styles).

### Padding, bounds, and labels

- `[8, 40, 12, 24]` equals uniform `40`, rather than CSS directional padding. State styles cannot override padding.
- Bounds include node bodies and child groups, not labels. Parents add their padding outside child-group bounds.
- top/bottom sit outside and centered; inside is upper-left; center is box-centered. No wrapping, truncation, collision handling, or node/edge LabelOptions.

### Runtime updates

Replace a data snapshot to change local styles. `updateOptions()` currently does not accept combo.

```ts
const data = graph.getData();
const group = data.combos?.find((combo) => combo.id === 'local');
if (group) {
  group.style = { ...group.style, fill: 'rgba(22,160,133,0.12)' };
  await graph.setData(data, { fitView: false });
}
```

This replaces all data and reruns configured layout; `fitView: false` only preserves the view. Recreate the instance for global style changes. Use [state APIs](/en/docs/api/graph#state-visibility-and-focus) for temporary highlights.

## Collapsed appearance

These fields belong in `combo.style` or local `style`, and affect the collapsed shape only.

| Field | Type | Default | Rules |
| --- | --- | --- | --- |
| `collapsedType` | `'circle' \| 'rect'` | `'circle'` | Circle or rounded rectangle; no callback |
| `collapsedSize` | `ComboStyleValue<number \| [number, number]>` | `30` | Graph units; scalar for equal dimensions, tuple for width/height |
| `size` | `ComboStyleValue<number \| [number, number]>` | None | Fallback alias; collapsedSize wins when both are set |
| `count` | `boolean \| string \| ((combo: ComboModel) => boolean \| string)` | `true` | true counts descendant nodes recursively; false hides; string displays custom text |

**label takes priority over count.** Explicit `label: false` or an empty string also suppresses count. Text is always centered; labelPlacement does not apply.

<details>
<summary>Collapsed dimensions and text rendering</summary>

Shapes scale with zoom. Circles use the smaller dimension as diameter, not an ellipse. Rectangles have a maximum corner radius of 8 screen pixels, ignoring borderRadius. Position uses computed group centers; empty groups remain undrawn.

Text has no wrapping, truncation, or collision handling. It renders when the drawing radius exceeds 8 pixels, with font size `max(10 * DPR, min(labelFontSize * DPR, radius * 0.7))`. Automatic count includes nodes in child groups; `childNodeIds.size` counts direct members only.

</details>

## State styles

Entry: `combo.style.stateStyles` or `ComboData.style.stateStyles`. Type: `Partial<Record<ElementState, ComboStateStyleOverride>>`. Each state can override these **8 fields**; omitted fields retain their previous values.

| Field | Type | Overrides |
| --- | --- | --- |
| `fill` | `ComboStyleValue<string>` | Fill color |
| `stroke` | `ComboStyleValue<string>` | Outline color |
| `strokeWidth` | `ComboStyleValue<number>` | Outline width |
| `opacity` | `ComboStyleValue<number>` | Group alpha |
| `borderRadius` | `ComboStyleValue<number>` | Expanded corners |
| `label` | `ComboStyleValue<string \| false>` | Text, or hides text |
| `labelFontSize` | `ComboStyleValue<number>` | Font size |
| `labelColor` | `ComboStyleValue<string>` | Text color |

Order: **active → highlight → selected → disabled → inactive**. Each state merges global then local overrides; later matching fields win. Padding, collapsed dimensions, and labelPlacement cannot be state overrides.

The example explicitly handles `combo:click` to toggle selected. The last group keeps inactive to demonstrate combined states.

<details>
<summary>Fallback outlines and custom states</summary>

- Without configured styles, selected adds a blue 2-screen-pixel outline; active/highlight add a blue 1.5-pixel outline. The selected fallback wins.
- Explicit selected styles, including an empty object, suppress that fallback. Configuring either active or highlight suppresses the fallback outlines for both.
- disabled/inactive have no automatic dimming; configure them explicitly. Custom names are stored but do not enter built-in style merging; default is also excluded.
- hidden skips the group's own rendering and picking without hiding members; it is independent of collapsed.

</details>
