Complete collapsed-shape and state-style lists remain for later batches; see the [Combo guide](/en/docs/guides/combo) for existing usage. The global entry is `GraphOptions.combo: ComboConfig`, whose only top-level field is currently `style?: ComboStyleConfig`.

Nesting, collapse, and runtime grouping remain experimental and may change within `0.1.x`; see [API stability](/en/docs/compatibility/api-stability).

## ComboData

Declare groups with `GraphData.combos?: ComboData[]`; nodes join through their own `comboId`. A Combo is not a node: edge source and target still reference node IDs.

| Field | Type | Required | Default and rules |
| --- | --- | --- | --- |
| `id` | `string` | Yes | Unique Combo identity; also avoid node/edge ID collisions to prevent ambiguity in unified queries and state operations |
| `parentId` | `string` | No | No parent; references a parent Combo in the same combos array |
| `collapsed` | `boolean` | No | `false`; whether the first render starts collapsed, see [Initial collapse](#initial-collapse) |
| `style` | `Partial<ComboStyleConfig>` | No | No local overrides; overrides corresponding base fields in global combo.style. See [precedence](#callbacks-and-precedence) |
| `data` | `Record<string, unknown>` | No | No business data; fields do not automatically become labels or layout parameters |
| `states` | `ElementState[]` | No | Empty state set; normalized to a Set, removing duplicates. See [Initial states](#initial-states) |

### Membership and nesting

- A node's `comboId?: string` names one direct group. Omission means ungrouped; nodes in child groups do not also need membership in the parent.
- A Combo's `parentId` declares hierarchy. Direct members come from node comboId; do not write childNodeIds or childComboIds into ComboData.
- Groups are all declared before relationships are linked, so a parent may appear after its children. Parent IDs must exist and hierarchy must be acyclic; cycle guards do not make circular nesting valid.
- Unknown comboId references are currently ignored: the node remains in the graph without valid membership. Unknown parentId references do not establish a real parent. Validate references in your application.
- Bounds come from member positions, node dimensions, child-group bounds, and padding. x/y and width/height are not ComboData fields. Empty groups have no content bounds and currently do not draw placeholder containers.

## Initial collapse

`collapsed: true` applies during initial data loading, hiding all descendant nodes and edges connected to them. Cross-group edges are not reconnected as virtual edges to a collapsed group. Child Combo outlines are not automatically suppressed solely because an ancestor is collapsed; validate the actual nested presentation.

Expanding should preserve preexisting business hidden states on nodes and edges. Multiple collapsed ancestors jointly retain member hiding; expanding one does not necessarily reveal everything. See the [existing guide](/en/docs/guides/combo) for runtime collapse methods; this example verifies initial declarations.

`collapsed` and `states` are independent: `states: ['collapsed']` stores a custom state name and does not collapse the group.

## Initial states

`states` accepts built-in names and custom strings. Current built-in Combo style processing follows active → highlight → selected → disabled → inactive. Hidden skips the group's own drawing and picking. Custom names are retained but do not automatically receive built-in effects. Full style fields and precedence will be documented in the appearance batch.

Combo state styles belong in `combo.style.stateStyles` or local `ComboData.style.stateStyles`, not `combo.stateStyles`. The preview explicitly defines a purple selected outline. Initial states need no behavior. Built-in `click-select` currently handles nodes and edges only. Update subsequent Combo selection with `setItemState()`, or handle `combo:click` and call state APIs; installing that behavior alone does not toggle Combo states.

`states: ['hidden']` hides only the group itself, unlike collapsed. It does not automatically hide member nodes, connected edges, or child Combos, and cannot declare a whole invisible subtree.

## Read-only query model

After the first `await graph.render()`, `graph.getComboData(id)` returns `ComboModel | undefined`. It is a read-only Graph-managed view; mutating returned objects or collections is not an update API.

| Field | Type | Meaning |
| --- | --- | --- |
| `id` / `parentId` | `string` / `string \| undefined` | Group identity and declared parent |
| `childNodeIds` | `ReadonlySet<string>` | Direct node members, excluding nodes inside child groups |
| `childComboIds` | `ReadonlySet<string>` | Direct child Combo IDs |
| `collapsed` | `boolean` | Current collapsed state |
| `x` / `y` | `number` | Computed graph-coordinate bounds center |
| `width` / `height` | `number` | Computed bounds in graph units, not the collapsed shape's display size |
| `style` | `Readonly<Partial<ComboStyleConfig>> \| undefined` | Local input, not fully resolved defaults plus state styles |
| `data` | `Readonly<Record<string, unknown>> \| undefined` | Business data |
| `states` | `ReadonlySet<ElementState>` | Current state set |

Bounds are recomputed during rendering. After membership changes, do not treat queries as synchronous geometry calculation. Query direct children with `getComboChildren()` and node membership with `getNodeCombo()`:

```ts
const group = graph.getComboData('client');
const directChildren = graph.getComboChildren('platform');
// directChildren.combos includes client; nodes excludes web/mobile inside client
const membership = graph.getNodeCombo('web'); // 'client'
const selected = group?.states.has('selected');
```

Use [public Combo methods](/en/docs/api/graph#combo) and [state methods](/en/docs/api/graph#state-visibility-and-focus) for changes. `graph.getData()` returns current GraphData snapshots, including membership, parentId, collapsed, and states. Member hidden states derived from collapse are not exported as business hidden. Functions in style are unsuitable for direct JSON persistence.

## Basic appearance and local overrides

This section covers expanded appearance and labels. Set global values in `combo.style` and override one group in `data.combos[].style`; both use `ComboStyleConfig`. Collapsed-shape fields collapsedType, collapsedSize, size, count, and the complete state-style list remain for later batches. Existing operations are in the [Combo guide](/en/docs/guides/combo).

### Basic style fields

| Field | Type | Default | Units and behavior |
| --- | --- | --- | --- |
| `fill` | `ComboStyleValue<string>` | `'rgba(100, 150, 255, 0.08)'` | Canvas fill color; use `'transparent'` for no fill |
| `stroke` | `ComboStyleValue<string>` | `'rgba(100, 150, 255, 0.3)'` | Canvas outline color, independent of fill |
| `strokeWidth` | `ComboStyleValue<number>` | `1` | Screen pixels; DPR-adjusted but not thickened by camera zoom. Use a finite positive value |
| `opacity` | `ComboStyleValue<number>` | `1` | Shared alpha for group fill, outline, and label; use 0–1. Does not change member-node or edge opacity |
| `borderRadius` | `ComboStyleValue<number>` | `8` | Expanded corner radius in graph units; use a finite nonnegative value, limited to half of displayed width/height |
| `padding` | `number \| [number, number, number, number]` | `20` | Graph units used for bounds; a constant without callbacks. Arrays currently use their maximum as uniform padding |
| `label` | `ComboStyleValue<string \| false>` | No expanded label | Nonempty text renders; `false` or an empty string hides it. IDs/data.name are not read automatically |
| `labelFontSize` | `ComboStyleValue<number>` | `12` | Unscaled CSS-pixel size; use a finite positive value. Expanded Canvas font size is `labelFontSize * DPR * min(zoom, 1.5)` and is skipped below 6 drawing pixels |
| `labelColor` | `ComboStyleValue<string>` | `'rgba(0, 0, 0, 0.65)'` | Group-label color |
| `labelPlacement` | `'top' \| 'bottom' \| 'inside' \| 'center'` | `'top'` | Expanded-label location; a constant without per-group callbacks |

Groups render with Canvas 2D and accept Canvas color strings. Values do not pass through uniform numeric validation; supply valid ranges instead of relying on invalid colors, negative widths, or non-finite values to restore defaults. Combo base styles do not receive theme tokens; defaults come from the group renderer.

### Callbacks and precedence

`ComboStyleValue<T> = T | ((combo: ComboModel) => T)`. Callback fields receive one group model, including identity, business data, direct-member sets, and current states. This is not the node/edge signature and has no index argument. Direct-member counts exclude nodes inside child groups. Keep callbacks inexpensive and do not mutate the model or trigger updates.

Base fields merge from global combo.style to local ComboData.style, then surviving callbacks resolve. Missing local fields retain global values; fields omitted from both use built-in fallbacks. Local constants and functions both replace their global counterpart. Callback results are values, not another configuration merge. Explicit false disables label; undefined does not clear a defined global field.

State layers apply after base merging, in active → highlight → selected → disabled → inactive order. Each active state merges its global override, then its local override, before surviving callbacks run. Consequently a global selected stroke can override a local base stroke, while that state's local stroke wins over its global stroke. The full state list and fallback outlines will be covered in the next batch.

### Padding, bounds, and labels

Padding chooses the local value, then global, then 20. Currently `[8, 40, 12, 24]` and `40` produce identical uniform padding, not separate CSS-like top/right/bottom/left insets. Use finite nonnegative values and exactly four tuple entries. States and field callbacks do not control padding.

Bounds wrap node bodies and child-group bounds, then add padding on every side. Member and group labels are not measured to expand the box. A parent adds its own padding around child-group bounds. Padding does not create a placeholder box for an empty group.

Expanded top/bottom labels sit outside the outline and are horizontally centered; center uses the box center, and inside uses the upper-left interior. There are no automatic wrapping, truncation, collision hiding, or group-label offset fields. Combo labels do not use node/edge LabelOptions; label.hideOnCollision and scaleWithZoom do not change them. Shorten long titles or provide space; increasing padding does not enable wrapping.

### Runtime updates

`graph.updateOptions()` currently accepts node, edge, label, and theme only. It does not accept combo. Do not use `updateOptions({ combo: ... })` or mutate getComboData() results to update appearance.

For local appearance, get a current GraphData snapshot after the first render, modify the appropriate ComboData.style, and replace data. This code belongs in an application's async function, not a control for this page:

```ts
const data = graph.getData();
const group = data.combos?.find((combo) => combo.id === 'local');
if (group) {
  group.style = { ...group.style, fill: 'rgba(22,160,133,0.12)' };
  await graph.setData(data, { fitView: false });
}
```

This replaces all data and reruns any configured layout. fitView: false preserves the view; it does not skip layout. Recreate with new options to replace global combo.style. Prefer state APIs for temporary selection or highlights. See [Graph data and configuration updates](/en/docs/api/graph#replacing-data-and-styles).
