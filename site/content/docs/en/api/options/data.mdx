Pass input to new Graph or setData. Query models are distinct from input objects; see [query models](/en/docs/api/graph/data#model-fields). Follow the [data guide](/en/docs/guides/data).

## GraphData

| Field | Type | Rules |
| --- | --- | --- |
| nodes | GraphNode[] | Required; [] for an empty graph |
| edges | GraphEdge[] | Required; [] for no edges |
| combos | ComboData[] | Optional; omission creates no groups |

```ts
import type { GraphData } from '@antv/g6-lite';
const data: GraphData = {
  nodes: [
    { id: 'A', x: 0, y: 0, data: { score: 1 }, states: ['selected'] },
    { id: 'B', x: 200, y: 0, comboId: 'team' },
  ],
  edges: [{ id: 'A-B', source: 'A', target: 'B', data: { weight: 2 } }],
  combos: [{ id: 'team', data: { name: 'Team' } }],
};
console.log(data);
```

Use distinct stable string IDs, also across element types. Validate uniqueness, endpoints, finite coordinates, and acyclic Combo hierarchies. Input paths do not all provide identical validation or rollback.

## GraphNode

| Field | Type | Required / defaults and meaning |
| --- | --- | --- |
| id | string | Required identity; avoid array indices for persistent IDs |
| name | string | Optional name; use label configuration to choose presentation |
| data | NodeData | Optional business record, with cluster?: string and other unknown fields |
| x / y | number | Optional graph coordinates; absent axes default to 0 without layout; layout can replace them |
| fx / fy | number | Optional fixed axes, applied after layout computation before write-back |
| states | ElementState[] | Optional initial flags, empty by default; runtime storage is a set |
| comboId | string | Optional direct membership in a declared Combo |

Without layout, position with x/y rather than fx/fy. Current models and post-render getData omit fx/fy, and layout() computes from that snapshot. Retain fixed-axis constraints in application input and include them in setData when needed; a one-time input is not a permanent node lock.

Runtime can retain input data references, and direct external edits do not schedule updates. Use updateNodeData and manage nested-object ownership in the application. Color, size, and labels belong to node configuration rather than GraphNode top-level fields.

## GraphEdge

| Field | Type | Required / defaults and meaning |
| --- | --- | --- |
| id | string | Optional; generated e0, e1, etc. restart on replacement. Supply explicit IDs for persistent business edges |
| source | string | Required source node ID, not a Combo ID |
| target | string | Required target node ID |
| data | Record&lt;string, unknown&gt; | Optional business record |
| states | ElementState[] | Optional initial flags, empty by default |

Equal source and target creates a loop. Multiple distinct edge IDs can share endpoints; see [parallel edges and loops](/en/docs/api/options/edge#parallel-edges-and-self-loops).

## ComboData

Declare groups in combos, join nodes through comboId, and nest groups through parentId. The six fields, initial folding, and states are defined in [ComboData](/en/docs/api/options/combo#combodata). See the [Combo guide](/en/docs/guides/combo).

## Initial states and export

Input states are name arrays; model states are ReadonlySet views. selected is not a registered click behavior, and disabled does not automatically block interaction. setData does not copy old states into new elements; explicitly carry required business states. See [using states](/en/docs/guides/states).

getData exports current positions, IDs, and business states rather than all original configuration. Collapse-derived hidden is excluded. Copying is shallow by layer; see [getData](/en/docs/api/graph/data#getdata).
