`GraphOptions.node` has type `NodeConfig`. This page details top-level options, body appearance, labels, icons, and states; existing decoration documentation is linked below. See the [node guide](/en/docs/guides/node) for configuration steps and effects.

```ts
import type { NodeConfig } from '@antv/g6-lite';

const node: NodeConfig = {
  type: 'rect',
  style: {
    size: 32,
    width: 96,
    height: 40,
    borderRadius: 8,
    fill: (item) => item.data?.risk === 'high' ? '#ff4d4f' : '#1783FF',
    stroke: '#fff',
    strokeWidth: 1,
  },
  stateStyles: {
    selected: { stroke: '#163B65', strokeWidth: 2 },
  },
};
```

Pass this object as `node` in `new Graph({ container, data, node })`.

## NodeConfig

All top-level fields are optional.

| Field | Type | Default behavior and constraints |
| --- | --- | --- |
| `type` | `'circle' \| 'rect' \| string` | Defaults to `'circle'`; register custom names with `register('node', ...)`, with the extension's `base` choosing the primitive |
| `style` | `NodeStyleConfig \| ((node: GraphNode) => Partial<NodeStyleConfig>)` | Theme and field fallbacks when omitted; whole-object functions differ as described below |
| `stateStyles` | `Partial<Record<ElementState, NodeStateStyleOverride>>` | Override body appearance per state; undefined states use extension or theme definitions |
| `labelRenderer` | `string` | Built-in label renderer by default; a named label renderer must be registered and `style.label` must supply nonempty text |
| `decorations` | `NodeDecorationConfig[]` | No decorations by default; use built-in `builtin-badge` or a registered decoration renderer |
| `autoExternalLabelPlacement` | `boolean` | Type declaration only, not read by the current runtime; neither `true` nor `false` changes placement. Set `style.labelPlacement` explicitly |

Unknown node names currently fall back to a circle primitive; do not use that fallback instead of registration.

## NodeStyleConfig

Defaults below apply to built-in nodes with a **style object**, including per-field callbacks. With no `theme`, the light preset applies; custom themes and node extensions can change fallbacks.

| Field | Type | Default or fallback | Meaning |
| --- | --- | --- | --- |
| `fill` | `NodeStyleValue<string>` | `theme.nodeFill`, preset `'#1783FF'` | Fill color |
| `size` | `NodeStyleValue<number>` | `theme.nodeSize`, preset `24` | Circle diameter; rectangle fallback when dimensions are omitted |
| `width` | `NodeStyleValue<number>` | Resolved `size` | Rectangle width; does not change a built-in circle's diameter |
| `height` | `NodeStyleValue<number>` | Resolved `size` | Rectangle height; does not change a built-in circle's diameter |
| `stroke` | `NodeStyleValue<string>` | `theme.nodeStroke`; light `'#fff'`, dark `'#333'` | Stroke color |
| `strokeWidth` | `NodeStyleValue<number>` | `theme.nodeStrokeWidth`, preset `0` | Stroke width; `0` draws no stroke |
| `opacity` | `NodeStyleValue<number>` | `1` | Opacity; use values from `0` to `1` |
| `borderRadius` | `NodeStyleValue<number>` | `0` | Rectangle corner radius, limited when drawing to half the smaller dimension |

`size`, `width`, `height`, `strokeWidth`, and `borderRadius` are graph-space lengths that follow camera zoom, rather than fixed CSS pixels. Do not multiply them by DPR. Setting `opacity: 0` does not replace the visibility APIs; see [Graph state methods](/en/docs/api/graph#state-visibility-and-focus).

### Style callbacks

`NodeStyleValue<T>` is `T | ((node: GraphNode) => T)`. A callback receives only the current node; read business fields from `node.data`. It receives no camera or zoom argument. Supply explicit fallbacks for missing data rather than returning `undefined` or invalid numbers.

```ts
import type { NodeConfig } from '@antv/g6-lite';

const node: NodeConfig = {
  style: {
    size: (item) => Number(item.data?.size ?? 24),
    fill: (item) => item.data?.group === 'core' ? '#1783FF' : '#61DDAA',
  },
};
```

Per-field body-style precedence is: node `style` object → extension `getStyle()` result → extension default `style` → theme or built-in fallback. Keep callbacks inexpensive and free of side effects; do not depend on how often they run per frame.

Whole-object functions, `style: (node) => ({ ... })`, currently use a different body-style resolution branch. Missing `size`, `width`, and `height` fall back to `40`, `100`, and `40`, and that branch does not apply `stateStyles`. Prefer per-field callbacks when relying on theme dimensions or state appearance. This is a current implementation limitation; the two forms are not fully equivalent.

## Labels

These fields belong in `node.style`. Each accepts a constant or `NodeStyleValue<T>` callback.

| Field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `label` | `NodeStyleValue<string \| false>` | Not drawn | Text; `false`, an empty string, or omission draws no label |
| `labelFontSize` | `NodeStyleValue<number>` | `12` | Base CSS-pixel font size, converted for DPR and label zoom |
| `labelFontFamily` | `NodeStyleValue<string>` | System sans-serif stack | Canvas font family |
| `labelFontWeight` | `NodeStyleValue<string>` | `'normal'` | Canvas font weight, such as `'600'` |
| `labelColor` | `NodeStyleValue<string>` | `'#333'` | Text color; does not automatically become white for the dark theme |
| `labelPlacement` | `NodeStyleValue<LabelPlacement>` | `'bottom'` | `'center'`, `'top'`, `'bottom'`, `'left'`, or `'right'` |
| `labelOffsetX` | `NodeStyleValue<number>` | `0` | Base CSS-pixel horizontal offset; positive moves right |
| `labelOffsetY` | `NodeStyleValue<number>` | `0` | Base CSS-pixel vertical offset; positive moves down |
| `labelBackground` | `NodeStyleValue<string \| false>` | `false` | Background color; `false` disables it |
| `labelBackgroundPadding` | `NodeStyleValue<number>` | `2` | Base CSS-pixel padding on each side of the background |
| `labelMaxWidth` | `NodeStyleValue<number>` | `0` | Default renderer's text width limit; positive values truncate with `...`, nonpositive values leave width unlimited |

The default font stack is `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif`. Camera zoom affects default font size, offsets, and background dimensions, but label zoom is clamped rather than growing indefinitely with node geometry. Use top-level `label.scaleWithZoom: false` for fixed screen font size and offsets. Do not multiply values by DPR.

Default label placement references `size`. For precise outline-relative placement on nonsquare rectangles, a custom Label Renderer uses the rendered width and height for its anchor. `autoExternalLabelPlacement` currently neither avoids decorations nor moves the label.

Top-level `label` policies also apply: `hideOnLowZoom` defaults to `true`, with `nodeMinZoom: 0.3`; `hideOnCollision` defaults to `true` and hides text overlapping an earlier label's measured text box. Background padding does not expand the default text collision box. Disabling these policies does not reveal nodes with `label: false`.

### labelRenderer

Register with `register('label', name, renderer)` before setting `node.labelRenderer: name`. A custom renderer still needs nonempty `style.label` and follows node-label zoom and collision policies. `measure()` must return finite, positive width and height. Missing registration, invalid measurements, or measure/draw errors produce a warning and fall back to the default label.

The supplied `style` is already converted to Canvas pixels, and `ctx` is translated to the label anchor. Do not apply DPR or node coordinates again. Custom renderers consume appearance fields such as `labelMaxWidth` themselves; the engine does not truncate their text. See [Custom Label Renderer](/en/docs/guides/custom-label-renderer) for full signatures.

## Icons

Icon fields also belong in `node.style` and accept constants or per-field callbacks.

| Field | Type | Default | Applicability and units |
| --- | --- | --- | --- |
| `icon` | `NodeStyleValue<string \| false>` | Not drawn | Image URL or text according to `iconType`; empty strings and `false` draw nothing |
| `iconType` | `NodeStyleValue<'image' \| 'text'>` | `'image'` | Image or text icon |
| `iconWidth` | `NodeStyleValue<number>` | Resolved `size` × `0.6` | Image icons only; graph-space width |
| `iconHeight` | `NodeStyleValue<number>` | Resolved `size` × `0.6` | Image icons only; graph-space height |
| `iconFontFamily` | `NodeStyleValue<string>` | System sans-serif stack | Text icons only; load the font in the application |
| `iconFontSize` | `NodeStyleValue<number>` | Resolved `size` × `0.6` | Text icons only; graph-space font size, skipped below 4 rendered Canvas pixels |
| `iconColor` | `NodeStyleValue<string>` | `'#fff'` | Text icons only |
| `iconOffsetX` | `NodeStyleValue<number>` | `0` | Graph-space offset; positive moves right |
| `iconOffsetY` | `NodeStyleValue<number>` | `0` | Graph-space offset; positive moves down |

Icon sizes and offsets follow camera zoom rather than the `label.scaleWithZoom` text policy. Icons do not participate in label collision hiding or `nodeMinZoom`; hidden nodes still skip drawing. Images load asynchronously and trigger a redraw when ready. Cross-origin images must permit anonymous CORS; failed URLs are not automatically retried by the instance.

```ts
import type { NodeConfig } from '@antv/g6-lite';

const node: NodeConfig = {
  style: {
    size: 40,
    label: (item) => String(item.data?.name ?? item.id),
    labelPlacement: 'bottom',
    labelMaxWidth: 120,
    labelBackground: '#fff',
    labelFontWeight: '600',
    icon: 'G',
    iconType: 'text',
    iconFontSize: 20,
    iconColor: '#fff',
  },
};
```

See the [label and icon guide](/en/docs/guides/label) and [label and icon example](/en/docs/examples/labels) for usage and effects.

## State styles

`NodeStateStyleOverride` accepts these constants, not per-field callbacks:

| Field | Type | Effect |
| --- | --- | --- |
| `fill` | `string` | Override fill color |
| `stroke` | `string` | Override stroke color |
| `strokeWidth` | `number` | Override stroke width in graph units |
| `opacity` | `number` | Override opacity |
| `haloWidth` | `number` | Outside halo width in graph units |

For each active state, the engine selects `node.stateStyles[state]`, otherwise the extension or theme definition for that state. Selection uses the entire state object; missing fields are not filled from the theme's same-name state. Include all effects you want to retain. Multiple states apply in their current collection iteration order; later fields win. The `default` state is skipped.

`hidden` makes body appearance transparent and skips other state appearance calculations. Built-in states also impose halo effects: `active` supplies `8` when the halo is `0`, and `selected` supplies at least `12`. Setting `haloWidth: 0` on the selected style therefore does not remove its halo.

## Runtime updates

After the first `await graph.render()`, update with `graph.updateOptions({ node: ... })`. Top-level fields merge shallowly. Two style objects merge by field; when a style function is involved, the supplied function or object replaces the previous style. `stateStyles` and `decorations` are top-level fields, so updates replace the entire state map or decoration array rather than individual states or items.

Updates do not rerun layout. See [`updateOptions()`](/en/docs/api/graph#updateoptions).
