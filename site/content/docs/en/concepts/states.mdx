States record whether an element is selected, highlighted, or marked by your application. One element can have several states, such as selected and awaiting review.

## States, Behaviors, and styles

- A **state** records a current flag, such as selected.
- A **Behavior** decides when to change it, such as click-select responding to clicks.
- A **state style** decides its appearance, such as a purple selected outline.

Listening to node:click does not select nodes; defining stateStyles does not create an interaction. Behaviors and application code can both change states.

## Add, replace, and clear

setItemState(id, name, true) adds one state; false removes only that state, preserving others. Toggle selected / Toggle review use this approach.

setElementStates(id, names) replaces the entire collection. Replace with highlight sets A to ['highlight'], removing selected and review.

clearItemStates(id) clears the collection, restoring base appearance; setElementStates(id, []) also clears it. Await graph.render() before the first mutation.

## Where state styles belong

Configure node.stateStyles / edge.stateStyles for nodes and edges, and combo.style.stateStyles for Combos. Each state overrides only the appearance fields it defines; remaining fields retain their base or other active-state values.

Built-in themes provide selected, active, highlight, disabled, and inactive presets. The example's review name is custom, with orange explicitly configured. Use fields supported by the corresponding element.

## Names and data

selected commonly represents application selection; active / highlight emphasize elements, and inactive dims them. disabled is a visual state and does not automatically block clicks or dragging; enforce business restrictions in application logic.

hidden controls visibility. default represents base appearance; you do not need to add a default state to restore it. Expand a collapsed Combo to restore elements hidden by that structure.

States are maintained separately from business data. Declare initial states in the data's states array. When replacing data through setData, carry states you want to preserve in the new data; old temporary selection is not automatically retained.

## Common questions

### Why did adding a state not change appearance?

Check that supported style fields are configured. The node whole-object style function currently skips stateStyles; use per-field configuration for state appearance. See [style callbacks](/en/docs/api/options/node#style-callbacks).

### Why did setting selected emit no selection event?

Programmatic state changes do not synthesize node:selectchange; click-select emits it. Synchronize business UI explicitly after programmatic writes. See [selection synchronization](/en/docs/guides/events/selection-drag#synchronize-selection).

### Why is an element still hidden after clearing states?

Check whether it belongs to a collapsed Combo. Expand that structure, then check the business hidden flag.
