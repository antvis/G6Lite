When built-ins cannot express a business rule, consume public Graph events through a Behavior and update data or state through ExtensionContext. Here, clicking a node makes it uniquely active. Canvas clicks clear only active, preserving A's initial selected state.

## Public type pattern

Give the name a literal type and business options their own type, then use satisfies at activation. Full generics, event mappings, and lifecycle signatures are in the [Behavior contract](/en/docs/api/options/behaviors#custom-behavior-contract).

## Recommended exports

Export a stable name, options type, and explicit registration function. Register before creating Graph, and use a business or package prefix to avoid global registry collisions. Do not rely on import side effects for registration order.

## Register and activate

The example calls registerBusinessSelect before constructing Graph and checks the configuration with satisfies BusinessSelectOptions. String names also activate the Behavior; normalized init options include type, and missing state defaults to active.

Multiple Graphs can reuse the registered factory; each mounted Behavior owns its context and state. Re-registering a name does not replace mounted instances. See [mounting and updates](/en/docs/api/options/behaviors#mounting-and-updates).

## Event typing

getEvents infers argument tuples from GraphEventMap. node:click has typed nodeId and nativeEvent; destroy has no arguments. Extend consumer event types by intersection:

```ts
import type { BehaviorExtension, BehaviorOptions, GraphEventMap } from '@antv/g6-lite';

interface BusinessEventMap {
  'business:reset': [payload: { source: 'toolbar' | 'shortcut' }];
}
type BusinessBehavior = BehaviorExtension<
  BehaviorOptions<'business-select'>,
  GraphEventMap & BusinessEventMap
>;
```

This adds handler types, not a public emit method. Prefer [existing events](/en/docs/guides/events) for integration rather than internal eventEmitter.

## Lifecycle and cleanup

The engine runs create → init → getEvents, then unbinds handlers and calls destroy on teardown. No update hook is promised; remounting destroys and recreates the instance. Readonly options are a type constraint, not guaranteed runtime freezing. Do not mutate the input.

The engine cleans up getEvents bindings. Clean up your own window listeners, timers, observers, DOM, and asynchronous work in destroy. Check context.isDestroyed before asynchronous completion and handle Promise rejections yourself.

## Boundaries and replacement

- Import public package-root APIs and use context.data/state/viewport, requestRender, and isDestroyed.
- Read snapshots; write payloads with data.updateNode/updateEdge and replace states with state.set/setAll.
- Independent DOM, keyboard controllers, or observers generally belong in Plugins; preprocessing belongs in Transforms.
- Registered names override built-ins without fallback on failure. Avoid overriding built-in names for temporary experiments.

<details>
<summary>Verify a reusable Behavior</summary>

Check left-button filtering, canvas clearing, and preservation of other states. Mount two Graphs and verify independence; destroy one while the other remains usable. Remounting must not duplicate handler calls.

The public context does not expose low-level gesture sessions, camera writes, or node-position writes. Extend the public contract when needed instead of casting to internal renderer or deprecated context.graph.
