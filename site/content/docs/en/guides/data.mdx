## Map application data

Map entities to nodes and relationships to edges. Put business fields in data for styles, tooltips, and panels. Give persistent relationships stable edge IDs too.

```ts
import type { GraphData } from '@antv/g6-lite';

const users = [
  { id: 'alice', name: 'Alice', team: 'design' },
  { id: 'bob', name: 'Bob', team: 'engineering' },
];

const data: GraphData = {
  nodes: users.map((user) => ({
    id: user.id,
    data: { name: user.name, team: user.team },
  })),
  edges: [{ source: 'alice', target: 'bob' }],
};
```

This converts data only. Display also needs a container and render. Configure layout when positions are absent; see [quick start](/en/docs/getting-started/quick-start)。

## Validate data

- Use stable string IDs and avoid collisions across element types.
- Edge endpoints must exist; Combo memberships and parent links must be valid and acyclic.
- Provide finite x/y without layout; retain fixed-axis constraints in application input.
- Validate before writing. Batches have no rollback guarantee; do not mutate models.

## Choose an update path

| Change | Method | What changes |
| --- | --- | --- |
| Dataset switch / full response | setData | Replaces data, runs configured layout, fits by default |
| Small business-field changes | updateNodeData / updateEdgeData | Shallow-merges data without layout |
| Add/remove elements | addNode(s) / addEdge(s) / remove… | Supply new positions; node removal removes adjacent edges |
| Position changes | updateNodePosition(s) | Graph position changes; identity remains |
| Selection, visibility, membership | State / Combo methods | Use the relevant APIs without full replacement |

## Replace all data

Call setData after a valid initial render. It runs configured layout and defaults to fitView(0.9). fitView: false retains the camera. Zoom below, then compare reloads as B alternates between x=240 and 800.

## Incremental updates

Update A increments score and changes size. Add D creates the node and C-D; Remove D removes the adjacent edge too. Edit snapshot edits only an export, without writing back.

Incremental methods do not layout or fit; routine updates need no render. Prefer batch methods for multiple elements. Nested data updates are shallow rather than recursive.

<details>
<summary>Async requests: cancel previous loads and clean up</summary>

The helper below owns cleanup of this page’s Graph. load accepts an AbortSignal. Handle refresh failures in the caller, and call dispose on exit.

```ts
import type { Graph, GraphData } from '@antv/g6-lite';
export function createLoader(graph: Graph, load: (signal: AbortSignal) => Promise<GraphData>) {
  let version = 0;
  let disposed = false;
  let controller: AbortController | undefined;
  return {
    async refresh() {
      const request = ++version;
      controller?.abort();
      const current = new AbortController();
      controller = current;
      try {
        const next = await load(current.signal);
        if (disposed || graph.destroyed || request !== version) return;
        await graph.setData(next, { fitView: false });
      } catch (error) {
        if (!current.signal.aborted && !disposed) throw error;
      }
    },
    dispose() {
      disposed = true;
      version++;
      controller?.abort();
      graph.destroy();
    },
  };
}
```

## Common questions

### Why did labels or colors not change?

Check that fields are inside data and read by the style callback. Editing exports or directly mutating models does not follow the public update flow.

### Why did refreshing lose the view or selection?

setData fits by default and builds states from new input. fitView: false keeps the camera; preserve selection explicitly by stable IDs.
