## Element events

Listening does not require click-select. Clicks below update only the readout. Listening toggles persistent subscriptions; Arm once waits for the next node click. Turning off persistent listeners leaves the independent once subscription active.

Clicking a node inside a Combo emits node:click without also emitting combo:click. See [element payloads](/en/docs/api/graph/events#element-event-payloads) for fields and picking rules.

## Selection and drag events

Enable click-select, brush-select / lasso-select, or drag-node in Graph behaviors first; see [interaction combinations](/en/docs/guides/interactions). To synchronize business selection, query the final set from the completion events of each source:

```ts
import type { Graph } from '@antv/g6-lite';

export function observeSelection(
  graph: Graph,
  onChange: (nodes: string[], edges: string[]) => void,
) {
  const sync = () => onChange(
    graph.findNodesByState('selected'), graph.findEdgesByState('selected'),
  );
  const events = ['node:selectchange', 'edge:selectchange', 'selection:clear', 'brush:end', 'lasso:end'] as const;
  for (const event of events) graph.on(event, sync);
  sync();
  return () => { for (const event of events) graph.off(event, sync); };
}
```

One action can invoke the callback more than once, such as clearing before selecting. Coalesce expensive UI updates in the application. Synchronize UI explicitly after programmatic state changes too; brushing does not emit node:selectchange per node.

Persist drag results at dragend, reading positions for every nodeIds entry. Move-stage dx/dy is cumulative graph-coordinate displacement from gesture start. This helper returns cleanup; implement network calls and error handling in the application save function:

```ts
import type { Graph, GraphEventMap } from '@antv/g6-lite';

export function observeDrag(graph: Graph, save: (positions: Array<{ id: string; x: number; y: number }>) => void) {
  const onEnd = ({ nodeIds }: GraphEventMap['node:dragend'][0]) => {
    save(nodeIds.flatMap((id) => {
      const position = graph.getNodePosition(id);
      return position ? [{ id, ...position }] : [];
    }));
  };
  graph.on('node:dragend', onEnd);
  return () => graph.off('node:dragend', onEnd);
}
```

Combo and edge dragging have different payloads; see the [drag reference](/en/docs/api/graph/events#drag-events). Applications must validate and write back drag-edge endpoint proposals.

## Lifecycle and data events

Subscribe before render to receive the initial layout and render events. Await graph.render() before initial incremental mutations. Compare the logs using these controls:

Update A / Add D / Remove D emit the corresponding after*item event. Replace data emits layout events and datachange; Layout emits only layout events. None repeats afterrender. A data write and the browser's next drawn frame are separate milestones; see [lifecycle timing](/en/docs/api/graph/events#lifecycle-and-data-events) for full ordering and cancellation boundaries.

## Removing listeners

Pass the original handler reference to off, rather than a new arrow function with identical text. The observeSelection / observeDrag helpers above return cleanup functions: call them on component unmount or subscription replacement. Graph destruction removes graph listeners; separately clean up application DOM, timers, and network requests.

Use once for a one-time action and register before the required occurrence. Cancel a pending once subscription with off and its original handler. See [on / off / once](/en/docs/api/graph/events#on) for signatures and a live example.

## Custom event typing

Typing an unknown event's handler does not create business events. Use your own channel for application messages. See [Custom Behavior](/en/docs/guides/custom-behavior) for extensions and [GraphEventMap](/en/docs/api/graph/events#grapheventmap) for subscription generics.

## Common questions

### Why is nativeEvent undefined?

Check the event family. Element clicks, hover, and wheel expose nativeEvent. Selection and some drag stages still expose event. node:dragend and region-selection events have no native-event field.

### Why are positions still old when layout finishes?

layout:end / afterlayout precede write-back. Await graph.layout() for results. Avoid unconditionally starting another layout from a completion listener.

### Why does a listener fire repeatedly or never fire?

Check repeated component registration, handler identity for off, whether once was already consumed, and whether the required Behavior is enabled. The unknown-string overload accepts custom names, so misspelled event names can also pass type checking.
