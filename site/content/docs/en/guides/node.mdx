title: Nodes
description: Configure node types, functional styles, labels, and state styles
---

Nodes support built-in circle and rectangle rendering plus registered extensions.

```ts
node: {
  type: 'circle',
  style: {
    size: (node) => node.data?.important ? 28 : 18,
    fill: (node) => node.data?.group === 'core' ? '#1783FF' : '#00C9C9',
    label: (node) => String(node.data?.label ?? node.id),
  },
  stateStyles: {
    selected: { stroke: '#1677ff', strokeWidth: 3 },
    inactive: { opacity: 0.25 },
  },
}
```

## Top-level configuration

These options belong directly under `node`, alongside `style`:

| Option | Purpose and support |
| --- | --- |
| `type` | Select built-in `circle`, `rect`, or a registered node type |
| `style` | Configure the body, label, and icon through an object or style function |
| `stateStyles` | Override body appearance for selected, highlighted, or other states |
| `labelRenderer` | Use a renderer registered with `register('label', ...)`; `style.label` must still supply text |
| `decorations` | Attach badges and other decorations using built-in `builtin-badge` or a registered decoration renderer |
| `autoExternalLabelPlacement` | Declared in the type only; the runtime does not read it, so setting it does not reposition labels |

Set `node.style.labelPlacement` explicitly, for example to `'bottom'`, when positioning labels. See [decoration visibility](/en/docs/guides/extensions#decoration-visibility) for decoration usage and [node configuration](/en/docs/api/options#node) for the configuration structure.

Use state APIs for runtime selection and highlighting. Prefer static or precomputed fields for large graphs; keep functional style callbacks inexpensive.
