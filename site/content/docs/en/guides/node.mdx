## Basic configuration

1. Prepare a container with explicit dimensions and node data with unique IDs. Use `x` and `y` for existing positions, or configure a layout for automatic placement. See [Quick start](/en/docs/getting-started/quick-start) for initial setup.
2. Pass node configuration as `node` in `new Graph({ container, data, node })`, then call and await `graph.render()`.
3. Handle business events and runtime updates after the first render completes. Call `graph.destroy()` when the page unmounts.

Each preview and its complete code use the same source. The code exports `run(container)`: pass a container element and await the returned Graph instance. The preview toolbar fits, zooms, or resets that example.

## Top-level configuration

Choose the configuration location first. These options belong directly under `node`, alongside `style`; individual label and icon appearance fields belong inside `style`.

| Option | When to use it |
| --- | --- |
| `type` | Choose `circle`, `rect`, or a registered business node type |
| `style` | Configure body appearance, labels, and icons; use callbacks for data-dependent fields |
| `stateStyles` | Configure selected or highlighted appearance; activate the state through behaviors or APIs |
| `labelRenderer` | Choose a registered label renderer for richer content, while supplying nonempty `style.label` |
| `decorations` | Attach badges or other supplemental content with built-in or registered decoration renderers |
| `autoExternalLabelPlacement` | Type declaration only: the runtime does not read it. Set `style.labelPlacement` explicitly |

See [`NodeConfig`](/en/docs/api/options/node#nodeconfig) for the complete structure and support status.

## Types

| Shape requirement | Type and dimensions |
| --- | --- |
| Dots, people, or device markers | `type: 'circle'`, with diameter set by `size` |
| Business cards or wide nodes | `type: 'rect'`, with `width`, `height`, and `borderRadius` |
| Reusable business appearance | Call `register('node', name, extension)` before using that `type`; see [Custom nodes](/en/docs/guides/custom-node) |

## Data mapping and selected styles

Put business properties in each node's `data`, then read them in the corresponding style callbacks. A callback receives the current node, without an additional camera or zoom argument.

Supply explicit fallbacks for missing business data and validate dimensions as finite positive numbers before passing data to the graph. Prefer per-field callbacks such as `style: { fill: callback, size: callback }` to retain other styles and state effects. Whole-object functions, `style: (node) => ({ ... })`, currently have different dimension fallbacks and state handling; see [Style callbacks](/en/docs/api/options/node#style-callbacks).

## State styles

Base styles express the node's classification and values. `stateStyles` expresses interaction states such as selection or highlighting. A behavior or state API must activate the state after you configure its appearance.

The circle example combines `stateStyles.selected` with `click-select`. Click B: its green fill and diameter 28 remain, while a dark stroke and halo appear. Click the canvas background to clear selection. In business code, call `graph.setItemState('B', 'selected', true)` on the same Graph instance; use `false` to remove that state, or `graph.clearItemStates('B')` to clear every state.

Specify every effect you want to retain when customizing a state: the same theme state is not merged field by field. Selection also has a minimum halo, so `haloWidth: 0` does not directly remove it. See [State styles](/en/docs/api/options/node#state-styles) for precedence and [Graph state methods](/en/docs/api/graph#state-visibility-and-focus) for visibility and batch operations.

Compare the six built-in states on nodes and edges in [Default theme and states](/en/docs/examples/default-theme).

## Labels and icons

1. Supply a name with `style.label`, usually from `node.data`, and place it with `labelPlacement`.
2. Supply icon content with `style.icon` and choose `iconType` explicitly: `'text'` for text or font glyphs, `'image'` for image URLs. Set the relevant font size or image dimensions.
3. Check the spacing between name and icon. Placing names outside and icons at the center avoids overlap. Top-level `label` policies separately control text scaling, low-zoom hiding, and collision hiding.

These three nodes share one configuration: center letters A, D, and C come from `data.icon`, while names appear on the left, bottom, and right. `labelPlacement` moves names independently of center icons.

## Badge decorations

Counts, warnings, and permission markers can supplement the node body:

1. Specify `renderer` in `node.decorations[]`. `builtin-badge` is already registered; register custom decoration renderers first.
2. Use `data` for a single item, or `layout: 'stack'` with `items` for multiple items. An `items` callback can read business data to produce different badges for each node.
3. Position decorations with `placement`, `attachment`, and `anchor`. Fold long lists with `maxVisible`, `overflow`, and visible `overflowData`.

With 5 badge items and `maxVisible: 3`, the initial view shows a count, warning, and `···`. Hover `···` to expand all 5 items and leave the expanded region to fold them. The node name remains below independently.

## Runtime updates

Reuse the current instance after the first `await graph.render()` completes. Choose the operation by what changed:

| What changed | Operation | Effect on the examples above |
| --- | --- | --- |
| One node's business value | `graph.updateNodeData('B', { value: 40 })` | B becomes diameter 40 in the data-mapping example and retains its group color |
| All nodes need a uniform fill | `graph.updateOptions({ node: { style: { fill: '#7262FD' } } })` | Replace the color callback while retaining size mapping and other appearance fields |
| Business logic selects a node | `graph.setItemState('B', 'selected', true)` | Activate `stateStyles.selected` without rebuilding data |
| All node names move | `graph.updateOptions({ node: { style: { labelPlacement: 'top' } } })` | Move names above nodes while icons remain centered |
| Remove configured decorations | `graph.updateOptions({ node: { decorations: [] } })` | Clear the decoration array while retaining node bodies and labels |
| Replace the entire dataset | `await graph.setData(nextData, { fitView: false })` | Use new data, rerun a configured layout, and retain the camera |

These calls operate on the Graph instance held by your business code. Reset example restores the corresponding initial preview configuration on this page. See [Node mutations](/en/docs/api/graph#nodes) and [`setData()`](/en/docs/api/graph#setdata).

`updateOptions()` merges fields of a style object, but a supplied `stateStyles` or `decorations` replaces the entire state map or decoration array. Submit the complete collection you want to retain. Style updates normally require neither another `render()` nor a layout run. See [Runtime updates](/en/docs/api/options/node#runtime-updates) and [`updateOptions()`](/en/docs/api/graph#updateoptions).

## Common questions

**Width and height do not change a circle**

Set `type: 'rect'` for rectangles. Built-in circles use `size` instead of rectangle dimensions.

**Clicking does not apply state appearance**

Enable a selection behavior or call a state API. Replace a whole-object style function with per-field callbacks when you need state appearance.

**Labels are missing or disappear when zooming out**

Check for nonempty `style.label`, then check top-level label zoom and collision policies; see the [label guide](/en/docs/guides/label#global-label-policies).

**An icon is missing**

Use `iconType: 'text'` for text or `'image'` for URLs, and check URL, cross-origin access, and loading results.

**A custom type or renderer has no effect**

Register before creating or updating configuration. Custom labels also need nonempty `style.label`.

**Fewer items appear than `maxVisible`**

A folded stack reserves an overflow slot. Supply `overflowData` to show it, and use `overflow: 'hover-expand'` for expansion.

**Automatic external labels do not move**

`autoExternalLabelPlacement` is not implemented; set `labelPlacement` explicitly.

**Other states or badges disappear after an update**

`stateStyles` and `decorations` are replaced as whole collections; submit everything you want to retain.

## Performance

- Built-in circles and rectangles use WebGL. Prefer constants for uniform appearance and lightweight callbacks for data-dependent fields; avoid fetching data or doing expensive work inside callbacks.
- Use state APIs for frequent selection or highlight changes and incremental operations for business-data changes, reducing full data replacements and layout runs.
- Show labels and decorations as needed, with zoom, collision, and item-count limits. Keep custom label and decoration measurement and drawing inexpensive.
