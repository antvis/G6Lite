---
title: Performance measurement
description: Measure data, layout, rendering, and interactions separately with reproducible conditions
---

Fix data and environment before comparing equivalent work. Record drawing with supplied coordinates, layout-inclusive startup, and later interactions separately.

## Environment requirements

Record package/source and dependency versions, browser/OS, CPU/GPU, CSS viewport, DPR, node/edge counts, labels/styles, layout options, cache state, and actual Worker execution. Save data, a seed where supported, runnable code, and raw samples.

## Current public measurement scope

| Metric | Boundary |
| --- | --- |
| Data preparation | Business input → GraphData; separate from rendering |
| Layout | runLayout start → positions returned; separate cold/warm loads |
| Construction and render resolution | new Graph → await render; CPU setup and draw submission, not GPU completion |
| Interactions | Continuous zoom/drag, state and bulk position updates; frame times and main-thread tasks |
| Resources | Compare instances, canvases, subscriptions, and memory after repeated mount/destroy |

This function separates layout and render work and releases each instance. Use a visible, non-zero-size container. Grid illustrates the boundaries; its time does not represent other algorithms.

```ts
import { Graph, runLayout, type GraphData } from '@antv/g6-lite';

export async function measureOnce(container: HTMLElement, data: GraphData) {
  if (document.visibilityState !== 'visible') throw new Error('Keep the tab visible');
  const start = performance.now();
  const positions = await runLayout(data, { type: 'grid' });
  const layoutMs = performance.now() - start;
  const coordinates = new Map(positions.nodes.map((node) => [node.id, node]));
  const positioned = { ...data, nodes: data.nodes.map((node) => ({
    ...node, ...coordinates.get(node.id),
  })) };
  const createStart = performance.now();
  const graph = new Graph({ container, data: positioned, behaviors: [] });
  try {
    await graph.render();
    const renderResolvedMs = performance.now() - createStart;
    await new Promise<void>((resolve) => requestAnimationFrame(() => {
      requestAnimationFrame(() => resolve());
    }));
    return { layoutMs, renderResolvedMs, throughTwoFramesMs: performance.now() - createStart };
  } finally {
    graph.destroy();
  }
}
```

Use the monotonic [performance.now clock](https://developer.mozilla.org/en-US/docs/Web/API/Performance/now). Two [requestAnimationFrame callbacks](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame) do not prove GPU completion or presentation to the user. Background tabs affect this measurement.

## Library selection comparison

Use the [capability comparison](/en/docs/compatibility/library-comparison) to select candidates. Match positions, labels, edges, and interactions. Do not compare one renderer without layout against another startup that includes force computation.

## How to compare numbers

1. Record cold startup separately. Warm up hot paths and collect at least 30 independent samples; report the count.
2. Keep all samples; report median, P95, and range. Explain outliers instead of silently deleting them.
3. Progress through 200/5000-node and realistic datasets, then verify dragging, labels, and cleanup on target devices.

Runnable workloads: [200 nodes](/en/docs/examples/large) · [5000 nodes](/en/docs/examples/large-labeled) · [AI Papers](/en/docs/examples/ai-papers)。Read each example’s dataset description. For tuning see [performance tuning](/en/docs/metrics/performance-tuning)。
