## 在本地使用 Skill

将仓库中的 [antv-g6lite-graph](https://github.com/antvis/G6Lite/tree/master/skills/antv-g6lite-graph) 目录交给支持 Skill 的 Agent，按所用客户端的安装方式加载；Skill 本身不安装 G6Lite npm 包。支持显式调用的客户端可以在请求中写：

```text
Use $antv-g6lite-graph to implement the graph described below.
Check the installed @antv/g6-lite version and package-root types first.
```

在项目目录用 `npm ls @antv/g6-lite` 确认版本。Skill 的主要约束是包根 API、浏览器生命周期、真实支持范围和分阶段验证；不确定的字段先查询[API 总览](/docs/api)，不要猜测深层导入或照搬 v5 插件。

## 适合交给 Agent 的任务

| 任务 | 应提供的输入 |
| --- | --- |
| 创建或更新关系图 | 框架、数据样本、ID/端点规则、规模、容器尺寸 |
| 增加选择、拖拽或 Tooltip | 手势、业务响应、状态保留和清理要求 |
| 调整布局、标签或品牌效果 | 已有坐标、布局目标、标签密度、目标截图 |
| 迁移或排障 | 当前版本、最小代码、报错与复现步骤、必须保留的行为 |

### 可复制的输入模板

```text
使用 $antv-g6lite-graph 完成以下任务：
- 项目：React + TypeScript；先读取实际依赖与 G6Lite 版本
- 数据：3 个节点 A/B/C，边 A→B、A→C；节点 ID 稳定
- 容器：宽度 100%，高度 360px；仅客户端创建
- 布局：circular；显示节点 ID；支持缩放、平移、拖拽
- 更新：新增 D 和 B→D，复用 Graph；保留视野
- 清理：首次 render 未完成就卸载，也不能遗留画布或监听
- 输出：完整组件、必要依赖、验证操作与预期结果
先确认字段与方法真实存在，再实现。超出能力边界时明确说明。
```

将框架、规模和交互替换为实际需求。需要 Vue 时，改用 [Vue 接入](/docs/getting-started/vue)的生命周期。

## 推荐工作流

1. **跑通最小图**：确认容器、数据、首次 render；对照[快速上手](/docs/getting-started/quick-start)。
2. **增加一类能力**：样式、布局、状态或扩展逐项添加；参数查[参考](/docs/api)，步骤查[指南](/docs)。
3. **验证变化和离开**：切换数据、快速切页、重复挂载；React 再启用 StrictMode。
4. **用真实业务验收**：检查目标设备上的标签、拾取、布局耗时与资源清理；参考[性能测量](/docs/metrics/performance)。

### 最小验收操作

模板案例应先出现 3 节点 / 2 边，更新后出现 4 / 3；视野保留，拖拽仍可用。卸载后不应遗留画布；重新挂载可以再次操作。类型检查通过和浏览器可操作都要验证，不能仅根据代码截图判断成功。
