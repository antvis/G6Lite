`Graph` 是业务代码操作一张图的实例。从包根导入后，先传入 [配置](/docs/api/options)，再 `await graph.render()`。

```ts
import { Graph } from '@antv/g6-lite';

const graph = new Graph({ container, data });
await graph.render();
```

数据写入、状态修改和 `layout()` 必须发生在首次 `render()` 成功之后。实例销毁后，这些方法直接返回。

## 生命周期

创建、渲染、销毁与刷新的完整契约见[生命周期方法参考](/docs/api/graph/lifecycle)。阶段选择与清理步骤见[Graph 生命周期](/docs/concepts/graph-lifecycle)。

### `new Graph(options)`

[创建实例](/docs/api/graph/lifecycle#new-graph)：容器、画布归属及 GraphOptions 入口。

### `render()`

[render](/docs/api/graph/lifecycle#render)：等待有效初始化完成，了解重复渲染、事件顺序和取消边界。

### `destroy()`

[destroy](/docs/api/graph/lifecycle#destroy)：销毁实例资源；业务请求、计时器和 DOM 监听由业务清理。

### `destroyed`

[destroyed](/docs/api/graph/lifecycle#destroyed)：只读销毁标记，不等于渲染成功或任务有效。

### `refresh()`

[refresh](/docs/api/graph/lifecycle#refresh)：重算样式并绘制，不重新初始化、布局或适配。

## 读取数据

查询返回当前图中的只读视图。修改画面请使用后面的写入方法。

```ts
const snapshot = graph.getData();
const nodes = graph.getNodes();
const node = graph.getNodeData('n1');
const neighbors = graph.getNeighborNodes('n1');
const edges = graph.getAdjacentEdges('n1');

if (graph.hasNode('n1') && node) {
  node.x;
  node.y;
  node.data;
  neighbors.length;
  edges[0]?.source;
  snapshot.nodes.length;
}
```

| 方法 | 返回值 | 说明 |
| --- | --- | --- |
| `getData()` | `GraphData` | 当前节点、边和 Combo 的数据快照 |
| `getNodes()` | `readonly NodeModel[]` | 全部节点 |
| `getNodeData(id)` | `NodeModel \| undefined` | 按 id 取节点 |
| `getEdges()` | `readonly EdgeModel[]` | 全部边 |
| `getEdgeData(id)` | `EdgeModel \| undefined` | 按 id 取边 |
| `getComboData(id)` | `ComboModel \| undefined` | 按 id 取 Combo |
| `getElementData(id)` | `ElementModel \| undefined` | 按 id 取节点、边或 Combo |
| `getNodeCount()` | `number` | 节点数量 |
| `getEdgeCount()` | `number` | 边数量 |
| `hasNode(id)` | `boolean` | 是否存在该节点 |
| `hasEdge(id)` | `boolean` | 是否存在该边 |
| `hasElement(id)` | `boolean` | 是否存在该节点、边或 Combo |
| `getElementPosition(id)` | `{ x, y } \| null` | 节点或 Combo 的图坐标；边没有单一位置 |
| `getNeighborNodes(nodeId)` | `string[]` | 相邻节点 id |
| `getAdjacentEdges(nodeId)` | `{ id, source, target }[]` | 与节点相连的边 |

`NodeModel` 包含 `id`、`name`、`x`、`y`、`data` 和 `states`。`EdgeModel` 包含 `id`、`source`、`target`、`data` 和 `states`。`states` 是只读集合。

首次 `render()` 之前，`getData()` 返回构造时传入的数据副本；其余查询按空图处理。

## 替换数据与样式

### `setData()`

```ts
await graph.setData(
  {
    nodes: [{ id: 'a' }, { id: 'b' }],
    edges: [{ id: 'a-b', source: 'a', target: 'b' }],
  },
  { fitView: false },
);
```

用一份新的节点、边和 Combo 替换整张图。配置了 `layout` 时会重新布局，然后完整重绘，并发出 `datachange`。

`options.fitView` 决定替换后的视口：

- 省略或 `true`：按 `0.9` 调用 `fitView()`。
- `false`：保留当前相机。
- 数字或 `FitViewOptions`：按该参数调用 `fitView()`。

局部增删改使用下面的增量方法，避免整图重布局。

### `updateOptions()`

[updateOptions](/docs/api/graph/lifecycle#updateoptions) 更新 node、edge、label 和 theme；对象、函数和状态样式的合并规则见方法参考。它不接受布局、行为或插件配置；更换布局使用 [setLayout + layout](/docs/api/graph/layout)。

## 修改节点和边

这些方法都要求首次 `render()` 已经完成。批量方法只触发一次绘制。

### 节点

```ts
graph.addNode({ id: 'n4', x: 240, y: 80, data: { label: 'N4' } });
graph.updateNodeData('n4', { label: '已更新' });
graph.updateNodePosition('n4', 260, 100);
graph.updateNodePositions([
  { id: 'n1', x: 40, y: 40 },
  { id: 'n4', x: 280, y: 120 },
]);
graph.removeNode('n4');
```

`addNode()` 的 `id` 必须唯一，并带上图坐标。它不会重新跑布局。

`updateNodeData()` 合并业务字段。样式函数读取了这些字段时，下一帧会按新字段重算样式。

`removeNode()` 同时删除与该节点相连的边。

成功修改后会发出 `afteradditem`、`afterupdateitem` 或 `afterremoveitem`。

### 边

```ts
const edgeId = graph.addEdge({ source: 'n1', target: 'n4', data: { weight: 1 } });
graph.updateEdgeData(edgeId, { weight: 2 });
graph.updateEdgeData([{ id: edgeId, source: 'n2', target: 'n4' }]);
graph.removeEdge(edgeId);
```

`source` 和 `target` 必须是已经存在的节点。省略 `id` 时由引擎生成，返回值就是这条边的 id，之后的查询和删除都使用它。

批量 `updateEdgeData()` 还可以修改边的两端节点。

### `setItemState()`

[增减一个状态](/docs/api/graph/states#setitemstate)，保留其他标记。

### `setElementStates()`

[替换完整状态集合](/docs/api/graph/states#setelementstates)，支持单 id 和状态映射。

### `batchSetState()`

### 查询和清空

[getItemStates](/docs/api/graph/states#getitemstates) 读取快照；[findNodesByState](/docs/api/graph/states#findnodesbystate)、[findEdgesByState](/docs/api/graph/states#findedgesbystate)、[findCombosByState](/docs/api/graph/states#findcombosbystate) 查询对应 ID；[clearItemStates](/docs/api/graph/states#clearitemstates) 清空业务状态。

### `hideItem()` 与 `showItem()`

[hideItem](/docs/api/graph/states#hideitem) 和 [showItem](/docs/api/graph/states#showitem) 增减 hidden；关联元素与折叠隐藏的边界见新参考中的代码与效果。

### `focusItem()`

[focusItem](/docs/api/graph/viewport#focusitem) 定位一个或多个节点；目标范围、缩放和 padding 规则见视口方法参考。

## 视口

相机、缩放、适配、定位、尺寸与坐标转换的完整契约见[视口方法参考](/docs/api/graph/viewport)。任务步骤见[视口指南](/docs/guides/viewport)，坐标关系见[核心概念](/docs/concepts/viewport)。

相机查询与恢复：[getCamera](/docs/api/graph/viewport#getcamera) · [setCamera](/docs/api/graph/viewport#setcamera) · [resetCamera](/docs/api/graph/viewport#resetcamera)。

### 容器尺寸变化

[setSize](/docs/api/graph/viewport#setsize) 同步画布尺寸；容器 CSS 变化由 ResizeObserver 自动处理。[autoFit](/docs/api/options#autofit) 决定尺寸变化后是否适配，resize 在可选适配后发出。宽度切换效果见[实时示例](/docs/api/graph/viewport#容器变宽变窄后的适配)。

### `zoomTo()` 与 `zoomBy()`

[getZoom](/docs/api/graph/viewport#getzoom) 查询缩放；[zoomTo](/docs/api/graph/viewport#zoomto) 设置绝对值，[zoomBy](/docs/api/graph/viewport#zoomby) 乘当前值。中心和 ZoomOptions 查方法参考；滚轮范围查 [Behavior](/docs/api/options/behaviors#导航与拖拽)。

### `fitView()`

[fitView](/docs/api/graph/viewport#fitview) 调整缩放和平移；[fitCenter](/docs/api/graph/viewport#fitcenter) 保持缩放只居中。刷新后保留视野见[使用指南](/docs/guides/viewport#刷新数据保留或重新适配)。

### 坐标转换

[screenToGraph](/docs/api/graph/viewport#screentograph) 从 client CSS 坐标转到图坐标；[graphToScreen](/docs/api/graph/viewport#graphtoscreen) 反向转换。实时观察与 DOM 定位见[坐标指南](/docs/guides/viewport#转换坐标定位-dom-内容)。

## 布局

签名、前提、事件顺序和取消语义统一见[布局方法参考](/docs/api/graph/layout)：[setLayout](/docs/api/graph/layout#setlayout) 保存配置，[layout](/docs/api/graph/layout#layout) 重新计算，[cancelLayout](/docs/api/graph/layout#cancellayout) 放弃当前任务。

布局字段见[配置参考](/docs/api/options/layout)，操作步骤见[布局指南](/docs/guides/layout)。不创建 Graph、只计算坐标时用 [runLayout](/docs/api/graph/layout#runlayout)。

## Combo

Combo 的折叠、嵌套和运行时重新归组仍是实验能力，配置细节可能在 `0.1.x` 内调整。外观见 [Combo](/docs/guides/combo)。这些方法同样要在首次 `render()` 之后调用；渲染前调用会直接返回，不会创建或修改 Combo。

```ts
graph.createCombo({ id: 'group', data: { label: '分组' } }, ['n1', 'n2']);
graph.addToCombo('n3', 'group');
const children = graph.getComboChildren('group');
graph.collapseCombo('group');
graph.expandCombo('group');
graph.removeFromCombo('n3');
graph.removeCombo('group');
children.nodes;
```

`createCombo()` 可以在第二个参数里把已有节点放进新 Combo。`collapseCombo()` 隐藏其下节点并发出 `combo:collapse`；`expandCombo()` 恢复它们并发出 `combo:expand`。对已经处于目标状态的 Combo 再次折叠或展开不会重复发事件。

Combo 的选中和隐藏使用前面的 `setItemState()`、`hideItem()`，不要再调用旧的 `setComboState()`。

通过 [on](/docs/api/graph/events#on)、[off](/docs/api/graph/events#off)、[once](/docs/api/graph/events#once) 注册和取消监听；可在首次 render 前订阅。

- [GraphEventMap](/docs/api/graph/events#grapheventmap)：参数元组、订阅类型和自定义名称边界。
- [元素载荷](/docs/api/graph/events#元素事件载荷)、[选择](/docs/api/graph/events#选择事件)、[拖拽](/docs/api/graph/events#拖拽事件)：完整字段与触发条件。
- [生命周期与数据](/docs/api/graph/events#生命周期与数据事件)：渲染、布局、数据修改、尺寸与销毁的时机。

业务接入和文档内代码效果见[事件指南](/docs/guides/events)。Behavior 开关查[交互组合](/docs/guides/interactions)。
