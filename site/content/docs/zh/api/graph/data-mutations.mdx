## 共同前提与类型简写

等待首次有效 render 完成；此前调用抛错，销毁后写入方法不执行。除 setData 返回 Promise、addEdge(s) 返回实际 ID 外，其余方法返回 void。数据同步改动不等于浏览器已绘制；常规增量操作自行调度更新，不需再次 render。

下文 NewNode / NewEdge 是为阅读定义的类型简写。提供唯一且稳定的 ID、有限坐标、有效端点。批量方法不承诺原子事务或失败回滚；先校验输入。

```ts
import type { ElementState } from '@antv/g6-lite';
type NewNode = { id: string; x: number; y: number; data?: Record<string, unknown> };
type NewEdge = {
  id?: string; source: string; target: string;
  data?: Record<string, unknown>; states?: ElementState[];
};
```

## setData

`graph.setData(data: GraphData, options?: SetDataOptions): Promise<void>`

替换全部节点、边和 Combo，执行注册转换及当前布局，再写回并发出 datachange。新数据未带的旧元素、归属与状态不自动保留。自动生成的边 ID 计数重新开始；跨更新保存边选择时显式提供稳定 ID。

| options.fitView | 行为 |
| --- | --- |
| 省略 / true | fitView(0.9) |
| false | 保留当前相机 |
| number / FitViewOptions | 使用本次适配参数，不继承 autoFit 对象 |

```ts
import type { Graph, GraphData } from '@antv/g6-lite';
export async function replace(graph: Graph, next: GraphData) {
  await graph.setData(next, { fitView: false });
  if (graph.destroyed) return;
  console.log(graph.getNodeCount());
}
```

正常有效路径在数据写回并请求绘制后完成，之后可查询新模型；不保证浏览器已绘制该帧。新操作、取消或销毁可使旧结果失效，旧 Promise 仍可能兑现，后续业务副作用需要自己的代次保护。错误可能拒绝 Promise，也不承诺保留旧数据。

### 增量更新的代码和效果

Update A 合并 score 并改变尺寸；Add D 创建 D 与 C-D；Remove D 同时移除节点和关联边。它们不重新运行布局或改变相机。

## addNode

`graph.addNode(node: NewNode): void`

新增节点，必须提供 id 和图坐标 x/y。重复节点 ID 当前被忽略；不接受初始 states、comboId 或 fx/fy，需随后调用对应方法。不重新布局。

## addNodes

`graph.addNodes(nodes: NewNode[]): void`

批量新增；重复 ID 跳过。统一调度绘制，但不是事务。

## updateNodeData

`graph.updateNodeData(id: string, data: Record<string, unknown>): void`

另有重载 graph.updateNodeData(updates: NodeDataUpdate[]): void；NodeDataUpdate 为 id 加 data。浅合并业务字段，嵌套对象整体替换；不能改节点 ID、坐标或归属。缺失节点跳过。

## updateNodePosition

`graph.updateNodePosition(id: string, x: number, y: number): void`

更新图坐标，缺失节点不改数据。不是客户端 CSS 坐标；不执行布局或视口适配。

## updateNodePositions

`graph.updateNodePositions(updates: NodePositionUpdate[]): void`

NodePositionUpdate 为 id/x/y。按顺序更新有效且坐标变化的节点，统一调度；缺失或未变化的项不发对应更新事件。

## removeNode

`graph.removeNode(id: string): void`

删除节点及其所有入边、出边，解除该节点归属；不删除所属 Combo。缺失节点不改数据。

## removeNodes

`graph.removeNodes(ids: string[]): void`

批量删除节点与关联边，缺失 ID 忽略；集合查询顺序可能改变。

## addEdge

`graph.addEdge(edge: NewEdge): string`

返回实际边 ID；省略 id 会生成 e0、e1 等并避开已有 ID。显式重复边 ID 抛错；端点须由业务先校验，当前新增路径不保证主动拒绝无效端点。销毁后返回空字符串。

## addEdges

`graph.addEdges(edges: NewEdge[]): string[]`

按输入顺序返回实际 ID，销毁后为 []。重复显式 ID 可能在前面项目已写入后抛错，不提供回滚。

## updateEdgeData

`graph.updateEdgeData(id: string, data: Record<string, unknown>): void`

单条形式只浅合并业务 data；重载 graph.updateEdgeData(updates: EdgeDataUpdate[]): void 还支持改 source/target。EdgeDataUpdate 为 id 和可选 data/source/target；不改 id。当前批量路径先校验有效边的新端点，不存在的端点会抛错，缺失边本身跳过。

## removeEdge

`graph.removeEdge(id: string): void`

删除指定边，保留两端节点；缺失边不改数据。

## removeEdges

`graph.removeEdges(ids: string[]): void`

批量删除边，忽略缺失 ID，统一安排更新。


## 批量调用示例

```ts
import type { Graph } from '@antv/g6-lite';
declare const graph: Graph; // 已渲染，A 存在
graph.addNodes([{ id: 'D', x: 300, y: 40 }, { id: 'E', x: 300, y: 120 }]);
graph.addEdges([{ id: 'A-D', source: 'A', target: 'D' }]);
graph.updateNodeData([{ id: 'D', data: { score: 2 } }]);
graph.updateNodePositions([{ id: 'D', x: 320, y: 60 }]);
graph.updateEdgeData([{ id: 'A-D', target: 'E', data: { weight: 3 } }]);
graph.removeNodes(['D', 'E']); // 关联边也会移除
```

## 事件与缺失 ID

add/remove 调用产生 afteradditem / afterremoveitem；数据与位置更新产生 afterupdateitem。批量调用按条目发事件，不代表事务提交，也不会补发 afterrender。删除节点引发的关联边删除不逐边发 afterremoveitem。

当前部分单项方法即使 ID 缺失或数据未变化也会发方法级事件，addNodes / removeNodes 等也可能对跳过的输入 ID 发事件。成功事件不能替代 hasNode / hasEdge 和实际模型查询；精确时序见[数据事件](/docs/api/graph/events/lifecycle)。
