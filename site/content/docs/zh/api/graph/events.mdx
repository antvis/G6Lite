用 on 注册监听，off 移除监听，once 只监听一次。第一次接入可从[事件入门](/docs/guides/events)开始；完整事件按[元素](/docs/api/graph/events/element)、[选择](/docs/api/graph/events/selection)、[拖拽](/docs/api/graph/events/drag)、[生命周期与数据](/docs/api/graph/events/lifecycle)分类查询。

## on

持续接收事件，直到取消监听或销毁实例。

```ts
import type { Graph } from '@antv/g6-lite';

declare const graph: Graph;
graph.on('node:click', ({ nodeId }) => {
  console.log('clicked', nodeId);
});
```

**参数**：event 为事件名称；handler 为处理函数，参数随事件名推导。**返回值**：void。

可以在 render 前注册，以接收首次渲染事件。同一函数重复注册会重复调用；销毁后不再添加监听。

## off

使用注册时的同一个函数取消监听，也可取消尚未触发的 once。

```ts
import type { Graph, GraphEventMap } from '@antv/g6-lite';

declare const graph: Graph;
const onClick = ({ nodeId }: GraphEventMap['node:click'][0]) => console.log(nodeId);
graph.on('node:click', onClick);
graph.off('node:click', onClick);
```

**参数**：event 为原事件名；handler 为原函数引用，均不可省略。**返回值**：void。

同一函数的重复注册会一并移除；未注册时无操作。完整页面清理见[监听与清理](/docs/guides/events#取消监听)。

## once

只接收注册后的下一次事件，触发后自动移除；不会补发历史事件。

```ts
import type { Graph } from '@antv/g6-lite';

declare const graph: Graph;
graph.once('afterrender', ({ nodeCount }) => console.log(nodeCount));
await graph.render();
```

**参数**与 on 相同。**返回值**：void。销毁后不再添加监听。

## 元素事件载荷

元素事件描述“点到了谁”。常用字段是 nodeId / edgeId / comboId、业务 data，以及 client、canvas、graph 三种坐标。原始鼠标或滚轮对象从 nativeEvent 读取。

字段定义和三种坐标的解释见[读取事件参数](/docs/api/graph/events/element#读取事件参数)。

### 元素事件清单

| 想监听的操作 | 事件与详情 |
| --- | --- |
| 点击节点 | [node:click](/docs/api/graph/events/element#nodeclick) |
| 悬停节点 | [node:pointerover](/docs/api/graph/events/element#nodepointerover) |
| 点击边 | [edge:click](/docs/api/graph/events/element#edgeclick) |
| 点击分组背景 | [combo:click](/docs/api/graph/events/element#comboclick) |
| 点击空白 | [canvas:click](/docs/api/graph/events/element#canvasclick) |

其余按下、松开、移动、离开、双击、右键和滚轮事件，查[完整元素事件](/docs/api/graph/events/element)。

## 选择事件

选择事件描述“选择结果改变了什么”，需要启用对应 Behavior；它们的参数与元素点击不同。

- [node:selectchange](/docs/api/graph/events/selection#nodeselectchange)：被点击节点切换选中。
- [selection:clear](/docs/api/graph/events/selection#selectionclear)：已有选择被清空。
- [brush:end](/docs/api/graph/events/selection#brushend)、[lasso:end](/docs/api/graph/events/selection#lassoend)：区域选择结束。

完整字段查[选择事件参考](/docs/api/graph/events/selection)，业务同步写法见[选择与拖拽](/docs/guides/events#选择与拖拽事件)。

## 拖拽事件

以 start → drag → end 描述一次拖拽。保存位置通常监听 [node:dragend](/docs/api/graph/events/drag#nodedragend)，边落点监听 [edge:dragend](/docs/api/graph/events/drag#edgedragend)。

[拖拽事件参考](/docs/api/graph/events/drag)分别说明节点、Combo 和边端点的参数及写回责任。

## 生命周期与数据事件

- [afterrender](/docs/api/graph/events/lifecycle#afterrender)：显式 render 完成同步绘制。
- [datachange](/docs/api/graph/events/lifecycle#datachange)：setData 完成整体数据替换。
- [afterupdateitem](/docs/api/graph/events/lifecycle#afterupdateitem)：增量修改结果。
- [destroy](/docs/api/graph/events/lifecycle#destroy)：首次销毁通知，无参数。

布局、尺寸和 Combo 折叠等事件查[完整参考](/docs/api/graph/events/lifecycle)；可操作日志见[生命周期指南](/docs/guides/events#生命周期与数据事件)。

### 顺序与完成边界

首次接入先在 render 前订阅，再 await graph.render()，然后修改数据或状态。setData、layout 和局部更新不会重复触发 afterrender。

布局结束通知发生在坐标写回之前；等待 await graph.layout() 后读取最终坐标。完整顺序和取消语义见[顺序与完成边界](/docs/api/graph/events/lifecycle#顺序与完成边界)。

## GraphEventMap

需要给复用函数声明参数类型时，从公开 GraphEventMap 取出对应事件的第一个参数：

```ts
import type { GraphEventMap } from '@antv/g6-lite';

type NodeClick = GraphEventMap['node:click'][0];
type DestroyArguments = GraphEventMap['destroy']; // []
```

<details>
<summary>完整订阅签名与类型边界</summary>

on、off、once 的公开签名均为：

```ts
import type { GraphEventMap, Handler } from '@antv/g6-lite';

declare function subscribe<K extends keyof GraphEventMap>(
  event: K, handler: Handler<GraphEventMap[K]>,
): void;
declare function subscribe<Args extends unknown[]>(
  event: string, handler: Handler<Args>,
): void;
```

Map 的值为参数元组：destroy 为 []，其余公开事件为单对象参数。未知字符串重载兼容业务声明，也意味着拼错名称可能通过检查。Graph 无公开 emit；自定义事件类型不会产生业务事件。普通元素参数类型从包根导出，详见[元素字段](/docs/api/graph/events/element#读取事件参数)。

</details>

<details>
<summary>调用顺序与回调异常</summary>

事件按监听注册顺序同步调用，once 在执行前移除。原生事件中触发 Behavior 时，可能同步发出嵌套的派生事件；不要假设 node:click 总在 node:selectchange 之前被业务观察到。需要最终选择集合时监听派生结束事件并查询状态。

普通 graph.on 回调抛出的异常会向外传播，可能中断后续监听或当前操作。业务回调自行处理异常，异步操作自行捕获拒绝；事件系统不等待 Promise。订阅名称 * 只收到载荷，不额外携带原事件名，不适合作为带名称的统一事件日志。

</details>
