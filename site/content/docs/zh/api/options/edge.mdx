`GraphOptions.edge` 的类型是 `EdgeConfig`。本页统一定义顶层配置、全部样式字段、状态覆盖、曲线路由、标签、平行边和运行时更新，提供同源码的代码与效果对照。按步骤配置与排查见[边使用指南](/docs/guides/edge)，整体结构见 [GraphOptions](/docs/api/options)。

## EdgeConfig

所有顶层字段均可省略。

| 字段 | 类型 | 默认行为与入口 |
| --- | --- | --- |
| `type` | `'line' \| 'arc' \| 'polyline' \| 'cubic' \| string` | 默认 `'line'`；自定义名称先通过 `register('edge', ...)` 注册，使用扩展声明的 `base` |
| `style` | `EdgeConfig['style']` | 外观字段对象；支持回调的字段使用 `EdgeStyleValue<T>`，见下文 |
| `stateStyles` | `Partial<Record<EdgeState, EdgeStateStyleOverride>>` | 按状态覆盖基础外观，见[状态样式](#状态样式) |
| `labelRenderer` | `string` | 使用默认边标签渲染器；指定名称须先注册 label 扩展，并通过 `edge.style.label` 提供非空文本 |
| `parallelEdges` | `boolean \| ParallelEdgesConfig` | 未配置时不从此字段启用平行边分离；已有 transform 入口仍独立生效，详见[平行边指南](/docs/guides/parallel-edges) |

内置类型分别表示直线、弧线、折线和三次贝塞尔曲线。未知名称当前回退为直线基型，不应依赖该回退代替注册。边数据中的 `source`、`target`、`id` 见 [`GraphEdge`](/docs/api/options#边-graphedge)。

## 基础样式

以下字段位于 `edge.style`。默认值适用于内置边；主题和边扩展可改变回退值。

| 字段 | 类型 | 默认或回退 | 说明 |
| --- | --- | --- | --- |
| `stroke` | `EdgeStyleValue<string>` | `theme.edgeStroke`；light 为 `'#99ADD1'`，dark 为 `'#637088'` | 边和箭头颜色 |
| `lineWidth` | `EdgeStyleValue<number>` | `theme.edgeLineWidth`，预设为 `1` | 视觉线宽，使用有限正数 |
| `opacity` | `EdgeStyleValue<number>` | `1` | 不透明度，使用 `0` 到 `1` |
| `lineDash` | `EdgeStyleValue<number[]>` | `[]` | 空数组为实线；当前按前两个值之和计算虚线周期，见[虚线规则](#虚线规则) |
| `startArrow` | `EdgeStyleValue<boolean>` | `false` | 起点箭头，指向 `source` |
| `endArrow` | `EdgeStyleValue<boolean>` | `theme.edgeArrow`，light、dark 均为 `true` | 终点箭头，指向 `target` |
| `arrowSize` | `EdgeStyleValue<number>` | 根据线宽自动计算 | 箭头沿路径方向的长度；显式长度使用有限正数，非正值使用自动长度 |
| `hitAreaWidth` | `EdgeStyleValue<number>` | 最终 `lineWidth` | 总点击热区宽度，不改变视觉线宽，见[点击热区](#点击热区) |

`lineWidth`、`hitAreaWidth`、`arrowSize` 和虚线周期使用屏幕渲染像素，随相机缩放保持其渲染尺寸；业务无需自行乘 zoom、DPR 或 Picking framebuffer 比例。节点位置仍使用图坐标。

三行预览分别为：Plain（灰色细实线、无箭头）、Dash（半透明橙色虚线、终点箭头）、Both（蓝色粗实线、双向箭头）。所有箭头显式设置 `arrowSize: 16`。点击边会变为紫色选中样式；重置恢复初始效果。

### 样式回调

`EdgeStyleValue<T>` 为 `T | ((source: GraphNode, target: GraphNode, edge: GraphEdge) => T)`。前两个入参是端点节点，第三个才是当前边；边的业务字段从 `edge.data` 读取。上面示例同时映射颜色、线宽、虚线、透明度和箭头方向。

`style` 的公开类型是字段对象，不是返回整个对象的函数。逐字段优先级为：显式边样式 → 边扩展 `getStyle(source, target, edge)` 的结果 → 扩展默认样式 → 主题或内置回退。回调只做轻量计算，并为缺失数据提供有效回退。

### 虚线规则

当前渲染使用 `lineDash[0] + lineDash[1]` 作为周期，每个周期中一半绘制、一半留空；后续数组项不参与。因此 `[4, 12]` 和 `[8, 8]` 的效果相同，并非 Canvas 的任意长短交替模式。少于两项或非正周期不产生虚线；使用有限非负数且总和大于零。

内置直线在没有额外加宽或状态要求时可能使用 1 像素绘制路径，该路径不绘制虚线。需要确定的虚线效果时，像上例一样显式设置 `lineWidth > 1`。虚线间隙仍可被命中，箭头本身不跟随虚线周期断开。

## 箭头

`startArrow` 和 `endArrow` 分别控制起点和终点；起终点由数据的 `source`、`target` 决定。关闭默认终点箭头需显式设置 `endArrow: false`。

自动长度按线宽计算：不大于 `2` 时为 `10`，大于 `2` 且不大于 `4` 时为 `12`，更粗时为 `Math.round(lineWidth * 2.5)`。`arrowSize` 控制沿边方向的长度，横向宽度由线宽加 `12` 决定，并非同时设置箭头宽高。箭头贴合端点节点边界，线段会为箭头预留空间。

当前静态配置会缓存基础线宽对应的自动长度；状态改变线宽时，静态与逐字段回调路径可能得到不同的自动箭头长度。需要跨状态保持确定尺寸时，显式设置正的 `arrowSize`，如上例的 `16`。

## 点击热区

`hitAreaWidth` 是路径两侧合计的命中宽度。例如 `24` 相当于中心线两侧各约 `12` 的范围；热区本身不可见。解析完成后，其值至少为当前视觉线宽；负值、非有限值或省略值使用视觉线宽。

下面两条边都以 `lineWidth: 1.5` 绘制，上方热区为 `2`，下方为 `24`。尝试在细线附近点击：下方更容易选中；选中只变为紫色，线条保持细线。工具栏缩放后再比较，热区保持同一屏幕尺寸口径。

<EdgeDocExample id="edge-hit-area" locale="zh" />

热区供悬停、点击选择、Tooltip 和拖拽边等共享 Picking 交互使用；配置热区本身不会安装交互行为，示例通过 `click-select` 激活选中状态。直线、弧线、曲线、折线、自环和箭头均使用该热区策略；更多路径可在[细边交互示例](/docs/examples/edge-hit-area)中比较。

## 状态样式

`EdgeStateStyleOverride` 支持下列固定值，不支持字段回调：

| 字段 | 类型 | 作用 |
| --- | --- | --- |
| `stroke` | `string` | 覆盖边和箭头颜色 |
| `lineWidth` | `number` | 覆盖视觉线宽 |
| `hitAreaWidth` | `number` | 覆盖总命中宽度，最终不会小于当前视觉线宽 |
| `opacity` | `number` | 覆盖不透明度 |
| `lineDash` | `number[]` | 覆盖虚线周期输入 |

状态由交互行为或 `graph.setItemState(edgeId, state, value)` 激活。每个状态选用配置、扩展、主题中的第一个已定义对象，不会逐字段补齐同名主题状态。多个状态按状态集合的迭代顺序覆盖，后处理的同名字段优先，`default` 不参与覆盖；`hidden` 优先令解析后的不透明度为 `0`。状态和显隐方法见 [Graph API](/docs/api/graph#状态显隐和定位)。

## 运行时更新

首次 `await graph.render()` 完成后，可用 `graph.updateOptions({ edge: { style: ... } })` 更新已有实例。`style` 按字段合并，提供的 `stateStyles` 替换整个状态映射；保留其他状态时提交完整映射。该操作重算样式，不自动重新布局。修改业务字段使用 `updateEdgeData()`，修改端点使用该方法的批量格式，在更新项中提供 `id`、`source`、`target`；详见[边增量操作](/docs/api/graph#边)与 [`updateOptions()`](/docs/api/graph#updateoptions)。

## 平行边与自环

`edge.parallelEdges` 接受布尔值或 `ParallelEdgesConfig`。仅用对象入口时，`{ offset: 30 }` 不会启用分离，须写 `{ enabled: true, offset: 30 }`；`true` 使用默认参数。

| 字段 | 类型 | 默认与规则 |
| --- | --- | --- |
| `enabled` | `boolean` | 默认关闭；对象入口须显式启用，transform 入口也可启用。边配置中的 `false` 可关闭两种入口 |
| `offset` | `number` | `20`，图坐标中的偏移步长；须为有限正数，否则回退为 `20` |
| `mergeBy` | `Array<'source' \| 'target'>` | `['source', 'target']`；当前始终按两端分组，子集或空数组不会启用业务字段分组 |
| `includeReverse` | `boolean` | `true`，将 A→B 和 B→A 归为同组；`false` 时按方向分组，两条单独的反向边可能仍重叠 |
| `minOffset` | `number` | `0`，非中心边的最小绝对偏移；有限非负数，否则回退为 `0` |
| `maxOffset` | `number` | `80`，最大绝对偏移；有限非负数，否则回退为 `80` |

### 分组与间距

同组按当前边数组顺序分配偏移，公式为 `(index - (count - 1) / 2) * offset`，再限制绝对值到 min/max；中心偏移始终为 `0`。例如三条边、步长 `20` 得到 `-20, 0, 20`，两条得到 `-10, 10`。建议 `0 <= minOffset <= maxOffset`；达到上限的多条边可能重叠，`maxOffset: 0` 会压为零。

`offset` 是曲线控制点的法向偏移步长，并非路径在屏幕上的等距间隔；二次曲线中点的偏移约为该值的一半，缩放也会改变屏幕间距。方向符号由引擎处理，业务无需给反向边手动取负。

分离作用于 `arc`；默认 `line` 在存在多边组时会自动走弧线路径。`cubic` 和 `polyline` 的专用路径优先，不使用此偏移，不能依靠此配置拆开它们。启用分离的 `arc` 单边组会回到零曲率，同组曲率替代 `style.curvature`。需要稳定展示时保持数据顺序及边 `id`；重排或增删同组边可能改变路径。

### 两种入口与优先级

transform 写法为 `transforms: [{ type: 'process-parallel-edges', options: { offset: 30 } }]`，也可使用字符串 `'process-parallel-edges'`。参数必须放在 `options` 内，`distance` 不是配置项。

解析顺序为：内置默认 → 最后一个同名对象 transform 的 `options` → `edge.parallelEdges` 对象，按字段覆盖。字符串 transform 只负责启用。任一同名 transform 条目都会启用，因此 transform 的 `options.enabled: false` 本身不关闭它；使用 `edge.parallelEdges: false` 或 `{ enabled: false }` 明确关闭。仅有 `parallelEdges: true` 不会重置已提供的 transform 参数。

运行时可用 `graph.updateOptions({ edge: { parallelEdges: { enabled: true, offset: 30 } } })` 重算分组，无需重新布局；新对象替换原 `parallelEdges` 对象，保留其他选项时一并提交。`updateOptions()` 不接受 `transforms`。自环尺寸与层级由内置渲染器决定，本配置的 offset/min/max 不控制它们。步骤与更多场景见[平行边指南](/docs/guides/parallel-edges)。

## 曲线与折线路由

这些字段位于 `edge.style`。路由决定两端之间的路径，布局决定节点位置；设置 `router` 不会自动把数据排成树。路径几何使用图坐标，随相机缩放；它与屏幕像素线宽的单位不同。

| 字段 | 类型 | 默认与生效条件 |
| --- | --- | --- |
| `curvature` | `EdgeStyleValue<number>` | `0.3`；仅 `arc`，无量纲；控制点为两端中点加垂直向量乘该值。正负控制弯曲方向，`0` 为直线；平行边元数据优先 |
| `curveOffset` | `EdgeStyleValue<number>` | `60` 图坐标单位；仅 `cubic`，控制起终点处的水平控制柄长度 |
| `radius` | `EdgeStyleValue<number>` | `0` 图坐标单位；`orth`、`indented`、`fishbone` 路径的圆角；使用有限非负数，实际半径受相邻线段各一半长度约束 |
| `router` | `'orth' \| 'tree' \| 'indented' \| 'fishbone'` | `'orth'`；仅 `polyline`，全图固定值，不支持逐边回调 |
| `indentTarget` | `'left' \| 'right'` | `'left'`；仅横向 `indented` 路由，详见下文；固定值 |
| `trunkGap` | `number` | `0`；公开类型保留此字段，但当前路由计算不读取它，设置后不会移动主干 |

### 路由选择

| router | 路径与限制 |
| --- | --- |
| `orth` | 横纵折线，根据两端矩形边界及方向连接；节点太近或方向相反时绕到一侧。只考虑当前两端，不是全图障碍物避让 |
| `tree` | 同源节点分组并分配端口，当前渲染器使用平滑三次路径细分，而非硬直角；`radius` 不控制其平滑程度 |
| `indented` | 父节点主干加通往子节点的 L 形分支，适合目录树；可配合圆角 |
| `fishbone` | 按鱼骨图的横向主骨和斜骨几何连接，当前方向参数不改变计算；应配合内置 fishbone 布局，不作通用正交路由 |

方向来自创建图时的 `layout.rankdir ?? layout.direction ?? 'TB'`，设置在 `layout`，不是 `edge.style`。正交路由支持 TB/BT/LR/RL；当前 tree 将 BT 与 TB、RL 与 LR 共用端口计算，不能承诺镜像后的端口。缩进示例显式提供 LR，避免布局内部 LR 默认与路由 TB 默认不一致。

### 缩进目标与主干

横向 `indented` 配置 `indentTarget: 'left'` 时，从父节点中心的下边缘沿竖直主干连接到子节点的近侧边缘；LR 到左边，RL 到右边。`'right'` 采用无背景文本的约定：从父节点中心出发，到 `target.x ± target.width`，并非普通居中矩形的右边界。不应用它为矩形节点切换任意连接端口。TB/BT 路由不读取这个选项。

下面使用矩形节点、LR 缩进布局、`indentTarget: 'left'` 与 `radius: 10`。主干位置由父节点坐标确定；调整层级缩进用 `layout.indent`，行距用 `layout.rowHeight`，当前不能通过 `trunkGap` 调整主干。

<EdgeDocExample id="edge-indented" locale="zh" />

当前 `router` 和布局方向保存在创建时的数据模型中，`updateOptions()` 不更新它们；改变路由模式或方向应销毁后以新配置创建实例。`curvature`、`curveOffset`、`radius` 的逐字段更新可使用 `updateOptions()`。不要把样式更新描述为重新布局。

## 边标签

下列字段位于 `edge.style`，均支持与基础样式相同的三参数回调。文本内容不会自动取自边的 id 或 data；须配置 `label`。

| 字段 | 类型 | 默认与规则 |
| --- | --- | --- |
| `label` | `EdgeStyleValue<string \| false>` | `false`；非空字符串才绘制，空串或 `false` 隐藏 |
| `labelFontSize` | `EdgeStyleValue<number>` | `10` 屏幕像素；使用有限正数 |
| `labelFontFamily` | `EdgeStyleValue<string>` | 系统无衬线字体栈：-apple-system、BlinkMacSystemFont、Segoe UI、Roboto、Helvetica Neue、Arial、sans-serif |
| `labelColor` | `EdgeStyleValue<string>` | `'#666'`，独立于边线颜色 |
| `labelPlacement` | `EdgeStyleValue<'start' \| 'center' \| 'end'>` | `'center'`；分别取路径参数 `t = 0.2 / 0.5 / 0.8`，不是精确端点 |
| `labelBackground` | `EdgeStyleValue<string \| false>` | `'rgba(255,255,255,0.8)'`；`false` 关闭底色 |
| `labelBackgroundPadding` | `EdgeStyleValue<number>` | `2` 屏幕像素，底色四周内边距，使用有限非负数 |
| `labelAutoRotate` | `EdgeStyleValue<boolean>` | `true`；随路径切线旋转并保持文字正向，`false` 保持水平 |

下面三行分别展示 start、center、end，淡色底框由标签配置绘制；点击边只改变线条颜色，标签颜色仍由 `labelColor` 决定。为清楚比较，示例显式关闭碰撞和低缩放隐藏；业务可保留默认策略。

### 位置与显示条件

标签层使用已缓存的边路径采样位置与切线；没有路径缓存时沿端点连线插值。当前 `cubic`、`polyline` 的标签位置和旋转采用端点连线，不保证贴合实际弯曲或折线；也不能把 `center` 理解为所有路径的等弧长中点。

边标签字号和内边距保持屏幕尺寸，不随 `label.scaleWithZoom` 缩放。默认 `hideOnLowZoom: true`、`edgeMinZoom: 0.5` 和 `hideOnCollision: true` 可能隐藏标签；边或任一端点处于 hidden 状态时也不绘制。排查时先确认文本非空，再检查全局[标签策略](/docs/api/options/label#labeloptions)及缩放、碰撞。边线 `opacity` 不等同于标签的显隐开关。

边配置不提供节点的 `labelMaxWidth`、`labelOffsetX/Y`、`labelFontWeight` 或图标字段，状态样式也不覆盖这些标签字段。复杂绘制使用已注册的 `edge.labelRenderer`，仍须提供非空 `edge.style.label`；注册和 measure/draw 协议见[自定义 Label Renderer](/docs/guides/custom-label-renderer)。
