G6Lite 仍处于 `0.1.x` beta 阶段。公开 API 以 npm 包根入口和 `package.json#exports` 为唯一边界；`src/` 中未从包根导出的模块属于内部实现，不承诺深层路径兼容性。

## 推荐公开入口

- `Graph`：创建、渲染、更新和销毁图实例。
- `register()` 与 `extensionFactory()`：注册受控扩展。
- `runLayout()`：独立运行布局。
- resolveTheme、EventEmitter / Handler：见[工具函数](/docs/api/utilities)。
- 从包根导出的配置、数据、行为和扩展类型。

```ts
import { Graph, register, runLayout } from '@antv/g6-lite';
import type { GraphData, GraphOptions } from '@antv/g6-lite';
```

不要从 `@antv/g6-lite/src/...` 或构建产物内部路径导入。发布包虽然包含 `src/`，但它不是额外的公开 API 面。

## 公开与内部边界

从包根导出不代表 Graph 上每个成员都是业务契约。以下成员带 internal 标记，供引擎渲染或交互分发使用；业务选择右侧公开入口。

| 内部成员 | 公开替代入口 |
| --- | --- |
| eventEmitter | [on / off / once](/docs/api/graph/events)；独立业务分发用 [EventEmitter](/docs/api/utilities#eventemitter) |
| getCanvas | 宿主保留自己的容器引用，位置转换用[坐标方法](/docs/api/graph/viewport) |
| getLayoutNodes / getNodeIndex | [getNodes / getNodeData](/docs/api/graph/data) |
| pickAt / pickComboAt | [元素事件载荷](/docs/api/graph/events#元素事件载荷) |
| setHighlight / clearHighlight | [统一状态方法](/docs/api/graph/states) |
| updateData | [数据写入方法](/docs/api/graph/data-mutations) |
| scheduleRender | [refresh](/docs/api/graph/lifecycle#refresh)，扩展用 [context.requestRender](/docs/api/extensions/registration#requestrender-与-isdestroyed) |

## ESM 与 CommonJS

当前包根只提供 ESM，不提供 `require('@antv/g6-lite')` 条件。CommonJS 可行性验证表明，同步 `require` 入口和类型声明本身可以生成，但双产物还必须同时保证两项运行时契约：

- ESM 与 CommonJS 入口共享同一套扩展注册状态，避免同一应用混用两种入口时出现重复或不可见的注册项。
- `layout.worker: true` 经业务打包器处理后仍能定位并加载包内的模块 Worker，不能因 Worker 资源丢失而静默回退主线程。

当前 CommonJS 消费构建无法可靠保留 Worker 的静态资源关联，验证中会请求不存在的 Worker 文件；独立双构建也会产生两份模块级注册表。因此本版本不发布“只能同步加载、但 Worker 或扩展边界不完整”的 CommonJS 产物。

仍使用 CommonJS 工具链的应用可以在客户端边界使用动态导入：

```js
const { Graph } = await import('@antv/g6-lite');
```

这不会改变 `Graph` 依赖真实 DOM、Canvas 和 WebGL 的运行环境要求。

## 弃用兼容层

以下入口仍为已有项目保留。替代关系以当前包根和源码 deprecated 标记为准；新代码使用右侧入口，升级时核对变更记录。

| 兼容入口 | 当前替代 |
| --- | --- |
| BaseNode / registerNode | [NodeExtension + register('node', ...)](/docs/api/extensions/drawing#nodeextension) |
| BreathingNode | 内置 node.type: 'breathing-node'，或无状态 NodeExtension |
| ExtensionConstructor | [extensionFactory](/docs/api/extensions/registration#extensionfactory)，返回新实例 |
| graph.isDestroyed() | [graph.destroyed](/docs/api/graph/lifecycle#destroyed) |
| graph.toData() | [getData](/docs/api/graph/data#getdata) |
| graph.getNodePosition() | [getElementPosition](/docs/api/graph/data#getelementposition) |
| setComboState / clearComboStates / getComboStates | [setItemState / clearItemStates / getItemStates](/docs/api/graph/states) |
| 元素载荷的 event：GraphElementEvent、NodeGraphEvent、EdgeGraphEvent、ComboGraphEvent、CanvasGraphEvent | nativeEvent；[元素载荷](/docs/api/graph/events#元素事件载荷) |
| ExtensionContext.graph | [data / state / viewport 等受控能力](/docs/api/extensions/registration#extensioncontext) |
| ExtensionContext 的平铺 screenToGraph / graphToScreen / getZoom | viewport 下的同名方法 |

元素载荷的 event 弃用不扩大到选择、拖拽等派生载荷中的 event 字段。完整事件字段见[事件参考](/docs/api/graph/events)。

弃用能力的移除通过更新记录和迁移说明公布；beta 阶段不承诺跨 minor 永久保留。

## 实验性能力

Combo 的折叠、嵌套和运行时归组仍为实验性能力。可以用于验证和受控场景，但其配置细节可能在 `0.1.x` 内调整。正式使用前请覆盖真实数据、嵌套层级和增量更新回归。

## 版本兼容预期

- beta 阶段：公开入口保持集中，但 API 仍可能根据契约测试和案例反馈调整。
- 稳定版后：遵循语义化版本；破坏性变更进入 major 版本。
- 每次升级前：查看 [Changelog](/docs/changelog)，并执行类型检查、构建和关键案例回归。

业务可调用的入口、方法和配置字段见 [可用 API](/docs/api)、[Graph](/docs/api/graph) 和 [配置](/docs/api/options)。
