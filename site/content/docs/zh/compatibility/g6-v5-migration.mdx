---
title: 从 G6 v5 迁移
description: 评估从 G6 v5 迁移到 G6-GL 时的能力差异、边界与改造点
---

G6-GL 借鉴 G6 的配置心智，但不是 G6 v5 的完整替代。迁移前应先确认你的项目是否真的需要 G6-GL 的性能取向。

## 适合迁移的情况

- 图规模较大，渲染后高亮、选择、邻居聚焦非常频繁。
- 当前瓶颈集中在大图交互和状态切换。
- 项目只使用了相对核心的节点、边、布局和交互能力。

## 不建议直接迁移的情况

- 深度依赖 G6 插件、动画、完整元素生态或图论能力。
- 需要复杂自定义 Canvas 绘制。
- 当前图规模不大，G6 v5 已经满足性能要求。

## 常见差异

| 能力     | G6 v5             | G6-GL                         |
| -------- | ----------------- | ----------------------------- |
| 渲染技术 | Canvas            | WebGL                         |
| 交互命名 | 如 `drag-element` | 如 `drag-node`、`drag-canvas` |
| 自动适配 | G6 有更完整配置   | G6-GL 使用 `fitView()` 等 API |
| 插件生态 | 更丰富            | 聚焦核心行为                  |
| 扩展能力 | 完整元素/插件体系 | 轻量节点扩展                  |

## 改造建议

1. 先用一份真实数据在 playground 中复现核心场景。
2. 把数据统一成 `nodes` / `edges` / `combos`。
3. 将样式映射迁移到 `node.style`、`edge.style` 和 `stateStyles`。
4. 将交互替换为 G6-GL 内置 behaviors。
5. 用 `setItemState()` 承接高亮、选中、隐藏等状态。
6. 对比首屏、拖拽、拾取和状态切换指标。

可参考 `playground/demos/g6-v5-compat.ts`。
