先确定必须具备的能力，再用相同业务数据验证候选。下表用于缩小范围；性能测量见[公平验证清单](#公平验证清单)。

核对日期：**2026-11-05**。G6Lite 按本仓库 `0.1.0-beta.27`；外部对照为 [G6 5.1.1](https://github.com/antvis/G6/releases/tag/5.1.1)、[sigma.js v4 文档（4.0.4）](https://www.sigmajs.org/get-started/quickstart/)与 [Cytoscape.js 3.34.4](https://github.com/cytoscape/cytoscape.js/releases/tag/v3.34.4)。版本是本次核对范围，不自动代表后续最新版。

## 一句话结论

| 核心任务 | 优先验证 |
| --- | --- |
| 浏览器关系探索、频繁状态与增量更新，常用点线形态足够 | G6Lite |
| 丰富元素、React 节点、插件、动画及多渲染器 | G6 v5 |
| 已有 Graphology 数据与布局管线的网络浏览 | sigma.js v4 |
| 图论查询、算法、compound nodes 与 headless 分析 | Cytoscape.js |

这些是选型起点；具体能力仍需验证对应版本、扩展包和目标设备。

## 渲染、数据与布局

| 方案 | 数据与布局 | 绘制路径 |
| --- | --- | --- |
| G6Lite | GraphData；14 个布局类型或已有坐标 | WebGL 节点/边，Canvas 2D 标签/Combo |
| G6 v5 | Graph 数据模型与布局体系 | Canvas / SVG / WebGL，按 renderer 选择 |
| sigma.js v4 | Graphology；坐标及布局通常由独立链路提供 | WebGL 2，含 SDF 标签 |
| Cytoscape.js | 内置图模型、集合、选择器；核心及扩展布局 | 浏览器可视化与 headless 模型 |

G6Lite 布局类型与 Worker 边界查[布局参考](/docs/api/options/layout)。外部方案依据 [G6 官方介绍](https://github.com/antvis/G6#readme)、[Sigma v4 迁移说明](https://www.sigmajs.org/how-to/technical/migration-v3-v4/)和 [Cytoscape.js 文档](https://js.cytoscape.org/)。

## 元素、标签与分组

| 需求 | G6Lite 当前边界 | 其他候选的验证入口 |
| --- | --- | --- |
| 自定义图形与文字 | circle / rect 基型、常用边、overlay、Label Renderer、Decoration；不提供任意 DOM 节点树 | [G6 节点](https://g6.antv.antgroup.com/en/manual/element/node/overview) · [Sigma 图元](https://www.sigmajs.org/concepts/styles-and-primitives/) |
| 分组、嵌套与折叠 | Combo 为实验能力，先验证目标数据 | [G6 Combo](https://g6.antv.antgroup.com/en/manual/element/combo/overview) · [Cytoscape compound nodes](https://js.cytoscape.org/#notation/compound-nodes) |

不要用旧 Sigma v3 结论判断 v4：v4 已调整图元和样式协议、标签渲染及拖拽能力，具体变化以[迁移说明](https://www.sigmajs.org/how-to/technical/migration-v3-v4/)为准。

## 交互、扩展与生态

G6Lite 的 11 个[内置 Behavior](/docs/api/options/behaviors)覆盖常用浏览、选择、拖拽与 Tooltip；八类[扩展契约](/docs/api/extensions)允许定制。完整动画编排、图论算法及成熟插件集合不在当前能力面内。

需要这些能力时，分别检查 [G6 功能说明](https://github.com/antvis/G6#features)、[Sigma 交互](https://www.sigmajs.org/how-to/interactivity/interactions-events/)与 [Graphology 生态](https://graphology.github.io/standard-library/)，或 [Cytoscape.js 扩展目录](https://js.cytoscape.org/#extensions)。伴生包和业务实现应计入集成成本。

## 运行环境与工程形态

- G6Lite 的 Graph 仅在真实浏览器客户端创建；[ESM、WebGL 与 Worker 要求](/docs/compatibility/browser)需在目标工程验证。
- G6 的 Node.js 出图能力依赖相应渲染环境，见[官方说明](https://github.com/antvis/G6#features)。
- sigma.js v4 的可视化要求 WebGL 2；Graphology 数据计算与浏览器绘制应分开考虑，见[v4 迁移](https://www.sigmajs.org/how-to/technical/migration-v3-v4/)。
- Cytoscape.js 支持 [headless 模式](https://js.cytoscape.org/#init-opts/headless)；无界面分析与输出图片是不同验收目标。

## 如何选择

用真实需求做一次小规模验证：最复杂的节点、标签、分组、关键交互及一次数据更新都应包含在内。已有 G6 项目先查[迁移差异](/docs/compatibility/g6-v5-migration)，不要仅替换包名。

## 公平验证清单

1. 锁定版本、业务数据、样式、标签密度、视口、DPR、浏览器和硬件。
2. 分开测量已有坐标的绘制与重新布局；同时记录首屏、交互和批量更新。
3. 重复挂载/卸载，观察资源和内存；保存样本量、P95 与完整配置。

测量步骤见[性能指标](/docs/metrics/performance)，处理瓶颈见[性能调优](/docs/metrics/performance-tuning)。
