## 创建与首次渲染

使用已挂载、宽高非零的专用容器。构造只准备画布与渲染器，render 才执行布局和绘制。

在本次未被取消、替代或销毁的正常路径中，等待 await graph.render() 完成后再写数据和状态。首次 afterrender 仍早于初始化完成，不适合作为数据写入入口。框架挂载和卸载见[在框架中使用](/docs/getting-started/react)。

## 运行中的更新

| 变化 | 使用方式 | 详细入口 |
| --- | --- | --- |
| 替换整份数据 | await graph.setData(nextData) | [数据更新](/docs/guides/data#替换整份数据) |
| 修改元素或状态 | 元素方法、状态方法 | [增量修改](/docs/api/graph#修改节点和边)、[状态](/docs/api/graph/states) |
| 修改外观或主题 | graph.updateOptions(options) | [合并规则](/docs/api/graph/lifecycle#updateoptions) |
| 外部样式输入变化 | graph.refresh() | [刷新边界](/docs/api/graph/lifecycle#refresh) |
| 重新计算位置 | setLayout 后 await layout | [布局方法](/docs/api/graph/layout) |
| 缩放、平移、适配 | 视口方法 | [视口与坐标](/docs/api/graph/viewport) |

这些操作复用当前实例。重复 render 会重建运行时并重新适配，临时状态和增量修改不保证保留；不要用它替代日常更新。

## 销毁与异步清理

页面退出或组件卸载时立即 destroy，即使初始化尚未结束。已销毁实例不能复用；正常清理后重复销毁无额外效果。

异步返回后检查 graph.destroyed；多个请求并发时还需自己的请求序号或取消机制。destroyed 只表示销毁，不表示初始化成功或当前任务仍有效。

Graph 负责实例自己的画布、交互、插件和监听。业务请求、计时器、DOM 监听仍由业务清理。取消和失败路径见[render 契约](/docs/api/graph/lifecycle#render)。

日志先出现 afterrender，再出现 await render resolved，之后才选中 A。比较样式更新、刷新和再次渲染；最后销毁，观察画布移除，再用工具栏重置创建新实例。

```ts
import { Graph, type GraphData } from '@antv/g6-lite';

export function mountGraph(container: HTMLElement, data: GraphData) {
  const graph = new Graph({ container, data });

  async function initialize() {
    await graph.render();
    if (graph.destroyed) return;
    console.log(graph.getNodeCount()); // 正常初始化后的业务逻辑
  }

  void initialize().catch((error) => {
    graph.destroy();
    console.error(error);
  });

  return () => graph.destroy(); // 交给页面或组件卸载逻辑
}
```

## 常见问题

### afterrender 里写数据为什么会报错？

首次触发时初始化标记尚未设置。先在 render 前订阅需要的事件，再在 await graph.render() 后执行写入。

### render 的 Promise 返回，为什么仍不能继续操作？

被取消、替代或销毁的任务也可能正常返回。不要只看 Promise 是否兑现；同时检查实例与应用自己的任务代次。销毁后应新建实例，不能再次 render 恢复它。
