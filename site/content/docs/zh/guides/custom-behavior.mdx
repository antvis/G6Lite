内置行为不能表达业务规则时，用 Behavior 消费公开 Graph 事件，通过 ExtensionContext 更新数据或状态。本例点击节点使其成为唯一 active；点击空白只清理 active，保留 A 原有的 selected。

## 公共类型范式

为名称声明字面量 type，为业务选项声明独立类型；在激活处用 satisfies 检查。完整泛型、事件映射和生命周期签名统一见 [Behavior 契约](/docs/api/options/behaviors#自定义-behavior-契约)。

## 推荐文件与导出

可复用模块导出行为名称、options 类型和显式注册函数；应用在创建 Graph 前注册。使用包或业务前缀，避免覆盖全局注册表中的其他名称。不要依赖导入副作用决定注册顺序。

## 注册并激活

示例 run 中先调用 registerBusinessSelect，再创建 Graph，配置对象用 satisfies BusinessSelectOptions。字符串名称也可激活，init 收到的 options 会包含 type，缺省 state 使用 active。

多个 Graph 可以复用同一注册工厂；每个已挂载 Behavior 持有自己的 context 和 state。后注册同名定义不会替换已经挂载的实例，更换配置的边界见[挂载与更新](/docs/api/options/behaviors#挂载与更新)。

## 事件类型

getEvents 的事件名从 GraphEventMap 推导参数元组。例如 node:click 的 nodeId、nativeEvent 都有类型；destroy 是零参数事件。需要扩展消费端事件类型时，可交叉组合：

```ts
import type { BehaviorExtension, BehaviorOptions, GraphEventMap } from '@antv/g6-lite';

interface BusinessEventMap {
  'business:reset': [payload: { source: 'toolbar' | 'shortcut' }];
}
type BusinessBehavior = BehaviorExtension<
  BehaviorOptions<'business-select'>,
  GraphEventMap & BusinessEventMap
>;
```

它只补充处理函数的类型，不提供新的公开 emit 方法。普通业务联动优先使用[已有事件](/docs/guides/events)，不访问内部 eventEmitter。

## 生命周期与清理

引擎执行 create → init → getEvents，并在卸载时解绑事件、调用 destroy。Behavior 不承诺 update；重新挂载会销毁再创建。Readonly options 是类型约束，运行时不保证冻结，不应修改传入对象。

getEvents 返回的监听由引擎清理；你自己创建的 window 监听、timer、Observer、DOM 和异步任务需在 destroy 中清理。异步回调完成前检查 context.isDestroyed，并自行捕获 Promise 拒绝。

## 边界与覆盖规则

- 只从包根导入公开 API，使用 context.data/state/viewport、requestRender 和 isDestroyed。
- 只读快照用于读取；修改业务字段用 data.updateNode/updateEdge，替换状态用 state.set/setAll。
- 独立 DOM、键盘控制器或 Observer 通常归 Plugin；渲染前数据处理归 Transform。
- 同名注册优先于内置，注册实现失败不会自动回退内置；不要覆盖内置名称做临时试验。
