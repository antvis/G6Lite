需要多行、富内容或自定义截断时使用 LabelRenderer；普通文字先用[label 配置](/docs/guides/label)。下面同一个 renderer 绘制节点名称与城市，以及边的协议与类型。

## 注册与使用

1. measure 设置字体，计算包含背景内边距的完整宽高，把分行结果放入 layout.data。
2. draw 显式设置字体和颜色，在原点附近绘制，不依赖 measure 留下的 Canvas 状态。
3. 注册 label 名称，分别配置 node.labelRenderer / edge.labelRenderer，并显式提供非空 label。

拖动节点或缩放，观察两行内容与背景。展开完整代码可看到两种激活配置。业务只负责内容，位置、旋转、缩放策略和碰撞由引擎处理。

## 协议约定

传入 text、已解析的 style、ctx、dpr、zoom。type='node' 时可读 node；type='edge' 时可读 edge / source / target。先按 type 分支再访问专用字段，完整联合类型查[LabelRenderer](/docs/api/extensions#labelrenderer)。

style 的字号、偏移和内边距已经是 backing-store 像素，不再乘 DPR 或 zoom。draw 原点位于标签中心，边旋转已应用，不要重复平移到节点或再次旋转。

measure 返回有限正数宽高，覆盖全部自绘内容；layout.data 仅缓存本次计算。碰撞或裁剪可能导致测量后不绘制，不在 measure 中修改业务状态。自绘背景和截断由 renderer 实现，labelMaxWidth 不会自动裁切自绘文字。

## 常见问题

### 为什么文字被跳过？

先查非空 label、hidden、低缩放阈值与碰撞策略；这不一定是 renderer 异常。临时关闭策略排查，之后再恢复适合业务的密度。

### 宽高错误或绘制抛错会怎样？

当前标签回退默认单行渲染并诊断；不要返回 0、NaN 或无限尺寸。Decoration 的失败行为不同，见[绘制契约](/docs/api/extensions#extension-drawing)。

### 边标签一定沿真实路径放置吗？

当前 polyline / cubic 使用端点连线位置与旋转，不能保证贴合折线或曲线。见[边标签限制](/docs/guides/edge#边标签)。
