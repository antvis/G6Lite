把重复的业务外观封装为无状态 NodeExtension；仅有颜色或尺寸差异时先用[node 配置](/docs/api/options/node)。本例蓝色为正常、红色为异常，左侧短条是 overlay，徽章使用装饰边界锚点。

## 适用场景

1. 选 circle / rect 基型，保留内置绘制和拾取。
2. 定义默认 style、纯函数 getStyle，首次 render 前 register。
3. 配置 node.type 激活；运行中通过公开数据方法更新业务字段。

## 覆盖绘制与边界锚点

drawOverlay 使用传入的屏幕 x/y，按 zoom 换算图尺寸，并配对 save / restore。静态绘制不返回 true；动画才持续请求重绘。覆盖内容不增加拾取热区，不能把短条当成独立交互组件。

getBoundaryAnchor 把右侧徽章上移四分之一节点高度。它返回相对中心的屏幕偏移，仅影响装饰定位，不改变边的连接端口或矩形拾取轮廓；传入宽高已换算，勿再乘 DPR。全部参数查[NodeExtension](/docs/api/extensions/drawing#nodeextension)。

逐字段配置覆盖扩展默认值；整对象 node.style 函数有独立解析路径，不要假定它自动继承默认样式和状态层。

## 内置扩展

breathing-node 已内置注册，可直接用于 node.type；[呼吸节点案例](/docs/examples/breathing-node)展示动画。BaseNode 与 registerNode 保留兼容，新代码用 register('node', ...)，不导入内部 Renderer 或缓存。

## 常见问题

### 注册后为什么没有变化？

检查名称与 node.type、注册顺序，以及配置是否覆盖了需要观察的字段。描述按名称缓存，不持有单个 Graph 的可变状态。

### 为什么徽章移动了，边端点没动？

锚点钩子仅供装饰定位。任意自定义形状和拾取轮廓不在当前能力范围。

### 为什么动画持续重绘？

检查 drawOverlay 是否始终返回 true。静态内容返回 void / false，大图不要为所有节点持续绘制。
