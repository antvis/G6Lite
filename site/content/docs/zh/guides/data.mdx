## 概述

图数据由节点、边和可选的 Combo 分组组成。将业务对象映射为节点、对象之间的关系映射为边，再把数据传给 `Graph`。图已经渲染时，可以替换整份数据，也可以只修改变化的元素。

### 节点数据（GraphNode） [#graphnode]

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | `string` | 是 | — | 节点的唯一 ID。边通过它指定端点，也可以用它查询和更新节点。 |
| `name` | `string` | 否 | — | 节点名称，可在 `node.style.label` 回调中读取并显示。 |
| `data` | [`NodeData`](/docs/api/options#config-node-data-fields) | 否 | — | 自定义业务数据，例如 `{ score: 80 }`。其中 `cluster` 如有设置，需为字符串。 |
| `x` | `number` | 否 | 无布局时为 `0` | 节点在图坐标系中的横坐标。配置布局后，最终位置由布局计算，可用 `fx` 固定横坐标。 |
| `y` | `number` | 否 | 无布局时为 `0` | 节点在图坐标系中的纵坐标。配置布局后，最终位置由布局计算，可用 `fy` 固定纵坐标。 |
| `fx` | `number` | 否 | 不固定横坐标 | 布局计算完成后，将节点的横坐标设为此值。 |
| `fy` | `number` | 否 | 不固定纵坐标 | 布局计算完成后，将节点的纵坐标设为此值。 |
| `comboId` | `string` | 否 | 不属于分组 | 所属 Combo 的 ID，需引用 `combos` 中已声明的分组。 |
| `states` | `NodeState[]` | 否 | `[]` | 节点的初始状态，例如 `['selected']`。通过 `node.stateStyles` 配置对应外观。 |

### 边数据（GraphEdge） [#graphedge]

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | `string` | 否 | 自动生成 | 边的唯一 ID。需要在整图替换前后识别同一条边时，显式传入稳定 ID。 |
| `source` | `string` | 是 | — | 起点节点的 ID，需引用 `nodes` 中的节点。 |
| `target` | `string` | 是 | — | 终点节点的 ID，需引用 `nodes` 中的节点。与 `source` 相同会形成自环。 |
| `data` | `EdgeData` | 否 | — | 自定义业务数据，类型为 `Record<string, unknown>`，例如 `{ weight: 2 }`。 |
| `states` | `EdgeState[]` | 否 | `[]` | 边的初始状态，例如 `['selected']`。通过 `edge.stateStyles` 配置对应外观。 |

### 分组数据（ComboData） [#combodata]

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | `string` | 是 | — | 分组的唯一 ID。节点通过 `comboId` 引用它，子分组通过 `parentId` 引用它。 |
| `parentId` | `string` | 否 | 无父分组 | 父分组的 ID，需引用同一 `combos` 列表中的分组。父子关系不能成环。 |
| `collapsed` | `boolean` | 否 | `false` | 设为 `true` 时初始折叠分组，隐藏后代节点及其关联边。 |
| `style` | `Partial<ComboStyleConfig>` | 否 | 使用图级分组样式 | 为当前分组覆盖指定的样式字段，例如 `{ fill: '#e6f4ff' }`。 [分组样式配置](/docs/api/options#options-combo) |
| `data` | `Record<string, unknown>` | 否 | — | 自定义业务数据，例如 `{ department: 'engineering' }`。 |
| `states` | `ElementState[]` | 否 | `[]` | 分组的初始状态，例如 `['selected']`。通过 `combo.stateStyles` 配置对应外观。 |

## 数据操作

### 数据初始化

将 `data` 传入 `new Graph()`，等待首次 `render()` 完成，再调用数据写入方法。示例中的 `#container` 需要已挂载并具有宽高。

```ts
import { Graph } from '@antv/g6-lite';

const graph = new Graph({
  container: '#container',
  data: {
    nodes: [{ id: 'A', x: 0, y: 0 }, { id: 'B', x: 120, y: 0 }],
    edges: [{ id: 'A-B', source: 'A', target: 'B' }],
  },
});

await graph.render();
```

### 选择更新方式

| 变化 | 方法 | 保留或重算 |
| --- | --- | --- |
| 切换数据集 / 全量返回 | setData | 替换全图，有配置就布局；默认适配 |
| 少量业务字段变化 | updateNodeData / updateEdgeData | 浅合并 data，不重布局 |
| 新增或删除元素 | addNode(s) / addEdge(s) / remove… | 新增节点提供坐标，删除节点连带删除边 |
| 位置变化 | updateNodePosition(s) | 图坐标变化，不改变身份 |
| 选择、隐藏、归组 | 状态 / Combo 方法 | 按所属主题修改，不必全量替换 |

### 替换整份数据

准备好完整的 `GraphData` 后调用 `setData()`。它会按当前配置重新布局，默认重新适配画布。传入 `fitView: false` 可以保留用户当前的缩放和平移。

```ts
await graph.setData(nextData, { fitView: false });
```

新数据决定初始选中状态。要保留选择，按仍存在的稳定 ID 恢复。 [保留选择](/docs/guides/states) · [视野保留示例](/docs/guides/viewport)

### 增量更新

下面接着使用初始化示例的图。先添加节点 C 和边 B-C，再更新它们的业务字段。

```ts
graph.addNode({ id: 'C', x: 240, y: 0 });
graph.addEdge({ id: 'B-C', source: 'B', target: 'C' });

graph.updateNodeData('C', { score: 80 });
graph.updateEdgeData('B-C', { weight: 2 });
```

删除边时会保留端点。删除节点时会一起移除关联边。

```ts
graph.removeEdge('B-C');
graph.removeNode('C');
```

在下面的示例中，可以查询 A、修改分数，或添加和删除节点 D。

增量方法会调度重绘。多个元素优先使用批量方法。业务字段按顶层键浅合并，嵌套对象整体替换。

### 查询数据

用 `getNodes()` 和 `getEdges()` 读取列表，用 `getNodeData(id)` 和 `getEdgeData(id)` 按 ID 查询单个元素。

```ts
const nodes = graph.getNodes();
const edges = graph.getEdges();
const node = graph.getNodeData('B');
const edge = graph.getEdgeData('A-B');
```

#### 输入、模型与快照 [#输入模型与快照]

| 形式 | 用途 | 修改方式 |
| --- | --- | --- |
| GraphData 输入 | 声明节点、边和 Combo | 交给 new Graph / setData |
| 查询 Model | 读取当前工作图，states 是集合 | 通过 Graph 方法修改 |
| getData 快照 | 导出当前坐标、归属与状态 | 修改后显式 setData；嵌套对象可能共享 |

稳定 ID 表示业务身份，数组顺序和坐标都不表示身份。相同端点可以有多条不同 ID 的边；跨刷新保留边选择时显式提供稳定 ID。

Model 是 Graph 持有的实时视图。数据替换或删除后重新查询。首次渲染前，各查询方法返回相应的空值，`getData()` 则返回构造数据的快照。查询可能在销毁后仍有返回值，可用 [destroyed](/docs/api/graph#graph-lifecycle-destroyed) 检查实例。

`getData()` 在渲染后导出当前坐标、实际边 ID、归属和状态。快照省略折叠派生的 `hidden`，固定轴 `fx` / `fy` 和布局配置需另存。

##### 查询返回类型 [#模型字段]

| 返回类型 | 字段 |
| --- | --- |
| `NodeModel` | `id`、`name?`、`x`、`y`、`data?`、`states` |
| `EdgeModel` | `id`、`source`、`target`、`data?`、`states` |
| [ComboModel](/docs/guides/combo#只读查询模型) | 分组坐标、尺寸、成员、折叠状态等 |
| `ElementModel` | `NodeModel \| EdgeModel \| ComboModel` |

字段均为只读，`?` 表示可选。节点的 `x`、`y` 是图坐标，`data` 的类型是 `Readonly<Record<string, unknown>>`，`states` 的类型是 `ReadonlySet<ElementState>`。

```ts
const element = graph.getElementData('A-B');
if (element && 'source' in element) {
  console.log(element.source, element.target);
}
const selected = graph.getNodeData('A')?.states.has('selected');
```

### 复杂数据结构

**嵌套分组。** 初始数据通过 `parentId` 表示分组的父子关系，通过节点的 `comboId` 声明归属。运行中可以创建分组、移动已有节点和切换折叠状态。下面把已存在的 B 加入 Storage，再将 Storage 折叠。

```ts
graph.createCombo({ id: 'platform' });
graph.createCombo({ id: 'storage', parentId: 'platform' }, ['B']);
graph.collapseCombo('storage');
```

**树形数据。** 将树展平为 `nodes` 和 `edges`。每条边从父节点指向子节点，例如 `{ source: 'root', target: 'child' }`。将这份数据交给 `mindmap`、`indented` 等树布局。 [Combo 用法](/docs/guides/combo) · [树布局示例](/docs/api/options#config-tree-layout-fields)

## 使用远程数据

接口返回完整图数据时，可以先创建并渲染空图，再加载 JSON。下面假设接口已经返回符合 `GraphData` 的数据。如果接口返回的是业务对象，先转换并校验 ID、边端点和分组归属。

```ts
import { Graph, type GraphData } from '@antv/g6-lite';

const graph = new Graph({
  container: '#container',
  data: { nodes: [], edges: [] },
  layout: { type: 'grid' },
});
await graph.render();

const response = await fetch('/data/graph.json');
if (!response.ok) throw new Error(`HTTP ${response.status}`);

const data: GraphData = await response.json();
if (!graph.destroyed) await graph.setData(data);
```

### 取消旧请求并清理图实例

下面的辅助函数拥有此页面 Graph 的清理职责。load 接受 AbortSignal；调用 refresh 时处理失败提示，退出时调用 dispose。

```ts
import type { Graph, GraphData } from '@antv/g6-lite';
export function createLoader(graph: Graph, load: (signal: AbortSignal) => Promise<GraphData>) {
  let version = 0;
  let disposed = false;
  let controller: AbortController | undefined;
  return {
    async refresh() {
      const request = ++version;
      controller?.abort();
      const current = new AbortController();
      controller = current;
      try {
        const next = await load(current.signal);
        if (disposed || graph.destroyed || request !== version) return;
        await graph.setData(next, { fitView: false });
      } catch (error) {
        if (!current.signal.aborted && !disposed) throw error;
      }
    },
    dispose() {
      disposed = true;
      version++;
      controller?.abort();
      graph.destroy();
    },
  };
}
```

## 常见问题

### 修改导出数据为什么没生效？

getData 不自动写回；少量变化用增量方法，整图替换才显式 setData，并选择视野策略。

### 删除后为什么原来的下标指向其他元素？

数组顺序可能变化。用 ID 查询，分别匹配节点和边，不保存数组下标作为身份。

<span id="数据与样式" />

### 更新后标签或颜色没变？

确认字段写在 data，样式函数读取同名字段；修改导出副本或直接改 Model 不会按公开流程更新。

### 更新后为什么视野或选择丢了？

setData 默认适配，状态按新输入建立。保留相机用 fitView: false，保留选择则按稳定 ID 显式恢复。
