## 基础配置

先准备两端节点，确保边的 source、target 引用已存在的节点 id，再设置 `edge.type` 和 `edge.style`。给需要更新、选择或删除的边提供稳定 id。

下面完整示例用三组数据配置细实线、虚线与双向箭头。点击边可看到紫色选中状态，重置恢复初始效果；展示与完整代码使用同一份源码。

## 类型

先按关系的展示需求选择全图边类型，再决定是否需要自动分离或路由。

| 场景 | 选择 | 后续配置 |
| --- | --- | --- |
| 普通关系 | 默认 `line` | 先设置颜色、线宽和方向 |
| 同端点多条关系或需要手动弯曲 | `arc` | 启用 parallelEdges，或在关闭分离时设置 curvature |
| 左右层级之间的平滑连接 | `cubic` | 用 curveOffset 调整水平控制柄；不使用平行边自动偏移 |
| 流程、目录树或鱼骨图 | `polyline` | 匹配布局方向与 router；它不会自动排布节点 |

[曲率与控制柄参考](/docs/api/options/edge#弧线与三次曲线)提供可运行对照。自定义类型先注册 edge 扩展，基型决定可用路径；未知名称回退为直线不代表扩展已注册成功。

## 样式字段

把关系的业务属性放到 `edge.data`，按字段映射外观。例如风险决定颜色、权重决定线宽、关系类别决定标签。回调为 `(source, target, edge) => value`，前两项是节点，第三项才是边；基础示例已经使用这三个入参读取边数据。

配置时依次考虑：

1. 用 stroke、lineWidth 区分类别与权重，opacity 弱化次要关系。
2. 有方向语义时保留 endArrow，需要双向时再加 startArrow；无方向时显式关闭默认终点箭头。
3. 需要虚线时设置两项周期并使用大于 1 的线宽；当前不是 Canvas 的任意长短交替模式。
4. 几何参数与类型配套使用，避免给 line 配 curvature 或给 arc 配 router。

精确字段与回退规则见[基础样式](/docs/api/options/edge#基础样式)、[箭头](/docs/api/options/edge#箭头)及[样式回调](/docs/api/options/edge#样式回调)。`style` 使用字段对象，支持回调的字段各自配置函数。

## 细边交互热区

保留细线的视觉密度，用 hitAreaWidth 扩大可点范围，再安装 click-select、tooltip 等需要的行为。仅扩大热区不会自动启用这些交互。

下面两条边的视觉线宽均为 1.5，上方热区为 2，下方为 24。点击细线附近比较命中范围；选中只改变颜色，线宽保持不变。图中的热区不可见。

<EdgeDocExample id="edge-hit-area" locale="zh" />

热区宽度是屏幕像素中的总宽度，24 对应中心线两侧各约 12；缩放时不需要手动乘 zoom 或 DPR。数值规则和适用路径见[点击热区参考](/docs/api/options/edge#点击热区)。

## 状态样式

先在 edge.stateStyles 中声明 selected、highlight、inactive 等效果，再由交互行为或状态 API 激活。基础示例已经配置 click-select 和 selected；只写 stateStyles 不会自动触发选中。

业务实例首次 render 完成后，也可以按 id 控制状态：

```ts
graph.setItemState('Plain', 'selected', true);
graph.setItemState('Plain', 'selected', false);
```

这里的 Plain 是基础示例中的边 id。配置同名状态对象会替代主题该状态的对象，多个状态的覆盖顺序也会影响结果；完整规则见[状态样式参考](/docs/api/options/edge#状态样式)。状态字段不用于切换边类型或标签颜色。

## 平行边与自环

先确认需要区分的是同一对节点的多条关系，再配置 `parallelEdges: true`，或显式写 `{ enabled: true, offset: 60 }`。使用 arc 或默认 line；cubic、polyline 不使用该自动偏移。

下面分别展示三条同向边、一对双向边和两个自环。橙色表示反向关系。边顺序参与偏移分配；增删关系后重新分组是正常行为。

<EdgeDocExample id="edge-parallel" locale="zh" />

已有项目也可保留 `transforms: [{ type: 'process-parallel-edges', options: { offset: 18 } }]`。两种入口通常选择一个；同时使用时查看[优先级参考](/docs/api/options/edge#两种入口与优先级)，不要把 distance 当成间距字段。offset 是图坐标中的控制点偏移，不是屏幕上两条线的固定间距。

自环只需 source 与 target 相同，不依赖分离开关；offset 不调整自环大小。更多使用场景见[平行边与自环指南](/docs/guides/parallel-edges)。

## 折线路由

先用布局确定节点位置和方向，再选择 `edge.type: 'polyline'` 与 router。流程图通常从 orth 开始；缩进目录用 indented 并显式设置 layout.direction；tree 当前为平滑树形连接，fishbone 配合鱼骨布局。

下面 Dagre 用 LR 方向排列节点，orth 连接两端边界，radius 处理圆角。可以拖动画布、缩放或重置；这是端点路由，不保证避开其他所有节点。

<EdgeDocExample id="edge-orth" locale="zh" />

[缩进目标与主干参考](/docs/api/options/edge#缩进目标与主干)有矩形目录树的代码与实际效果。普通矩形优先使用 indentTarget: 'left'；'right' 是无背景文本的专用坐标约定。trunkGap 当前不生效，层级间距应配置布局参数。更换 router 或方向需要重建实例，见[路由限制](/docs/api/options/edge#曲线与折线路由)。

## 边标签

先用 label 回调提供非空文本，再设置位置、字号与底色。边标签与边线颜色独立；下面 start、center、end 分别展示三个位置，代码同时提供实际效果。

<EdgeDocExample id="edge-labels" locale="zh" />

这个对照显式关闭碰撞和低缩放隐藏，便于查看。业务中可保留默认策略，只显示关键关系的标签，避免过密。边标签保持屏幕尺寸；当前 cubic 和 polyline 的标签沿端点连线定位，不保证跟随弯曲路径。字段、显示条件与自定义渲染器入口见[边标签参考](/docs/api/options/edge#边标签)。

## 运行时更新

按变更目的选择 API；以下用于已完成首次 render 的业务实例，不是本页的操作按钮。

| 变更 | 操作 |
| --- | --- |
| 某条边的业务属性 | `graph.updateEdgeData('Plain', { risk: 'high' })`；对应样式回调读取该属性后才有视觉变化 |
| 两端重新连接 | `graph.updateEdgeData([{ id: 'Plain', source: 'a', target: 'b' }])`；端点节点须存在 |
| 全图边样式 | `graph.updateOptions({ edge: { style: { lineWidth: 2 } } })` |
| 分离参数 | `graph.updateOptions({ edge: { parallelEdges: { enabled: true, offset: 30 } } })`；提交需要保留的完整对象 |
| 临时选中或隐藏 | 用状态和显隐 API，避免替换整份数据 |
| 路由模式或布局方向 | 销毁后以新配置创建实例；样式更新不会更新创建时保存的路由模式和方向 |

更多方法见[边增量操作](/docs/api/graph#边)和[配置更新](/docs/api/graph#updateoptions)。高频更新优先批量修改数据，并保持边 id 稳定。

## 常见问题

### 为什么多条边仍然重叠？

先检查对象入口是否 enabled: true，再确认类型是默认 line 或 arc。检查 maxOffset 是否把偏移压到同一值，以及 includeReverse 是否把反向边分到不同组。单独的两条反向边在分组关闭时仍可能重叠。

### 为什么改 offset 后自环大小没变？

自环不参与平行边分组。当前大小与层级由内置自环渲染器决定，parallelEdges 的间距字段不控制它。

### 为什么细线仍然难点中？

扩大 hitAreaWidth 后还需要对应交互行为。总宽度不是单侧半径，最终热区也不会小于视觉线宽；用上面的 2/24 对照确认实际效果。

### 为什么看不到标签？

先确认 label 返回非空字符串，再检查缩放阈值、碰撞、边和端点的 hidden 状态。把文本存入 data 本身不会自动绘制；排查时可暂时关闭隐藏策略。

### 为什么改 router 或 trunkGap 没变化？

router 在创建时保存，当前需要重建实例才能切换；trunkGap 虽然在类型中，但尚未用于计算。主干与间距由当前布局和路由决定。

### 为什么边没有按预期绕开节点？

orth 只依据两个端点计算，不执行全图障碍物避让。先调整节点间距与布局，再选择合适路径，不要把圆角当成避障参数。

### 为什么配置了状态却没触发？

stateStyles 只描述效果，需要行为或 setItemState 激活。确认传入的是边 id，且配置了需要的状态字段。
