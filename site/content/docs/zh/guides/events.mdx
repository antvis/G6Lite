## 元素事件

监听无需启用 click-select。下面点击只更新说明区；Listening 控制持续监听，Arm once 等待下一次节点点击。关闭持续监听后，单独注册的 once 仍然生效。

业务数据读 data，菜单等屏幕定位读 client，图内定位读 graph；不要把 canvas 的 CSS 像素直接当图坐标。点击 Combo 内的节点只发 node:click，不同时发 combo:click。字段与命中规则见[元素载荷](/docs/api/graph/events#元素事件载荷)。

## 选择与拖拽事件

先在 Graph 的 behaviors 中启用 click-select、brush-select / lasso-select 或 drag-node；组合方法见[交互指南](/docs/guides/interactions)。同步业务选择时，在多个来源的结束事件中读取最终集合：

```ts
import type { Graph } from '@antv/g6-lite';

export function observeSelection(
  graph: Graph,
  onChange: (nodes: string[], edges: string[]) => void,
) {
  const sync = () => onChange(
    graph.findNodesByState('selected'), graph.findEdgesByState('selected'),
  );
  const events = ['node:selectchange', 'edge:selectchange', 'selection:clear', 'brush:end', 'lasso:end'] as const;
  for (const event of events) graph.on(event, sync);
  sync();
  return () => { for (const event of events) graph.off(event, sync); };
}
```

一次操作可能回调多次（先清空再选中）。昂贵 UI 更新可在应用层合并；代码直接设置状态后，也应主动同步业务 UI。框选不会逐个发 node:selectchange。

拖拽保存使用结束事件，读取 nodeIds 中所有节点的位置；每次 move 的 dx/dy 是从手势起点累计的图坐标位移。下面返回清理函数，保存函数的网络请求和错误处理由应用实现：

```ts
import type { Graph, GraphEventMap } from '@antv/g6-lite';

export function observeDrag(graph: Graph, save: (positions: Array<{ id: string; x: number; y: number }>) => void) {
  const onEnd = ({ nodeIds }: GraphEventMap['node:dragend'][0]) => {
    save(nodeIds.flatMap((id) => {
      const position = graph.getNodePosition(id);
      return position ? [{ id, ...position }] : [];
    }));
  };
  graph.on('node:dragend', onEnd);
  return () => graph.off('node:dragend', onEnd);
}
```

Combo 和连线拖拽的载荷不同，见[拖拽参考](/docs/api/graph/events#拖拽事件)；drag-edge 的新端点仍需业务验证并写回。

## 取消监听

保留同一个 handler 引用交给 off；不要重新创建一个看似相同的箭头函数。上面的 observeSelection / observeDrag 都返回清理函数：组件卸载、业务订阅替换时调用它。Graph 销毁会移除自身监听；应用创建的 DOM、计时器和网络请求需另行清理。

一次性操作用 once，在需要它的事件发生前注册。待定的一次性监听也能用原 handler 调用 off 取消；API 签名与示例见 [on / off / once](/docs/api/graph/events#on)。

## 自定义事件类型

未知事件名可声明 handler 参数，但不会因此产生业务事件。业务消息使用自己的事件通道；自定义行为见[自定义 Behavior](/docs/guides/custom-behavior)，订阅泛型见 [GraphEventMap](/docs/api/graph/events#grapheventmap)。

## 常见问题

### 为什么 nativeEvent 是 undefined？

先确认事件类别。元素点击、悬停和滚轮用 nativeEvent；选择、拖拽的部分阶段仍用 event；node:dragend 和区域选择没有原始事件字段。

### 为什么布局结束时读到的坐标还是旧的？

layout:end / afterlayout 在写回前发出。需要结果时等待 await graph.layout()，不要在结束事件里再次无条件调用 layout。

### 为什么监听有时重复执行，有时完全不触发？

检查组件是否重复注册、off 是否使用原函数、once 是否已经消费，以及对应 Behavior 是否启用。未知字符串重载兼容自定义名称，拼错事件名也可能通过类型检查。
