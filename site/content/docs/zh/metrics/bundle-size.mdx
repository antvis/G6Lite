description: G6-GL 的 size-limit 测量口径、120 kB brotli 预算与复现方法

G6-GL 使用 [size-limit](https://github.com/ai/size-limit) 对真实包入口和完整依赖树进行体积约束。默认包继续保持 **120 kB（minify + brotli）** 门槛，并为不含布局算法的渲染核心增加 90 kB 门槛。

## 测量口径

- 入口：`dist/index.js`，对应 `import { Graph } from '@antv/g6-gl'`。
- 范围：核心引擎、regl、事件依赖和默认入口可达的布局算法。
- 处理：size-limit 使用打包器模拟生产 bundle，执行 minify 与 brotli 压缩。
- 门槛：根目录 `.size-limit.mjs` 分别约束不含布局算法的 core 和默认入口；`dagre`、`radial`、`mds` 是显式启用的独立子入口，不计入默认包。

## 复现

```bash
npm run build
npm run size
```

2026-07-30 当前工作区结果为：core **83.18 kB / 90 kB**，默认入口 **109.69 kB / 120 kB**。最新结果以当前 checkout 执行 `npm run size` 为准。

## 使用建议

- 从包根导入公开 API，让业务打包器可以正确分析依赖。
- 使用支持 tree-shaking 的 Vite、Rollup、esbuild 或等价工具；包已声明 `sideEffects: false`。
- 生产 CDN 开启 brotli 或 gzip，并以业务最终 bundle analyzer 结果评估真实增量。
- 不把 G6-GL 与功能范围、依赖口径不同的图库做未经复现的体积倍数比较。

体积门槛是工程约束，不代表所有业务只增加同等下载量；业务打包器版本、去重策略和已有共享依赖都会影响最终结果。
