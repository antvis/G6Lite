先固定业务数据和环境，再比较相同工作。已有坐标的绘制、重新布局的首屏和渲染后的交互应分别记录。

## 环境要求

记录包版本和源码 commit、依赖版本、浏览器/系统、CPU/GPU、视口 CSS 尺寸、DPR、节点/边数量、标签与样式、布局参数、缓存和 Worker 是否实际运行。保存输入数据、随机种子（如算法支持）、完整代码和原始样本。

## 当前公开口径

| 指标 | 测量边界 |
| --- | --- |
| 数据准备 | 业务原始输入 → GraphData，不计入纯渲染 |
| 布局 | runLayout 开始到坐标返回；冷/热加载分别记录 |
| 构造与 render 完成 | new Graph → await render；包含 CPU 初始化与 draw 提交，不是 GPU 完成时间 |
| 交互 | 连续缩放/拖拽、状态和批量位置更新；观察帧时间与主线程长任务 |
| 资源 | 反复挂载/销毁后比较实例、画布、监听与内存趋势 |

以下函数每次释放图实例，用于拆分布局与 render 的测量；容器必须可见且有非零尺寸。为说明边界使用 grid，不代表其他算法的耗时。

```ts
import { Graph, runLayout, type GraphData } from '@antv/g6-lite';

export async function measureOnce(container: HTMLElement, data: GraphData) {
  if (document.visibilityState !== 'visible') throw new Error('Keep the tab visible');
  const start = performance.now();
  const positions = await runLayout(data, { type: 'grid' });
  const layoutMs = performance.now() - start;
  const coordinates = new Map(positions.nodes.map((node) => [node.id, node]));
  const positioned = { ...data, nodes: data.nodes.map((node) => ({
    ...node, ...coordinates.get(node.id),
  })) };
  const createStart = performance.now();
  const graph = new Graph({ container, data: positioned, behaviors: [] });
  try {
    await graph.render();
    const renderResolvedMs = performance.now() - createStart;
    await new Promise<void>((resolve) => requestAnimationFrame(() => {
      requestAnimationFrame(() => resolve());
    }));
    return { layoutMs, renderResolvedMs, throughTwoFramesMs: performance.now() - createStart };
  } finally {
    graph.destroy();
  }
}
```

计时使用单调时钟 [performance.now](https://developer.mozilla.org/en-US/docs/Web/API/Performance/now)。两次 [requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame) 只跨过帧回调，不证明 GPU 已完成或像素已被用户看到；后台标签页会影响此测量。

## 常用图库选型对比

先用[能力对比](/docs/compatibility/library-comparison)筛选可行方案。统一坐标、标签、边和交互；不要把某方案不做布局的时间与另一方案含 force 计算的首屏放在同一列。

## 如何进行数值对比

1. 冷启动单独记录；热路径先预热，再至少收集 30 次独立样本，明确样本量。
2. 保留全部样本，给出中位数、P95 和范围；异常样本说明原因，不静默删除。
3. 用 200 / 5000 节点及真实拓扑逐级验证，最后在目标设备检查拖拽、标签与销毁。

可运行入口：[200 节点](/docs/examples/large) · [5000 节点](/docs/examples/large-labeled) · [AI Papers](/docs/examples/ai-papers)。先看各示例的数据规模说明；调优步骤见[性能优化](/docs/metrics/performance-tuning)。
